This page is for the engineer migrating an existing customer database into Trusset. After reading it you will know how records are matched, what happens to the ones that fail, and why a failed on-chain verification does not undo the import.

The `sync` sub-module handles bulk migration of customer data between your existing systems and Trusset. It is designed for institutions with established customer databases that need to onboard thousands of records without manual entry.

Records are mapped by `externalId`, your system's unique customer identifier. The SDK uses it for deduplication and conflict resolution across syncs.

## Import records

`externalId` is the only required field on a record. `kycHash` takes the root hash from the KYC proof tool, which is what lets proof-backed claims attach later.

```typescript
import { SyncRecord } from '@trusset/sdk'

const records: SyncRecord[] = existingCustomers.map(row => ({
  externalId: row.customerId,
  name: row.fullName,
  walletAddress: row.ethAddress,
  country: row.countryCode,
  investorType: 'RETAIL',
  kycHash: row.kycRootHash,
  metadata: { source: 'core-banking', migrationBatch: '2025-Q1' },
}))

const result = await trusset.customers.sync.importRecords(records, {
  batchSize: 50,
  onConflict: 'update',
  onProgress: (done, total) => {
    console.log(`${done}/${total} processed`)
  },
})
```

The result counts each outcome separately:

| Field | Holds |
|---|---|
| `result.total` | Total records submitted |
| `result.created` | New customers created |
| `result.updated` | Existing customers updated |
| `result.skipped` | Skipped due to `onConflict: 'skip'` |
| `result.errors` | Array of `{ externalId, code, message }` |

The SDK processes records in configurable batches to avoid overloading the API. Each record is matched against existing customers by `externalId`. If a match is found, the `onConflict` strategy determines the outcome.

### Conflict strategies

| Strategy | Behavior |
|---|---|
| `update` | Overwrites name, country, investorType, walletAddress, and metadata on the existing record. Default. |
| `skip` | Leaves the existing record untouched. Counted in `result.skipped`. |

### Verify on-chain during import

Set `verifyOnChain: true` to batch-verify imported records on chain once the database import completes. It applies to records that were created or updated, not skipped, and that carry both a `walletAddress` and a `country`. Each record's `kycHash`, the root hash from the [KYC proof tool](/sdk/customers/kyc-proofs), goes into the on-chain verification, so proof-backed claims can be added later.

The verification transactions are signed by your registered issuer wallet, so `verifyOnChain` requires `signer`, any ethers v5 `Signer` for that wallet. The import throws a `ValidationError` before touching any record when `signer` is missing.

```typescript
const result = await trusset.customers.sync.importRecords(records, {
  onConflict: 'update',
  verifyOnChain: true,
  signer,
  verificationDefaults: {
    softExpiryDays: 365,
    hardExpiryDays: 730,
  },
})
```

On-chain verification failures do not roll back the database import. Entries the API rejects appear in `result.errors` with the API's code. When a whole verification batch fails, each of its entries appears with code `VERIFY_FAILED`. For these verification errors, `externalId` holds the wallet address of the entry rather than your customer ID.

<Expandable title="SyncOptions reference">
  <ParamField body="batchSize" type="number" default={50}>
    Records per API call. Range: 1-200. Higher values reduce HTTP overhead but increase per-request latency.
  </ParamField>
  <ParamField body="onConflict" type="string" default="update">
    `update` or `skip`. Determines behavior when a customer with the same `externalId` already exists.
  </ParamField>
  <ParamField body="verifyOnChain" type="boolean" default={false}>
    If `true`, batch-verifies addresses on the IdentityRegistry after import, in batches of up to 500. Only applies to created or updated records with both `walletAddress` and `country`. Requires `signer`.
  </ParamField>
  <ParamField body="signer" type="Signer">
    An ethers v5 `Signer` for the registered issuer wallet. Required when `verifyOnChain` is `true`. The SDK signs with it and never asks for the key.
  </ParamField>
  <ParamField body="confirmations" type="number" default={1}>
    Confirmations to wait for per verification batch before confirming it with Trusset. Range: 1-12.
  </ParamField>
  <ParamField body="verificationDefaults" type="object">
    Default `softExpiryDays` and `hardExpiryDays` for on-chain verification.
  </ParamField>
  <ParamField body="onProgress" type="function">
    Callback invoked after each batch: `(processed: number, total: number) => void`.
  </ParamField>
</Expandable>

## Export records

Pull all customer data back out as flat `SyncRecord` objects. Useful for syncing Trusset state back into your core systems or for audit purposes.

```typescript
const records = await trusset.customers.sync.exportRecords({
  includeArchived: false,
})
```

The method paginates internally and fetches all records regardless of total count. For very large datasets (50k+ customers), consider using the [list endpoint](/endpoints/customers/list) directly with pagination for more control.

## SyncRecord schema

Every record requires `externalId`. All other fields are optional.

```typescript
interface SyncRecord {
  externalId: string
  walletAddress?: string
  name?: string
  country?: string
  investorType?: string
  kycHash?: string
  metadata?: Record<string, unknown>
}
```

| Field | Holds |
|---|---|
| `externalId` | Your system's unique customer ID |
| `walletAddress` | Ethereum address |
| `name` | Display name |
| `country` | ISO country code |
| `investorType` | Preset or custom verification profile key |
| `kycHash` | Root hash from the KYC proof tool |

## Handle per-record errors

Import errors are collected per-record rather than failing the entire batch. The `errors` array in the result contains one entry per failed record:

```typescript
const result = await trusset.customers.sync.importRecords(records)

for (const err of result.errors) {
  console.error(`Failed ${err.externalId}: ${err.code}: ${err.message}`)
}
```

Common error codes:

| Code | Cause |
|---|---|
| `INVALID_ADDRESS` | Wallet address failed checksum validation |
| `CUSTOMER_EXISTS` | Duplicate wallet address (different externalId) |
| `VERIFY_FAILED` | On-chain batch verification failed for this entry; `externalId` holds its wallet address |
| `UNKNOWN` | Unexpected server error. Check `message` for details |
