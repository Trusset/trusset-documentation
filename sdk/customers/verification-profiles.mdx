title: "Verification Profiles"
description: "Read the reusable KYC requirement sets configured on your instance"
---

<Note>
  Verification profiles are in beta. The API surface is read-only. Create and edit profiles in the [Issuer Platform](https://issuers.trusset.org).
</Note>

A verification profile bundles a KYC requirement set: which documents an investor must provide, which Sumsub level applies, and which on-chain investor type a completed verification maps to. Every instance ships three presets, `RETAIL`, `PROFESSIONAL`, and `ELIGIBLE_COUNTERPARTY`, and can define custom profiles.

Profile keys are valid `investorType` values wherever the SDK accepts one: customer records, ID links, and identity verification.

## List profiles

```typescript
const profiles = await trusset.customers.profiles.list()

for (const profile of profiles) {
  console.log(profile.key, profile.enabled, profile.onChainInvestorType)
}
```

Presets are listed first. Each profile:

```typescript
interface VerificationProfile {
  id: string
  key: string
  name: string
  description: string | null
  onChainInvestorType: number
  sumsubLevelName: string
  requiredFields: ProfileRequiredField[]
  isPreset: boolean
  enabled: boolean
  onChainProfileId: number | null
  gateAddress: string | null
  createdAt: string
  updatedAt: string
}
```

`key` is what you pass as `investorType`. `onChainInvestorType` is the numeric classification: `1` Retail, `2` Professional, `3` Eligible Counterparty.

`onChainProfileId` and `gateAddress` are set once the profile is published to the instance's [ID register](/sdk/customers/identity#instance-id-registers), and `null` before (from 0.9.0). The register then holds the profile's rules: the [predicates](/sdk/customers/identity#predicates) it requires (`KYC_DONE`, and `RESIDENCY_ON_FILE` when the profile asks for proof of residence), the minimum investor class, and the maximum age of an attestation, taken from the profile's re-verification period. `gateAddress` is the profile's gate contract, which answers `isVerified` for this profile only. Point a market's borrower or provider gate, a vault or a profile-restricted token at it. A professional-only profile has minimum class `2`, so its gate refuses retail wallets on chain. Publish profiles in the issuer app.

`requiredFields` describes the document sets requested during a linked KYC flow, e.g. `{ idDocSetType: 'IDENTITY', types: ['PASSPORT', 'ID_CARD'], required: true, label: 'Government ID' }`.

## Use a custom profile

The profile key works anywhere an `investorType` is accepted.

```typescript
await trusset.customers.idLinks.create({
  recipientEmail: 'investor@example.com',
  investorType: 'my-custom-profile-key',
})
```

On chain, a custom profile resolves to its `onChainInvestorType`, because an attestation only carries the three MiFID II classifications. Its other requirements live in the profile's gate.
