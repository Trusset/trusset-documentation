Trusset is non-custodial infrastructure. It holds no client keys and no client assets.

## DORA, ISO, TÜV, GDPR, and audit documentation

Trusset provides a searchable database of regularly updated compliance documents. Those documents are currently being reviewed by TÜV as part of the final certification process. You can find the database in the [Issuer App](https://issuers.trusset.org/) under "Compliance Data Room".

<Tip>This allows issuers to forward the required infrastructure documentation to their authorities on request, with a full audit trail.</Tip>

## Secret management

Development and Staging secrets are managed via [Doppler](https://www.doppler.com/). Production secrets are managed via [HashiCorp Vault](https://www.hashicorp.com/products/vault), deployed in a hardened Docker container.

## Contract updates and roles

Trusset holds no role and no key on the identity contracts. The identity hub, one per chain, has no owner, cannot be upgraded and cannot be paused. Any wallet attests on it, but only under its own address. Each instance ID register is created by the client's own wallet through a factory any wallet can call, and every role on it goes to the client's wallets in the same transaction. The register decides which attesters it trusts, so relying on another institution's KYC is always the relying client's own choice. See [Which register you write to](/endpoints/customers/introduction#which-register-you-write-to).

## KYC proofs

Trusset never receives proof bytes. Proofs made with [KYC-STARKs](/tools/kyc-starks/overview) 3.1 are sound but not zero-knowledge: the STARK library it uses, Winterfell 0.13.1, has no hiding mode, so an age proof reveals the date of birth, a set-membership proof the country and a tier proof the investor class. Verification is therefore local. The institution verifies the proofs on its own machines with the tool or the SDK, and sends Trusset the manifest and the header it signed. Trusset checks the header signature against the operator key the attester publishes on the identity hub, and the leaves and the root against the header. Every proof endpoint refuses proof bytes with `PROOFS_NOT_ACCEPTED`, and a manifest that carries personal values in clear text with `PERSONAL_DATA_IN_MANIFEST`. No STARK is verified on chain.

[Disclosure requests](/endpoints/customers/create-disclosure-request) follow the same rule. A holder's browser encrypts the disclosed proofs to the requesting institution's record key with HPKE, and the holder's wallet signs a consent that names the digest of that exact envelope. Trusset relays and stores only the ciphertext and a header without personal data, holds no key that opens it, and verifies no disclosed proof. It deletes the ciphertext when the institution opens it, rejects it, or leaves it uncollected for 30 days. The institution decrypts and verifies the proofs on its own machine. See [Disclosures from a holder](/protocol/infrastructure/sealed-kyc-records#disclosures-from-a-holder).

## Audits

Softstack audited the full smart contract protocol in May 2026. Read the [audit report](https://www.trusset.org/audits/trusset-audit.pdf).

## Audit policy

Once a year, Trusset renews all security audits with a chosen third-party auditor based in the EU.

ISO certification with TÜV is in progress and not yet complete. Once it is granted, it enters the same annual renewal cycle.

## App updates

Updates undergo a strict, 3-step process that is defined internally and in the Trusset compliance documentation.
