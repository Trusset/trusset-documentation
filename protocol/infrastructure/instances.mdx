This page is for the engineer or operator setting up a Trusset environment. After reading it you will know what an instance isolates, what is permanent about one, and how production instances are granted.

Instances are isolated environments that control access to Trusset APIs on your chosen blockchain network. Each instance operates independently with dedicated API keys, data storage, and smart contract deployments.

<Note>
Instances are free to create. No setup fees or monthly charges.
</Note>

## Instance types

Separate development and production environments for safe testing before mainnet deployment:

<Tabs>
    <Tab title="Development Instances">
        Run on the testnet of the chosen network:

        - Free testnet tokens for gas fees
        - Isolated from mainnet operations
        - Reset anytime without consequences
        - Available to every account

        The products on a testnet are not always the ones on its mainnet. [Networks](/protocol/infrastructure/networks) lists what runs for development and for production instances on each network.
    </Tab>
    
    <Tab title="Production Instances">
        Run on the mainnet of the chosen network, with real assets:

        - Requires real tokens for gas fees
        - Immutable smart contract deployments
        - Irreversible transactions
        - Subject to network fees
        - Need production access granted by Trusset

        Without production access, creating one is refused with `403 PRODUCTION_ACCESS_REQUIRED`. Request access at hello@trusset.de.
    </Tab>
</Tabs>

## Choose the target network

Choose your blockchain network during instance creation. This decision is permanent. Every asset, market and identity of the instance is written to that chain, but only the products Trusset has deployed there for the instance type work on it. [Networks](/protocol/infrastructure/networks) lists them per network for development and production instances, and `GET /public/networks` returns the same list. The Create Instance dialog marks a network without any deployment for the chosen type as not yet available.

A product that is not deployed for the instance's network and type answers HTTP `501` with its code, for example `SECURITY_LENDING_V2_NOT_CONFIGURED`. Customer verification still works on every EVM network when the instance is bound to an identity register you control.

| API Keys per Instance | 10 active |
| Data Storage | Usage-based pricing (coming soon) |

*verified_services = number of licensed service categories you hold (tokenization, trading, lending, etc.)

## Manage API keys

Each instance supports up to 10 active API keys with independent permissions and rate limits. Keys are created, rotated, and revoked through the Issuer Platform. See [Authentication](/endpoints/authentication) for key format and rotation details.

A rotated key enters `PENDING_ROTATION` and stays valid for 7 days, which is the window to move every consumer across.

## Service isolation

Data never leaks between instances - complete isolation at every level:

- **Database Isolation:** Each instance stores data in separate encrypted databases inaccessible to other instances.

- **Smart Contract Isolation:** Instance-specific contracts deploy independently - no shared state or cross-instance calls.

- **API Isolation:** API keys only access their instance's resources - cannot query other instances even accidentally.

- **Network Isolation:** Instances on different blockchains operate completely independently.

## Go to production

<Warning>
Production instances act on real assets. Test exhaustively on a development instance first: bugs in production lose real money.
</Warning>

A development instance does not convert into a production one, and there is no migration in the Issuer Platform. Going live means a new instance:

<Steps>
  <Step title="Request production access">
    Write to hello@trusset.de, or use **Request access** next to Production in the Create Instance dialog. Trusset grants access per account. Until then, a production instance is refused with `403 PRODUCTION_ACCESS_REQUIRED`.
  </Step>

  <Step title="Check the network">
    Confirm on [Networks](/protocol/infrastructure/networks) that the products you need run for production instances on your network.
  </Step>

  <Step title="Create the production instance">
    Create it in the Issuer Platform with the instance type Production. It gets its own instance ID and API keys.
  </Step>

  <Step title="Update integrations">
    Point your backend at the production instance's API keys. Customers, markets and assets of the development instance stay there.
  </Step>
</Steps>
