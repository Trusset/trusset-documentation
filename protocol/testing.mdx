A development instance runs the same API and the same contracts as production, on a testnet and with test tokens. It is free, API calls on it are unlimited, and it can be reset without consequence. Create one in the [Issuer Portal](https://issuers.trusset.org). [Instances](/protocol/infrastructure/instances) covers the types and limits.

On Ethereum, development instances run on Sepolia with the full lending stack: the Trusset ID Register, external securities lending, operator vaults, whitelists and liquidation bots. [Networks](/protocol/infrastructure/networks) lists what runs where, and the contract addresses.

## Test funds

[List Borrow Assets](/endpoints/lending/list-borrow-assets) offers test versions of USDC, USDT, DAI, EURC and EUROP on development networks, marked `(Mock)` in their names. `mintable` says whether a test token can be minted there. Gas comes from the network's free testnet tokens.

## What you can reproduce

There is no simulation endpoint. Every event below happens on the testnet contracts, through the same calls production uses. Playing the bank's side needs an instance approved as a lender of record: taking a market is refused with `CURATOR_NOT_APPROVED` otherwise.

| Scenario | How to reproduce it |
|---|---|
| A borrower draws, tops up and repays | Act as the borrower from a test wallet with [Open Loan](/endpoints/lending/open-loan), [Add Collateral](/endpoints/lending/add-collateral) and [Repay Loan](/endpoints/lending/repay) |
| A price drop makes a position liquidatable | Push a lower price as the market's price signer with [Sync Oracle Price](/endpoints/lending/sync-oracle). One push moves the price by at most the oracle's deviation bound, 50 percent by default, and so does one hour of pushes |
| A liquidation and its settlement | Liquidate from a wallet with the liquidator role, then run the router steps with [Withdraw Collateral for Sale](/endpoints/lending/withdraw-collateral-for-sale) and [Settle Liquidation](/endpoints/lending/settle-liquidation) |
| A vault deposit with distributor attribution | Build the deposit with [Deposit](/endpoints/vaults/deposit) from the instance that should be credited, and approve it with [Set Distributor Approval](/endpoints/vaults/set-distributor-approval) |
| A refused borrower or depositor | Use a wallet that is not on the market's or vault's register |
| A paused market or a price halt | Pause with [Pause Market](/endpoints/lending/pause-market), halt with [Halt Prices](/endpoints/lending/halt-prices), then try each path |

## What only real time shows

Interest accrues every second, on the testnet as on mainnet, and nothing advances the clock. Three scenarios therefore take as long as they would in production:

- **A stale price.** A price turns stale once it is older than `maxPriceAge`, 24 hours by default.
- **A term realization.** A termed loan becomes realizable after its due date plus grace, 3 days by default.
- **A liquidation write-off.** [Handle Liquidation Timeout](/endpoints/lending/handle-timeout) accepts a liquidation only after 7 days unsettled.

Plan these as long-running tests, or test the code that reacts to them against the documented responses.

## Moving to production

A development instance does not turn into a production one. Going live means a new production instance, with its own ID and API keys, and production access granted by Trusset. Customers, markets and assets stay on the development instance. See [Go to production](/protocol/infrastructure/instances#go-to-production).
