---
title: 'Get Delivery Status'
api: 'GET /kyc-inbox/{sourceId}/records/{envelopeId}'
authMethod: 'bearer'
description: 'What happened to a record you delivered'
---

Returns where a delivered record stands at the bank: whether it was opened, approved, rejected or revoked, and whether its wallet is listed on the bank's whitelists. You see only records delivered through your own inbox, looked up by the `envelopeId` you chose.

The answer holds what your header already stated plus the bank's decisions. It never returns anything from inside the record.

## Path Parameters

<ParamField path="sourceId" type="string" required>
  Your source ID, from the invite.
</ParamField>

<ParamField path="envelopeId" type="string" required>
  The `envelopeId` of the delivery, 32 lowercase hex characters.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="envelopeId" type="string">The envelope ID.</ResponseField>
    <ResponseField name="recordDigest" type="string">The `recordDigest` from your header. [Revoke Record](/endpoints/kyc-inbox/revoke-record) takes it.</ResponseField>
    <ResponseField name="walletAddress" type="string">The wallet, checksummed.</ResponseField>
    <ResponseField name="status" type="string">`RECEIVED`, `OPENED`, `APPROVED`, `REJECTED`, `REVOKED`, `EXPIRED`, `UNCLAIMED` or `SUPERSEDED`. See [What happens to a record](/endpoints/kyc-inbox/introduction#what-happens-to-a-record).</ResponseField>
    <ResponseField name="receivedAt" type="string">When Trusset received the envelope, ISO 8601.</ResponseField>
    <ResponseField name="openedAt" type="string">When the bank proved it decrypted the record, or `null`.</ResponseField>
    <ResponseField name="approvedAt" type="string">When the bank approved it, or `null`.</ResponseField>
    <ResponseField name="rejectedAt" type="string">When it was rejected, or `null`.</ResponseField>
    <ResponseField name="rejectReason" type="string">`BAD_SIGNATURE`, `DIGEST_MISMATCH`, `UNKNOWN_SOURCE_KEY`, `UNDECRYPTABLE`, `INCOMPLETE` or `NOT_ACCEPTED`, or `null`.</ResponseField>
    <ResponseField name="revokedAt" type="string">When you revoked it, or `null`.</ResponseField>
    <ResponseField name="validUntil" type="string">The `validUntil` from your header.</ResponseField>
    <ResponseField name="admitted" type="boolean">`true` when the record is `APPROVED` and the bank's records show the wallet listed on every whitelist bound to your source. `false` otherwise. `null` when the bank bound no whitelist to your source.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  `admitted` follows the whitelist records the bank confirmed on Trusset. A listing takes effect on chain when the bank's transaction mines, which can be before the bank confirms it.
</Note>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/kyc-inbox/cmhw2a6r10003l80c9d4h1n8v/records/75aa6ca04ca5ab4223136c3bea128de0" \
  -H "Authorization: Bearer tki_your_token_here"
```
```typescript TypeScript
const res = await fetch(
  `${invite.api}/kyc-inbox/${invite.sourceId}/records/${envelopeId}`,
  { headers: { Authorization: `Bearer ${invite.token}` } }
);
const { data } = await res.json();

if (data.status === 'REJECTED') {
  console.warn(`Rejected by the bank: ${data.rejectReason}`);
}
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `UNAUTHORIZED` | `401` | The token is missing, malformed or wrong, the `sourceId` is unknown, or the bank removed the source |
| `RECORD_NOT_FOUND` | `404` | No record with this `envelopeId` was delivered through your inbox |
| `RATE_LIMIT_EXCEEDED` | `429` | A rate limit was exceeded. See [Rate limits](/endpoints/kyc-inbox/introduction#rate-limits) |
| `KYC_STATUS_FAILED` | `500` | The status could not be read |
