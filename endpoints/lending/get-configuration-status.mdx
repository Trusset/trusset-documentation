---
title: 'Get Configuration Status'
api: 'GET /lending-external-securities-v2/api/markets/{marketId}/configuration-status'
description: 'Check whether a market is ready to accept loans, and what is still outstanding'
---

Returns a single readiness verdict, the individual checks behind it, and ready-to-sign calldata for every outstanding step. Each step names the authority that must sign it and says whether a wallet of your instance holds that authority. Poll this after deployment and after each authorization step until `fullyConfigured` is `true`.

Readiness spans three parties. Contract wiring is set up by the factory at deployment and rarely needs attention. The market admin and the oracle owner exist only once a lender of record has taken the market. Token-side authorization depends on parties outside Trusset: the collateral token's agent administrator, its compliance administrator and its identity registry operator. That layer is the one that usually blocks a new market.

## Path Parameters

<ParamField path="marketId" type="string" required>Market ID.</ParamField>

## Step Keys

| Key | Offered when | Signed by |
|---|---|---|
| `setInsuranceFund` | No insurance fund is set on the market | The market admin |
| `grantAgentRoleToAdapter` | `FREEZE`: the adapter lacks the agent role | The collateral token's agent administrator |
| `authorizeAdapterOnToken` | `CUSTODY`: the token gates holders through its own contract allow-list | The collateral token's compliance administrator |
| `verifyAdapterAsHolder` | `CUSTODY`: the token gates holders through an identity registry | An agent of that registry |
| `authorizeRouterOnToken` | The router must be allow-listed on the token | The collateral token's compliance administrator |
| `verifyRouterAsHolder` | The router must be registered on the token's identity registry | An agent of that registry |
| `authorizeVenueOnToken` | An auction venue is wired and must be allow-listed on the token | The collateral token's compliance administrator |
| `verifyVenueAsHolder` | An auction venue is wired and must be registered on the token's identity registry | An agent of that registry |
| `authorizeRelayerOnOracle` | The instance's wallet cannot sign prices on the oracle | The oracle owner |
| `grantLiquidatorRole` | The instance's wallet lacks `LIQUIDATOR_ROLE` | The market admin |

The key is the `action` to name on [Configure Market](/endpoints/lending/configure-market) and [Confirm Configuration](/endpoints/lending/confirm-configuration).

## Requirement Values

| `requirement` | Meaning | Resolved by |
|---|---|---|
| `adapter_must_hold_agent_role` | `FREEZE` mode. The adapter needs the agent role on the collateral token | The token's agent administrator |
| `token_not_freeze_compatible` | The token does not implement the freeze interface, so `FREEZE` mode is impossible. Redeploy in `CUSTODY` mode | Not resolvable |
| `adapter_must_be_verified_holder` | `CUSTODY` mode. The adapter must be a verified holder on the token's identity registry | The token's identity registry operator |
| `adapter_must_be_authorized_contract` | `CUSTODY` mode. The adapter must be allow-listed on the collateral token itself | The token's compliance administrator |
| `none_required` | The token exposes neither an identity registry nor a contract allow-list, so there is nothing to authorize on it | Nobody, see the warning below |
| `holder_status_unreadable` | The token or its registry could not be read, so authorization is unknown | Retry |
| `adapter_not_deployed` | No adapter address is recorded on the market | Contact Trusset |
| `unknown` | The check could not complete, usually an RPC failure | Retry |

## Blocked Step Codes

| `code` | Meaning |
|---|---|
| `IDENTITY_REGISTRY_UNRECOGNISED` | The registry answers neither the Trusset registry interface nor the ERC-3643 reference interface. The token issuer has to authorize the subject on it directly |
| `IDENTITY_REGISTRY_WRITE_REJECTED` | Replayed from your instance's wallet, the registration reverts. The registry's own agent, usually the token issuer's KYC operator, must send it |
| `ONCHAINID_REQUIRED` | The ERC-3643 registry admits a holder only through an ONCHAINID, and the subject has none. The token issuer's KYC operator issues it. Then pass `identityAddress` to [Configure Market](/endpoints/lending/configure-market) |
| `IDENTITY_CLAIMS_REQUIRED` | The subject is registered, but its ONCHAINID carries no valid claim for a required topic from a trusted issuer |
| `IDENTITY_ALREADY_REGISTERED` | The subject already holds a valid ONCHAINID on the registry. Refresh to pick up the registry's answer |
| `CLAIM_TOPICS_UNREADABLE` | The ERC-3643 registry did not return the claim topics it requires |

<Warning>
  With `none_required`, the adapter and the router both report as authorized, because nothing the platform can read gates who holds the token. That is not proof of eligibility. If the token restricts transfers through a surface this platform cannot read, only its issuer can admit the adapter and the router, and a liquidation would fail until it does. Verify out of band before letting borrowers in.
</Warning>

<Tip>
  This endpoint tells you what is unfinished and who signs it. [Get Setup Steps](/endpoints/lending/get-setup-steps) returns the same state as an ordered checklist that starts with the lender-of-record step. [Configure Market](/endpoints/lending/configure-market) returns one step's calldata on request.
</Tip>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/lending-external-securities-v2/api/markets/{marketId}/configuration-status" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const res = await fetch(
  `https://api.trusset.org/lending-external-securities-v2/api/markets/${marketId}/configuration-status`,
  { headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { data } = await res.json();

for (const [key, step] of Object.entries(data.configurationCalldata)) {
  if (step.heldByThisInstance === true) console.log(`Sign ${key} yourself`, step);
  else console.log(`Send ${key} to ${step.requiredAuthority}`);
}
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `NO_MARKET_ADDRESS` | `400` | The market has no on-chain address recorded |
| `MISSING_MARKET_ID` | `400` | `marketId` is longer than 100 characters |
| `MARKET_NOT_FOUND` | `404` | No market with this ID on your instance |
| `ROUTER_UNRESOLVED` | `503` | The record carries no router address and the market's router could not be read. Retry |
