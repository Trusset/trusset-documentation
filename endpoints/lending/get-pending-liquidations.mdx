---
title: 'Get Pending Liquidations'
api: 'GET /lending-external-securities-v2/api/liquidations/{marketId}/pending-liquidations'
description: 'List liquidations awaiting settlement'
---

Returns the market's liquidation records that are neither settled nor written off. Most are router records whose collateral sits at the router awaiting the manual settlement workflow. A record whose Dutch auction is still open appears too, under a `venue-` ID, until the auction sells out or hands its remainder to the router.

Before reading, the endpoint reconciles against the chain. It adopts any record on the market's router the backend has not recorded, so a liquidation triggered outside this API still appears here once its collateral reaches the router. It also closes records the router has settled since, including atomic sales, when the confirm call for that settlement never arrived.

## Path Parameters

<ParamField path="marketId" type="string" required>The market's record ID, as `id` on [List Markets](/endpoints/lending/list-markets), not its contract address. See [Market IDs](/endpoints/lending/list-markets#market-ids). At most 100 characters.</ParamField>

        <ResponseField name="loanId" type="string">Loan that was liquidated.</ResponseField>
        <ResponseField name="marketAddress" type="string">Market contract.</ResponseField>
        <ResponseField name="collateralAmount" type="string">Collateral seized at liquidation.</ResponseField>
        <ResponseField name="debtOwed" type="string">Debt the proceeds must cover.</ResponseField>
        <ResponseField name="tokenAddress" type="string">Collateral token.</ResponseField>
        <ResponseField name="borrower" type="string">Borrower whose loan was liquidated.</ResponseField>
        <ResponseField name="termRealization" type="boolean">`true` when the loan was realized on its expired term rather than on its health.</ResponseField>

        <ResponseField name="status" type="string">`PENDING` for every record in this list.</ResponseField>
        <ResponseField name="realization" type="string">How the collateral is being realized: `ROUTER` for a record on the router, `VENUE` while its auction runs. `null` when the record does not state it.</ResponseField>
        <ResponseField name="settledTxHash" type="string">`null`, except on a record the router administrator reopened after a settlement, where it keeps that settlement's hash.</ResponseField>
        <ResponseField name="createdAt" type="string">ISO 8601 timestamp of the seizure. Adopted records are backdated to the time the router received the collateral.</ResponseField>
        <ResponseField name="onChainData" type="object">Live router state, or `null` when the read failed and on every `venue-` record.</ResponseField>
        <ResponseField name="proceedsHeld" type="string">Cash the auction venue forwarded for this record that the market holds until the record settles, in borrow asset units. `null` when unknown.</ResponseField>
        <ResponseField name="proceedsForwarded" type="string">Cash the auction venue has forwarded for this record's auction in total. `null` without an auction.</ResponseField>
        <ResponseField name="heldOnMarket" type="boolean">`true` when `proceedsHeld` is above zero. Such a record can settle at zero proceeds over the held cash.</ResponseField>
        <ResponseField name="marketSettled" type="boolean">Whether the market has already settled or written off its own record. `null` when unknown.</ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

## On-Chain Data

`onChainData` is the authoritative view of what the router still holds.

<ResponseField name="onChainData" type="object">
  <Expandable>
    <ResponseField name="collateralAmount" type="string">Collateral originally received.</ResponseField>
    <ResponseField name="collateralRemaining" type="string">Collateral still held. Decreases as it is withdrawn for sale.</ResponseField>
    <ResponseField name="debtOwed" type="string">Debt to be covered, in borrow asset units.</ResponseField>
    <ResponseField name="proceedsCollected" type="string">Proceeds deposited so far, in borrow asset units. Increases with each reported partial sale.</ResponseField>
    <ResponseField name="borrower" type="string">Borrower address.</ResponseField>
    <ResponseField name="lendingMarket" type="string">Contract that delivered the collateral: the market, or its auction venue for the remainder of an expired auction.</ResponseField>
    <ResponseField name="token" type="string">Collateral token.</ResponseField>
    <ResponseField name="routerAddress" type="string">Router holding the position.</ResponseField>
    <ResponseField name="timestamp" type="integer">Unix seconds the router received the collateral. This is when the 7 day write-off clock starts. For the remainder of an expired auction the clock started earlier, at the seizure into the auction.</ResponseField>
    <ResponseField name="settled" type="boolean">Whether the router considers the liquidation closed.</ResponseField>
    <ResponseField name="marketLiquidationId" type="string">Market-local ID.</ResponseField>
  </Expandable>
</ResponseField>

<Warning>
  A router query for a liquidation ID that does not exist returns a zero-filled object rather than null. Treat `onChainData.timestamp === 0` as "not found", not as a valid timestamp.
</Warning>

<Note>
  Track progress with `collateralRemaining` and `proceedsCollected` rather than `status`. Withdrawing collateral for sale and reporting partial sales both leave `status` at `PENDING`. Only settlement, a router close or a write-off changes it.
</Note>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/lending-external-securities-v2/api/liquidations/{marketId}/pending-liquidations" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const res = await fetch(
  `https://api.trusset.org/lending-external-securities-v2/api/liquidations/${marketId}/pending-liquidations`,
  { headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { data } = await res.json();

const overdue = data.pendingLiquidations.filter(l => {
  const t = l.onChainData?.timestamp;
  return t && Date.now() / 1000 - t > 7 * 86400;
});
```
</RequestExample>

The filter above reads the router's clock, which can start later than the market's for an auction remainder. The `eligibleAt` that [Handle Liquidation Timeout](/endpoints/lending/handle-timeout) returns when it refuses is exact.

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `MISSING_MARKET_ID` | `400` | `marketId` is longer than 100 characters |
| `MARKET_NOT_FOUND` | `404` | No market with this ID on your instance |

A failed database read answers `200` with an empty list rather than an error.
