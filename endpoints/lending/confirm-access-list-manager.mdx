---
title: 'Confirm Whitelist Manager'
api: 'POST /lending-external-securities-v2/api/access-lists/{listId}/managers/confirm'
description: 'Record the managers a mined setManager transaction added or removed'
---

Verifies a mined `setManager` transaction on the whitelist, reads its `ManagerSet` events, and records the list's managers as the chain answers them after that block. Only the instance that keeps the list confirms. The change is written to the audit log as `LENDING_ACCESS_LIST_MANAGER_SET`.

This is also the confirm leg of the add-the-lender-as-manager step that [Get Identity Gates](/endpoints/lending/get-identity-gates#gates-built-on-whitelists) and [Confirm Lender Role](/endpoints/operators/confirm-lender-role) offer.

## Path Parameters

<ParamField path="listId" type="string" required>
  The whitelist ID from [List Whitelists](/endpoints/lending/list-access-lists). The list must be kept by your instance.
</ParamField>

## Body Parameters

<ParamField body="txHash" type="string" required>
  Hash of the mined `setManager` transaction, 0x followed by 64 hex characters.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="list" type="object">The recorded list after the change, with the fields of [List Whitelists](/endpoints/lending/list-access-lists) apart from `own`.</ResponseField>
    <ResponseField name="applied" type="array">One entry per account the transaction touched: `account`, `enabled` as the transaction set it, and `current`, whether the account is a manager now.</ResponseField>
    <ResponseField name="txHash" type="string">The verified transaction.</ResponseField>
    <ResponseField name="signedBy" type="string">The wallet that sent the transaction, lowercased.</ResponseField>
  </Expandable>
</ResponseField>

<RequestExample>
```bash cURL
curl -X POST "https://api.trusset.org/lending-external-securities-v2/api/access-lists/cmv2k8q1d0004l70a3n6p2w9e/managers/confirm" \
  -H "X-API-Key: trusset_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"txHash": "0x5c8e1a7f9b3d2046e1c7a9f08b4d6e2317c5a0f9e8d7b6c5a4f3e2d1c0b9a8f7"}'
```
```typescript TypeScript
const res = await fetch(
  `https://api.trusset.org/lending-external-securities-v2/api/access-lists/${listId}/managers/confirm`,
  {
    method: 'POST',
    headers: { 'X-API-Key': 'trusset_your_key_here', 'Content-Type': 'application/json' },
    body: JSON.stringify({ txHash })
  }
);
const { data } = await res.json();
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `VALIDATION_ERROR` | `400` | `txHash` is missing or malformed |
| `TX_NOT_VERIFIED` | `400` | The transaction set no manager on this list |
| `NOT_ACCESS_LIST_OWNER` | `403` | Another instance keeps the list. `details` names the owner |
| `ACCESS_LIST_NOT_FOUND` | `404` | No whitelist with this ID is kept by your instance, or managed or pending to one of its wallets, on this network |
| `ACCESS_LIST_MANAGER_CONFIRM_FAILED` | `500` | The change could not be recorded and no more specific code applied |
| `ACCESS_LISTS_NOT_CONFIGURED` | `503` | The whitelist factory is not deployed on this network |
| `ACCESS_LIST_UNREADABLE` | `503` | The managers could not be read after the transaction's block, so nothing was recorded. Retry shortly |
| `SERVICE_UNAVAILABLE` | `503` | Your instance's verified wallets could not be read. Retry shortly |

The confirm call can also return any [transaction verification error](/endpoints/introduction#confirm-a-transaction).
