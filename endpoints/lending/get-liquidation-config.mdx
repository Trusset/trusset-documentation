---
title: 'Get Liquidation Config'
api: 'GET /lending-external-securities-v2/api/liquidations/{marketId}/config'
description: 'Check whether a market can be liquidated and settled'
---

Returns the readiness of the liquidation path for a market: every gate `liquidate` passes through, the onward delivery of seized collateral to the sale recipient, and aggregate liquidation counters.

Call this before relying on liquidation. A market can accept loans while its liquidation path is incomplete, which leaves bad debt with no remedy.

Realization is two hops with two different signers, so readiness carries two aggregates. `seizureConfigured` covers everything up to and including moving collateral to the router, or to the auction venue when Dutch auctions are on. `isConfigured` covers that and more: the router's operator must hold its role, and the collateral must be able to leave the router for the sale recipient.

## Path Parameters

<ParamField path="marketId" type="string" required>Market ID. At most 100 characters.</ParamField>

## Query Parameters

<ParamField query="signerAddress" type="string">
  Wallet to evaluate the liquidator role against. Omit to use your instance's primary verified wallet. Anything that is not a valid address is ignored.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="marketId" type="string">Market ID.</ResponseField>
    <ResponseField name="marketAddress" type="string">Market contract.</ResponseField>
    <ResponseField name="liquidationRouterAddress" type="string">This market's liquidation router, resolved per market. Also present as `routerAddress`.</ResponseField>
    <ResponseField name="routerAuthorized" type="boolean">The router accepts liquidations originating from this market. Set by the factory at deployment. `null` when the read failed.</ResponseField>
    <ResponseField name="routerTokenEligible" type="boolean">The router can legally receive the collateral token under the token's own compliance rules, either as an allow-listed contract or as a verified identity. Without this, seizing collateral reverts. `null` when the token could not answer.</ResponseField>
    <ResponseField name="routerTokenRequirement" type="string">What the token asks of the router: `adapter_must_be_authorized_contract`, `adapter_must_be_verified_holder`, `none_required`, `holder_status_unreadable` or `unknown`. `null` when no router or no collateral token is known.</ResponseField>
    <ResponseField name="liquidatorRoleReady" type="boolean">Whether `LIQUIDATOR_ROLE` on the market, which calling `liquidate` requires, is held by `signerAddress` or by a connected liquidation bot. `null` when it could not be read.</ResponseField>
    <ResponseField name="liquidatorViaBot" type="boolean">`true` when a connected liquidation bot rather than the signer wallet holds `LIQUIDATOR_ROLE`. `liquidatorBotAddress` names the bot.</ResponseField>
    <ResponseField name="operatorRoleReady" type="boolean">Whether `operatorAddress` holds `OPERATOR_ROLE` on the router, which withdrawal, partial sales and settlement require. `null` when the read failed.</ResponseField>
    <ResponseField name="operatorAddress" type="string">The address the operator-role check ran against: the liquidation operator the market records, or `signerAddress` when it records none. `operatorDeclared` says which.</ResponseField>
    <ResponseField name="signerAddress" type="string">The address the liquidator-role check resolved against, or `null` when none was available.</ResponseField>
    <ResponseField name="collateralTransferAllowed" type="boolean">Whether the collateral token would permit the seizure transfer from the custody adapter to the router. `null` when the check did not run. It never runs on a `FREEZE` market, where seizure is a forced transfer that bypasses the sender-side gates, or while the adapter holds no collateral. `collateralTransferChecked` says whether it ran, `collateralTransferCode` carries the restriction code below and `collateralTransferReason` states it in words.</ResponseField>
    <ResponseField name="saleRecipient" type="string">The recipient the lender of record fixed for onward sale, or `null` when none is set yet.</ResponseField>
    <ResponseField name="saleRecipientFixed" type="boolean">`true` when the router's recipient was read, `null` when the router could not be read.</ResponseField>
    <ResponseField name="saleRecipientRotatable" type="boolean">`true` for every market with a router. The router admin can rotate the recipient through an announced, delayed flow, which this API does not expose.</ResponseField>
    <ResponseField name="saleVenue" type="string">The destination that applies: `saleRecipient`, or the trading venue recorded for the market (`configuredSaleVenue`) when no recipient is known.</ResponseField>
    <ResponseField name="saleDeliveryAllowed" type="boolean">Whether the collateral token would permit the onward transfer from the router to `saleRecipient`. `saleDeliveryChecked`, `saleDeliveryCode` and `saleDeliveryAmount` accompany it.</ResponseField>
    <ResponseField name="dutchAuctionEnabled" type="boolean">The market's `useDutchAuction` switch. With it on, a health liquidation delivers the collateral to the auction venue instead of the router.</ResponseField>
    <ResponseField name="auctionVenue" type="string">The auction venue wired on the market, or `null`.</ResponseField>
    <ResponseField name="auctionVenueAdmitted" type="boolean">Whether the collateral token admits the venue as a holder. A market with Dutch auctions on and a venue the token refuses cannot seize at all. `auctionVenueRequirement` says what the token asks of the venue.</ResponseField>
    <ResponseField name="priceStale" type="boolean">Whether the oracle price sits outside its window, which makes `liquidate` revert. `priceAge` in seconds accompanies it.</ResponseField>
    <ResponseField name="seizureConfigured" type="boolean">Every gate up to and including the seizure is satisfied, including the liquidator role.</ResponseField>
    <ResponseField name="isConfigured" type="boolean">`seizureConfigured`, plus the router's operator role and onward delivery to the sale recipient.</ResponseField>
    <ResponseField name="canSeizeNow" type="boolean">`seizureConfigured`, and the price was read and is not stale.</ResponseField>
    <ResponseField name="canRealizeNow" type="boolean">`isConfigured`, and the price was read and is not stale.</ResponseField>
    <ResponseField name="readFailed" type="boolean">`true` when at least one gate could not be read. `unverifiedSections` lists which, `errors` carries the same as objects, and `unverifiedReason` states it in one sentence. A failed read is never reported as a closed gate.</ResponseField>
    <ResponseField name="blockedConfirmed" type="boolean">`true` only when a gate was actually read and found closed. `seizureBlockedConfirmed` is the same restricted to the seizure gates.</ResponseField>
    <ResponseField name="blockedReason" type="string">The first gate that fails, in words. When nothing is confirmed closed it carries `unverifiedReason`, which is `null` when every read succeeded.</ResponseField>
    <ResponseField name="stats" type="object">
      <Expandable>
        <ResponseField name="totalLiquidations" type="integer">Liquidation records the market has opened over its lifetime, on either trigger and on either path.</ResponseField>
        <ResponseField name="pendingLiquidationDebt" type="string">Debt seized but not yet settled or written off, in borrow asset units.</ResponseField>
        <ResponseField name="totalAuctions" type="integer">Dutch auctions the market's auction venue has opened. `0` when no venue is wired.</ResponseField>
        <ResponseField name="readFailed" type="boolean">Present and `true` when a counter could not be read. The unread counters then read `0`.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="onChainError" type="string">Present when the readiness read failed as a whole. The readiness fields and `stats` are absent in that case.</ResponseField>
  </Expandable>
</ResponseField>

<Warning>
  `routerTokenEligible` is reported as `true` when the collateral token exposes no identity registry and no contract allow-list, because eligibility cannot be evaluated without one. That is an unknown, not a pass. `routerTokenRequirement` reads `none_required` in that case. Confirm the router's compliance status out of band for such markets.
</Warning>

<Note>
  The two role flags answer for different wallets. `liquidatorRoleReady` answers for `signerAddress`, or your instance's primary verified wallet when it is omitted, and also counts a connected liquidation bot. `operatorRoleReady` answers for the liquidation operator the market records, and falls back to that same wallet only when the market records none. The settlement endpoints of this API check `OPERATOR_ROLE` against your instance's primary verified wallet, so a market whose operator is a different wallet settles outside this API.
</Note>

## Transfer Restriction Codes

`collateralTransferCode` and `saleDeliveryCode` are the collateral token's own transfer restriction codes. `0` means the transfer is permitted, and `null` means the check did not run.

| Code | Meaning | Lever that lifts it |
|---|---|---|
| `1` | The sender is not a verified holder on this token | Restore the sender's verified status on the token's identity registry, or allow-list it on a token without a registry |
| `2` | The receiver is not a verified holder on this token | Restore the receiver's verified status on the token's identity registry, or allow-list it on a token without a registry |
| `3` | The sender address is frozen on this token | Unfreeze the sender address |
| `4` | The receiver address is frozen on this token | Unfreeze the receiver address |
| `5` | The token compliance module rejects this transfer | Lift the restriction on the token's compliance contract |
| `6` | The token is paused | Un-pause the token |
| `7` | The sender does not hold enough of the collateral token | Fund the sender's balance of the collateral token |

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `MISSING_MARKET_ID` | `400` | `marketId` is longer than 100 characters |
| `NO_MARKET_ADDRESS` | `400` | The market has no on-chain address recorded |
| `MARKET_NOT_FOUND` | `404` | No market with this ID on your instance |
