---
title: 'Sign Price'
api: 'POST /lending-external-securities-v2/api/markets/{marketId}/sign-price'
description: 'Produce an EIP-712 signed price for atomic use in a transaction'
---

Returns an EIP-712 payload for a NAV, ready to sign. Sign it with a key authorized on the market's oracle. Then pass the price and the signature as `signedPrice` on [Open Loan](/endpoints/lending/open-loan), [Borrow More](/endpoints/lending/borrow-more), [Withdraw Collateral](/endpoints/lending/withdraw-collateral), [Repay](/endpoints/lending/repay) or [Liquidate Loan](/endpoints/lending/liquidate). The contract applies the price and the action in one transaction.

<Warning>
  A signed price does not stay private to the transaction that carries it. When it lands, the oracle stores it, and every loan in the market is valued at it from then on. Sign only a price the market's price authority stands behind.
</Warning>

This is the alternative to [Sync Oracle Price](/endpoints/lending/sync-oracle). Signing costs no gas and writes nothing on-chain; the price lands only with the transaction that carries it. That suits a borrower who needs a fresh valuation without waiting for a scheduled push. A key that signs outside this instance can also post its signature to [Record Price Attestation](/endpoints/lending/record-price-attestation), which lets a later push submit it.

An `ORACLE`-priced market reads an external feed and refuses every attested price. This endpoint refuses it with `EXTERNAL_FEED_ACTIVE`.

A `FIXED` market's oracle refuses every signed price too, so there is nothing to sign. This endpoint answers `409 FIXED_PRICE_ACTIVE` with `details.markDownOnly: true`. The price authority can only mark a fixed price down, through [Sync Oracle Price](/endpoints/lending/sync-oracle#mark-down-a-fixed-price).

## Path Parameters

<ParamField path="marketId" type="string" required>The market's record ID, as `id` on [List Markets](/endpoints/lending/list-markets), not its contract address. See [Market IDs](/endpoints/lending/list-markets#market-ids).</ParamField>

## Body Parameters

<ParamField body="price" type="number" required>
  Net asset value per collateral token, denominated in the market's borrow asset. Must be greater than zero, and a numeric string is accepted too. More decimal places than the borrow asset carries fail with `SIGNING_FAILED`.
</ParamField>

<ParamField body="validitySeconds" type="integer" default="300">
  Signature lifetime in seconds. Values below 60 are raised to 60 and values above 3600 are lowered to 3600. Zero or a non-numeric value falls back to 300.
</ParamField>

<ParamField body="signerAddress" type="string">
  The wallet that will sign, when price authority sits with a key this instance does not hold. Supply it and the payload is built for that address and its authorization is checked against the oracle. Omit it and the signer is resolved in order: the price signer the market's lender of record declared, then your instance's first verified wallet. A value that is not a 0x-prefixed 40-character hex address is ignored.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="action" type="string">Always `SIGN_TYPED_DATA`.</ResponseField>
    <ResponseField name="typedData" type="object">
      The EIP-712 payload to sign, carrying `domain`, `types`, `primaryType`, and `message`. Pass it straight to `signTypedData`.
    </ResponseField>
    <ResponseField name="display" type="object">
      The same values in readable form, also flattened onto `data` itself.
    </ResponseField>
    <ResponseField name="price" type="string">Price in base units at the borrow asset's decimals. Pass this value, not `priceUsd`, in the `signedPrice` object.</ResponseField>
    <ResponseField name="priceUsd" type="string">The same price as a human-readable decimal string. Informational.</ResponseField>
    <ResponseField name="timestamp" type="integer">Unix seconds the price is stamped at. Never ahead of chain time.</ResponseField>
    <ResponseField name="validUntil" type="integer">Unix seconds after which the signature is rejected.</ResponseField>
    <ResponseField name="signer" type="string">The wallet expected to sign. Signing with any other wallet produces a signature the oracle rejects.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  No signature is returned. You produce it by signing `typedData`. The contract then reads `price`, `timestamp`, `validUntil`, and your `signature`. Pass the first three through unchanged.
</Note>

## Signature Structure

```
domain = {
  name: "SecurityPriceOracle",
  version: "1",
  chainId: <chain the market is deployed on>,
  verifyingContract: <market oracle address>
}

PriceUpdate = {
  price:      uint256
  timestamp:  uint256
  validUntil: uint256
}
```

The signature is bound to one oracle on one chain through `verifyingContract` and `chainId`, and expires at `validUntil`. It carries no nonce and names no submitter, so anyone who holds it can submit it until it expires. It lands at most once, because the oracle only accepts a timestamp newer than the price it holds. Keep `validitySeconds` tight, and treat a signed price as a bearer credential over its lifetime.

## What the Oracle Checks When the Price Lands

The oracle judges the signature again inside the transaction that carries it, and a refusal reverts that whole transaction. It refuses a signature past `validUntil`, one dated in the future or older than `maxPriceAge`, and one whose signer is neither an authorized signer nor the owner. It also refuses a price outside the deviation limit, both against the current price and against the price that opened the current one-hour window.

The API runs both deviation checks before it builds the payload, whenever the oracle's price can be read. A price outside them is refused with `PRICE_DEVIATION_TOO_LARGE` or `PRICE_WINDOW_DEVIATION_TOO_LARGE`, carrying the same fields as on [Sync Oracle Price](/endpoints/lending/sync-oracle#circuit-breaker).

A signed price dated no later than the price the oracle already holds is skipped rather than refused. The transaction then runs against the stored price, which must not be stale.

Check a signature without spending gas using [Verify Signed Price](/endpoints/lending/verify-price).

## Error Codes

Every refusal from the signing step carries `signerAddress` in the error object. It names the rejected wallet on `SIGNER_NOT_AUTHORIZED` and is `null` otherwise.

| Code | HTTP | Cause |
|---|---|---|
| `NO_ORACLE` | `400` | The market records no oracle address |
| `MISSING_PRICE` | `400` | `price` is missing, unparseable, or not greater than zero |
| `EXTERNAL_FEED_ACTIVE` | `400` | The market's oracle reads an external feed and refuses signed prices |
| `SIGNER_NOT_AUTHORIZED` | `400` | The resolved signer is neither an authorized signer nor the owner of the market's oracle |
| `WALLET_NOT_CONFIGURED` | `400` | No `signerAddress` was given, the market declared no price signer, and this instance has no verified wallet |
| `PRICE_DEVIATION_TOO_LARGE` | `400` | The step from the on-chain price exceeds `maxDeviationBps`. The error carries `currentPrice` and `maxDeviationPercent` |
| `PRICE_WINDOW_DEVIATION_TOO_LARGE` | `400` | The movement within the current one-hour window would exceed `maxDeviationBps`. The error adds `windowAnchorPrice`, `windowStartedAt`, `windowResetsAt`, `acceptedLow` and `acceptedHigh` |
| `SIGNING_FAILED` | `400` | The payload could not be built and no more specific code applied |
| `MISSING_MARKET_ID` | `400` | `marketId` is longer than 100 characters |
| `MARKET_NOT_FOUND` | `404` | No market with this ID on your instance |
| `FIXED_PRICE_ACTIVE` | `409` | The market has a fixed price, and its oracle refuses every signed price. `details.markDownOnly` is `true`. Mark the price down through Sync Oracle Price instead |
| `PRICE_STATE_UNAVAILABLE` | `503` | Whether the market's oracle holds a fixed price could not be read. Retry shortly |
