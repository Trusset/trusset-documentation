---
title: 'Get Setup Steps'
api: 'GET /lending-external-securities-v2/api/markets/{marketId}/setup-steps'
description: 'Post-deployment checklist with calldata for each outstanding step'
---

Returns the work a market still needs before it can lend, as an ordered checklist. The first step is always a lender of record taking the market. Each step after it names the role required to execute it. Every incomplete step after it comes with ready-to-sign calldata, unless it is blocked or delegated to another party.

The checklist fails closed. When the factory cannot be read, or holds no deployment record for the market, the lender-of-record step is reported blocked rather than done, and `complete` stays `false`.

The token-side steps differ by collateral mode, because freeze markets and custody markets rely on different token-side permissions. They also differ by how the collateral token gates its holders: through a contract allow-list, or through an identity registry.

## Path Parameters

<ParamField path="marketId" type="string" required>Market ID.</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="complete" type="boolean">True when a lender of record has taken the market and every step is either done or delegated.</ResponseField>
    <ResponseField name="mode" type="string">`FREEZE` or `CUSTODY`. Determines which token-side steps appear.</ResponseField>
    <ResponseField name="priceSource" type="string">`NAV`, `MARKET` or `ORACLE`, read from the contract where possible and from the record otherwise.</ResponseField>
    <ResponseField name="collateralAgent" type="string">Named pledgee, from the factory record where it could be read. Addresses read from the factory record keep their checksum casing.</ResponseField>
    <ResponseField name="curator" type="string">The institution holding the lender-of-record role, or `null`.</ResponseField>
    <ResponseField name="seekingCurator" type="boolean">`true` while the market has no lender of record. `null` when the factory record could not be read.</ResponseField>
    <ResponseField name="realizationMode" type="string">How that institution declared it will realize seized collateral: `EXCHANGE_SALE`, `ISSUER_REDEMPTION` or `AUCTION`.</ResponseField>
    <ResponseField name="saleRecipient" type="string">Where seized collateral is sent for realization.</ResponseField>
    <ResponseField name="operable" type="boolean">Whether a lender of record has taken the market, so it can be operated at all. `complete` can never be true while this is `false`.</ResponseField>
    <ResponseField name="deploymentReadable" type="boolean">Whether the current factory holds a deployment record for this market and it could be read. When `false`, the lender-of-record fields above fall back to the stored record.</ResponseField>
    <ResponseField name="governance" type="object">`marketAdminHeldByInstance`, `oracleOwnedByInstance` and `oracleOwner`. Says which of the two administrative keys your instance actually holds, which decides which steps you can sign yourself.</ResponseField>
    <ResponseField name="liquidationRouterAddress" type="string">Router that must be an eligible holder of the collateral token.</ResponseField>
    <ResponseField name="relayerAddress" type="string">The instance's registered wallet: the primary one, or the oldest verified wallet when no primary is set. The oracle signer and liquidator steps are evaluated against this address, and when it is `null` neither can complete.</ResponseField>
    <ResponseField name="steps" type="array">
      <Expandable>
        <ResponseField name="key" type="string">Step identifier.</ResponseField>
        <ResponseField name="title" type="string">Human-readable description.</ResponseField>
        <ResponseField name="done" type="boolean">Whether the on-chain state already satisfies this step.</ResponseField>
        <ResponseField name="requiredRole" type="string">Role the executing party must hold.</ResponseField>
        <ResponseField name="target" type="string">Contract the transaction is sent to.</ResponseField>
        <ResponseField name="subject" type="string">Address being authorized. On the lender-of-record step, the institution that took the role.</ResponseField>
        <ResponseField name="candidates" type="array">Lender-of-record step only. The addresses nominated for the role.</ResponseField>
        <ResponseField name="delegated" type="boolean">Oracle signer and liquidator steps only. `true` when the step is not this instance's to perform, because another party holds the authority it needs. A delegated step counts toward `complete` without being `done`, and carries no calldata.</ResponseField>
        <ResponseField name="blocked" type="boolean">`true` when the step cannot be achieved as things stand, rather than merely being outstanding.</ResponseField>
        <ResponseField name="blockedReason" type="string">Why, in words. Carried by the allow-list and registry steps, `null` when not blocked, and by a blocked lender-of-record step.</ResponseField>
        <ResponseField name="blockedCode" type="string">The machine-readable form of the same, on the same steps. See the table below.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="calldata" type="object">Transactions for incomplete steps, keyed by calldata name, each `{ to, data, description }` with `value` and `chainId` added. Completed, blocked and delegated steps carry none.</ResponseField>
  </Expandable>
</ResponseField>

## Steps

Every checklist opens with the lender-of-record step and closes with the two steps the market admin and the oracle owner sign. The token-side steps sit between them.

| `key` | `requiredRole` | Calldata key | Executed by |
|---|---|---|---|
| `adoptCurator` | `NOMINATED_CANDIDATE` | None | A nominated candidate, through [Accept Lender Role](/endpoints/lending/accept-lender-role) |
| `grantAdapterAgentRole` | `TOKEN_AGENT_ADMIN` | `grantAdapterAgentRole` | `FREEZE` only. The collateral token's agent administrator |
| `authorizeAdapterOnToken` | `TOKEN_COMPLIANCE_ADMIN` | `authorizeAdapterOnToken` | `CUSTODY`, allow-list token. The token's compliance administrator |
| `verifyAdapterAsHolder` | `IDENTITY_REGISTRY_AGENT` | `verifyAdapterAsHolder` | `CUSTODY`, registry token. An agent of the token's identity registry |
| `authorizeRouterOnToken` | `TOKEN_COMPLIANCE_ADMIN` | `authorizeRouterOnToken` | Allow-list token. The token's compliance administrator |
| `verifyRouterOnRegistry` | `IDENTITY_REGISTRY_AGENT` | `verifyRouterAsHolder` | `FREEZE`, registry token. An agent of the token's identity registry |
| `verifyRouterAsHolder` | `IDENTITY_REGISTRY_AGENT` | `verifyRouterAsHolder` | `CUSTODY`, registry token. An agent of the token's identity registry |
| `authorizeVenueOnToken` | `TOKEN_COMPLIANCE_ADMIN` | `authorizeVenueOnToken` | Present when an auction venue is wired. The token's compliance administrator |
| `verifyVenueAsHolder` | `IDENTITY_REGISTRY_AGENT` | `verifyVenueAsHolder` | Present when an auction venue is wired. An agent of the token's identity registry |
| `authorizeOracleSigner` | `ORACLE_OWNER` | `authorizeRelayerOnOracle` | The oracle owner named by the lender of record |
| `grantLiquidatorRole` | `DEFAULT_ADMIN_ROLE` | `grantLiquidatorRole` | The market admin |

<Note>
  Two step keys differ from the calldata keys they produce: `verifyRouterOnRegistry` emits `verifyRouterAsHolder`, and `authorizeOracleSigner` emits `authorizeRelayerOnOracle`. Look up calldata by the `calldata` object's own keys rather than by step key. [Configure Market](/endpoints/lending/configure-market) names the agent-role grant `grantAgentRoleToAdapter`, not `grantAdapterAgentRole`.
</Note>

## Blocked Codes

| `blockedCode` | Step | Meaning |
|---|---|---|
| `MARKET_NOT_IN_FACTORY` | `adoptCurator` | The factory this instance deploys to holds no deployment record for the market. A market from an earlier factory generation has to be deployed again |
| `FACTORY_READ_FAILED` | `adoptCurator` | The factory could not be read, so nothing on the checklist counts as done. Retry |
| `IDENTITY_REGISTRY_WRITE_REJECTED` | Registry steps | Replayed from your instance's wallet, the registration reverts. The registry's own agent must send it |
| `IDENTITY_REGISTRY_UNRECOGNISED` | Registry steps | The registry answers neither the Trusset nor the ERC-3643 reference interface |
| `ONCHAINID_REQUIRED` | Registry steps | The ERC-3643 registry admits a holder only through an ONCHAINID, and the subject has none yet |
| `IDENTITY_CLAIMS_REQUIRED` | Registry steps | The subject's ONCHAINID lacks a valid claim for a required topic |
| `IDENTITY_ALREADY_REGISTERED` | Registry steps | The subject already holds a valid ONCHAINID on the registry |
| `CLAIM_TOPICS_UNREADABLE` | Registry steps | The ERC-3643 registry did not return the claim topics it requires |

`grantAdapterAgentRole` reports `blocked: true` without a code when the token does not implement the freeze interface. That market has to be redeployed in `CUSTODY` mode.

<Warning>
  The token-side steps are executed by whoever administers the collateral token. For an imported third-party security that is the original issuer or its transfer agent, not Trusset and not necessarily you. Plan for that dependency before announcing a market.
</Warning>

<Tip>
  [Set Liquidator Role](/endpoints/lending/set-liquidator-role) builds the same `LIQUIDATOR_ROLE` grant for any address, for the market admin to sign.
</Tip>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/lending-external-securities-v2/api/markets/{marketId}/setup-steps" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const res = await fetch(
  `https://api.trusset.org/lending-external-securities-v2/api/markets/${marketId}/setup-steps`,
  { headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { data } = await res.json();

const outstanding = data.steps.filter((s) => !s.done && !s.delegated);
for (const step of outstanding) {
  console.log(`${step.title} requires ${step.requiredRole}`, step.blocked ? step.blockedReason : '');
}
console.log('Calldata ready to sign:', Object.keys(data.calldata));
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `NO_MARKET_ADDRESS` | `400` | The market has no on-chain address recorded |
| `MISSING_MARKET_ID` | `400` | `marketId` is longer than 100 characters |
| `MARKET_NOT_FOUND` | `404` | No market with this ID on your instance |
| `ROUTER_UNRESOLVED` | `503` | The record carries no router address and the market's router could not be read. Retry |
