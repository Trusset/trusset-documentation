---
title: 'Get Loan Agreement'
api: 'GET /lending-external-securities-v2/api/markets/{marketId}/loan-agreements/{ref}'
description: 'Read one loan agreement with its schedule, salt and acceptance typed data'
---

Returns one agreement to a party: the bank, or the borrower side. Anyone else gets `AGREEMENT_NOT_FOUND`. The answer carries the schedule, the salt once the agreement is issued, the loans it is bound to, and, while it waits for acceptance, the typed data the borrower signs.

## Path Parameters

<ParamField path="marketId" type="string" required>
  The market's record ID on your instance.
</ParamField>

<ParamField path="ref" type="string" required>
  The agreement reference: `agr_` followed by 20 characters.
</ParamField>

## Query Parameters

<ParamField query="copyVerified" type="string">
  `true` or `false` (default). The value written into `acceptTypedData`: whether the borrower's copy matched the reported commitment. The borrower signs exactly the typed data it reads.
</ParamField>

See [Get Loan Schedule](/endpoints/lending/get-loan-schedule) for `fees`. The field names double as merge fields for an e-signature template.</ResponseField>

    <ResponseField name="scheduleVersion" type="string">The schema of the schedule: `1.1.0` since 2026-11-23, `1.0.0` before.</ResponseField>
    <ResponseField name="scheduleFrozen" type="boolean">`false` while `REQUESTED`: the bank may still lower the figures when it issues.</ResponseField>

    <ResponseField name="certificateCommitment" type="string | null">The salted commitment of the signing certificate, when reported.</ResponseField>
    <ResponseField name="copyVerified" type="boolean | null">After acceptance: the borrower's own signed statement that its copy matched. Trusset cannot check it. While `SIGNED`: `false` when the borrower side reported that its copy does not match, else `null`.</ResponseField>
    <ResponseField name="copyVerifiedIsBorrowerStatement" type="boolean">Always `true`: `copyVerified` is the borrower's statement, never a Trusset check.</ResponseField>
    <ResponseField name="copyMismatchReported" type="boolean">`true` while `SIGNED` after the borrower side reported a copy mismatch and before the bank reports the signed file again.</ResponseField>
    <ResponseField name="acceptance" type="string | null">The borrower's acceptance signature.</ResponseField>
    <ResponseField name="salt" type="string">32 bytes, once issued. Keep it with the signed file: file plus salt proves the record.</ResponseField>
    <ResponseField name="issuedAt" type="string | null">When the bank issued it.</ResponseField>
    <ResponseField name="signedAt" type="string | null">When the bank last reported the signed file.</ResponseField>
    <ResponseField name="acceptedAt" type="string | null">When the borrower accepted.</ResponseField>
    <ResponseField name="expiresAt" type="string | null">When the offer (`LOAN`) or the framework (`FRAMEWORK`) ends.</ResponseField>
    <ResponseField name="supersedes" type="string | null">The reference of the agreement this one replaced, if any.</ResponseField>
    <ResponseField name="createdAt" type="string">When the request or agreement was created.</ResponseField>
    <ResponseField name="updatedAt" type="string">The last change.</ResponseField>
    <ResponseField name="requestedByThisInstance" type="boolean">Your instance created the request or, as the bank, the agreement.</ResponseField>
    <ResponseField name="issuedByThisInstance" type="boolean">Your instance issued it as the bank.</ResponseField>
    <ResponseField name="links" type="object[]">The loans it is bound to: `{ loanId, openTxHash, matched, differences, recordedTxHash, recordedAt }`. `differences` lists `{ field, expected, actual }` where the opened loan differs from the schedule.</ResponseField>
    <ResponseField name="remainingLimit" type="string">`FRAMEWORK` in force: the limit minus the open principal of the wallet's loans in this market.</ResponseField>
    <ResponseField name="remainingLimitRaw" type="string">The same in the settlement asset's base units.</ResponseField>
    <ResponseField name="openLoans" type="number">`FRAMEWORK` in force: how many open loans of the wallet count against the limit.</ResponseField>
    <ResponseField name="acceptTypedData" type="object">While `SIGNED`: the EIP-712 typed data the borrower signs. See [Acceptance](/endpoints/lending/loan-agreements#acceptance).</ResponseField>
    <ResponseField name="viewerRole" type="object">`{ bank, borrower }` for your instance.</ResponseField>
    <ResponseField name="nextStep" type="string">What your side does next. The bank sees `ISSUE` (`REQUESTED`), `REPORT_SIGNED` (`ISSUED`), `WAIT_FOR_ACCEPTANCE` (`SIGNED`), `WAIT_FOR_LOAN` (`ACCEPTED` loan agreement) and `RECORD` (`BOUND`). The borrower side sees `WAIT_FOR_BANK` (`REQUESTED`), `SIGN_IN_BANK_TOOL` (`ISSUED`), `VERIFY_AND_ACCEPT` (`SIGNED`), `OPEN_LOAN` (`ACCEPTED` loan agreement) and `WAIT_FOR_RECORD` (`BOUND`). Both see `IN_FORCE` for an accepted framework, `DONE` once `RECORDED` and `NONE` in a final state. An instance that is both bank and borrower side sees the bank's step, except `VERIFY_AND_ACCEPT` and `OPEN_LOAN`.</ResponseField>
  </Expandable>
</ResponseField>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `VALIDATION_ERROR` | `400` | `copyVerified` is neither `true` nor `false` |
| `AGREEMENT_NOT_FOUND` | `404` | No agreement with this reference on this market, or your instance is not a party to it. List the agreements to find it |
| `MARKET_NOT_FOUND` | `404` | No market with this ID on your instance |
| `RATE_LIMIT_EXCEEDED` | `429` | Too many reads in a short time. Retry after the interval in `Retry-After` |
| `CHAIN_UNAVAILABLE`, `SERVICE_UNAVAILABLE` | `503` | The market or your instance's wallets could not be read just now. Nothing was decided. Retry shortly |
