---
title: 'Upgrade Market'
api: 'POST /lending-external-securities-v2/api/markets/{marketId}/upgrade'
description: 'Announce, cancel or execute the upgrade of a market, its rate model, router, oracle or insurance fund to the factory implementation'
---

Builds the unsigned transactions that move one of the market's proxies onto the implementation the factory serves, then confirms each once mined. `target` picks the proxy: the market itself, its interest rate model, its liquidation router, its price oracle or its insurance fund. `action` picks the step. An upgrade is announced with `propose`, may be withdrawn with `cancel`, and runs with `execute` no earlier than 7 days after the announcement. Each proxy has its own authority, and the response names who must sign.

The target implementation is always read from the factory and cannot be named in the request. A factory implementation that lacks a feature the proxy already runs is refused, so an upgrade never moves a proxy backwards. An address that is not a market of the lending factory this instance deploys to is refused with `MARKET_NOT_IN_FACTORY`. [Get Upgrade Status](/endpoints/lending/get-upgrade-status) shows what each upgrade would change before you build it.

## Path Parameters

<ParamField path="marketId" type="string" required>The market's record ID, as `id` on [List Markets](/endpoints/lending/list-markets), not its contract address. See [Market IDs](/endpoints/lending/list-markets#market-ids).</ParamField>

## Body Parameters

<ParamField body="target" type="string" default="market">
  The proxy to upgrade: `market`, `rateModel`, `router`, `insuranceFund` or `oracle`.
</ParamField>

<ParamField body="action" type="string" default="execute">
  `propose`, `cancel` or `execute`. `execute` is accepted only for an implementation announced with `propose` at least 7 days earlier. See [Announce, then execute](#announce-then-execute).
</ParamField>

<ParamField body="txHash" type="string">
  Hash of the mined transaction. Send it with the same `target` and `action` to confirm it. Omit it to receive the calldata.
</ParamField>

## Who Signs

| `target` | Signed by | Also refused while |
|---|---|---|
| `market` | The market admin (`DEFAULT_ADMIN_ROLE`) | |
| `router` | The router admin | |
| `rateModel` | The market admin (`DEFAULT_ADMIN_ROLE` on the market) | The market or the factory still owns the model: `RATE_MODEL_OWNER_PENDING` |
| `oracle` | The price oracle's owner | The market or the factory still owns the oracle: `ORACLE_OWNER_PENDING` |
| `insuranceFund` | The insurance fund's owner | The market or the factory still owns the fund: `INSURANCE_FUND_OWNER_PENDING` |

Every target is refused with `MARKET_PENDING_CURATOR` while the market has no lender of record. The oracle, the model and the fund pass to the owners the lender of record named only when each nominee accepts ownership. [Get Handover](/endpoints/operators/get-handover) returns those acceptance transactions.

The rate model is the one proxy whose code and whose parameters answer to different parties. The market admin announces and executes its upgrades. Its owner keeps the curve parameters, the rate mode and the fixed-rate ceiling, and cannot announce or execute an upgrade of the model's code.

## Announce, then execute

The three actions build the following, and the notice runs 7 days from the announcement.

| `action` | Function | Refused with |
|---|---|---|
| `propose` | `proposeUpgrade(implementation)`, with the implementation the factory serves | `ALREADY_UPGRADED` when the proxy already runs it, `UPGRADE_ALREADY_PROPOSED` when it is already announced, `INVALID_IMPLEMENTATION` when the factory's address holds no code |
| `cancel` | `cancelUpgradeProposal()` | `NO_UPGRADE_PROPOSAL` when nothing is announced |
| `execute` | `upgradeToAndCall(implementation, "0x")` | `UPGRADE_NOT_READY` without a proposal, for an implementation other than the announced one, or before `notice.activatesAt` |

A later `propose` replaces an earlier one and restarts the week. [Get Upgrade Status](/endpoints/lending/get-upgrade-status) reports each proxy's `notice`, with `ready` and `secondsUntilReady`, so an integration can schedule the execution.

## Confirmed Response

On `execute`, the confirm call verifies that the transaction targeted the proxy for `target`, called `upgradeToAndCall` or `upgradeTo`, and emitted `Upgraded` on that proxy. It then reads the new implementation from the receipt. On `propose` and `cancel` it verifies that the transaction targeted the proxy, called `proposeUpgrade` or `cancelUpgradeProposal`, and emitted `UpgradeProposed` or `UpgradeProposalCancelled` on it. The audit log records `LENDING_MARKET_UPGRADE_PROPOSED`, `LENDING_MARKET_UPGRADE_PROPOSAL_CANCELLED` or `LENDING_MARKET_UPGRADED`.

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="confirmed" type="boolean">Always `true`.</ResponseField>
    <ResponseField name="target" type="string">The proxy the transaction acted on.</ResponseField>
    <ResponseField name="action" type="string">`propose` or `cancel`. Absent on a confirmed `execute`.</ResponseField>
    <ResponseField name="proxy" type="string">Its address, lowercased.</ResponseField>
    <ResponseField name="txHash" type="string">Transaction hash.</ResponseField>
    <ResponseField name="implementation" type="string">The implementation the event names, lowercased: the one now running after `execute`, the one announced after `propose`, the one withdrawn after `cancel`.</ResponseField>
    <ResponseField name="activatesAt" type="integer">`propose` only. When the announced upgrade can execute, from the `UpgradeProposed` event. `activatesAtIso` is the same as ISO 8601. `null` on `cancel`.</ResponseField>
    <ResponseField name="signer" type="string">The address that sent the transaction, lowercased.</ResponseField>
  </Expandable>
</ResponseField>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `NO_MARKET_ADDRESS` | `400` | The market has no on-chain address recorded |
| `VALIDATION_ERROR` | `400` | `target` is not one of the five values, `action` is not `propose`, `cancel` or `execute`, or `txHash` is not a transaction hash |
| `MARKET_PENDING_CURATOR` | `409` | No lender of record has taken the market, so no admin can sign an upgrade. Not checked on the confirm call |
| `ALREADY_UPGRADED` | `409` | The proxy already runs the factory's implementation. On `execute`, only while nothing is announced |
| `UPGRADE_NOT_READY` | `409` | `execute`: nothing is announced (`details.reason` `NO_PROPOSAL`), the announced implementation is not the one the factory serves (`PROPOSAL_DIFFERS`, with both), or the notice has not passed (`NOTICE_RUNNING`, with `activatesAt` and `secondsUntilReady`) |
| `UPGRADE_ALREADY_PROPOSED` | `409` | `propose` for an implementation already announced. `details.notice` says when it executes. Announcing again would restart the week |
| `NO_UPGRADE_PROPOSAL` | `409` | `cancel` while no upgrade of that proxy is announced |
| `INVALID_IMPLEMENTATION` | `400` | `propose` or `execute`: the implementation the factory serves holds no code, so the call would revert |
| `TARGET_IMPL_WITHOUT_NOTICE` | `409` | `propose` or `execute`: the implementation the factory serves does not carry the upgrade notice, or a function the target relies on (`GUARDIAN_ROLE()` on the market, `priceHaltedUntil()` on the oracle, `withdrawalActivatesAt()` on the fund). Moving onto it would take the proxy off the notice, so nothing is built. `details.missing` names what it lacks |
| `MARKET_NOT_IN_FACTORY` | `409` | The address is not a market of the lending factory this instance deploys to, so the factory's implementations are not upgrades for it. Applies to `propose` and `execute`; `cancel` stays open |
| `FACTORY_UNREADABLE` | `503` | The factory record of the market could not be read. Retry |
| `CHAIN_UNAVAILABLE` | `503` | The chain could not be read just now. Retry shortly |
| `RATE_MODEL_OWNER_PENDING` | `409` | `rateModel`: the market or the factory still owns the model. `details` carries `target`, `address` and `owner` |
| `INSURANCE_FUND_OWNER_PENDING` | `409` | `insuranceFund`: the market or the factory still owns the fund. `details` carries `target`, `address` and `owner` |
| `ORACLE_OWNER_PENDING` | `409` | `oracle`: the market or the factory still owns the oracle. `details` carries `target`, `address` and `owner` |
| `NO_ORACLE` | `400` | `oracle`: the market records no oracle and none could be read from the market contract |
| `NO_TARGET_IMPL` | `400` | The factory serves no implementation for that proxy |
| `TARGET_IMPL_NO_CODE` | `400` | The factory's implementation address holds no code |
| `TARGET_IMPL_NOT_INSTRUMENTED` | `400` | `market`: the factory implementation lacks the snapshot function |
| `TARGET_IMPL_NOT_STAMPING` | `400` | `market`: the factory implementation does not stamp loan terms or hold venue proceeds |
| `TARGET_IMPL_NOT_CEILINGED` | `400` | `rateModel`: the factory implementation lacks the fixed-rate ceiling |
| `TARGET_IMPL_NOT_TOPPABLE` | `400` | `insuranceFund`: the factory implementation lacks the permissionless top-up |
| `TARGET_IMPL_NOT_ROTATABLE` | `400` | `router`: the factory implementation lacks the sale-recipient rotation flow |
| `TARGET_IMPL_NOT_HALTABLE` | `400` | `oracle`: the factory implementation lacks the guardian halt |
| `MARKET_STATE_UNAVAILABLE` | `503` | The proxy's implementation or its upgrade notice could not be read. Retry |
| `MODEL_UNRESOLVED` | `503` | `rateModel`: the model could not be resolved. On the confirm call, `409` when the market has none |
| `MODEL_STATE_UNAVAILABLE` | `503` | `rateModel`: the model's implementation could not be read |
| `FUND_UNRESOLVED` | `503` | `insuranceFund`: the fund could not be resolved |
| `FUND_STATE_UNAVAILABLE` | `503` | `insuranceFund`: the fund's implementation could not be read |
| `ORACLE_STATE_UNAVAILABLE` | `503` | `oracle`: the oracle's implementation could not be read |
| `NO_INSURANCE_FUND` | `409` | Confirm call, `insuranceFund`: the market has no insurance fund |
| `ROUTER_UNRESOLVED` | `400` or `503` | `router`: the record carries no router address and the market's router could not be read. `400` when building, `503` when confirming |
| `TX_NOT_VERIFIED` | `400` | Confirm call: the transaction emitted no `Upgraded`, `UpgradeProposed` or `UpgradeProposalCancelled` event, as `action` requires, on that proxy |
| `UPGRADE_FAILED` | `500` | A step failed for a reason no other code covers |
| `MISSING_MARKET_ID` | `400` | `marketId` is longer than 100 characters |
| `MARKET_NOT_FOUND` | `404` | No market with this ID on your instance |

Confirming with `txHash` can also return any [transaction verification error](/endpoints/introduction#confirm-a-transaction).
