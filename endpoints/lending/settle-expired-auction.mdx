---
title: 'Settle Expired Auction'
api: 'POST /lending-external-securities-v2/api/liquidations/{marketId}/settle-expired-auction'
description: 'Route unsold collateral from an expired auction to the liquidation router'
---

Closes a Dutch auction that reached its end time without selling out, and moves the unsold collateral from the market's auction venue to the market's liquidation router. The router opens a record for the remainder, linked to the market's own liquidation record, and the position enters the manual settlement workflow. The transaction targets the venue, not the market.

Until this is called, an expired auction leaves the collateral in limbo: no longer purchasable, and not yet available for an off-platform sale. The loan stays locked too, because the market treats the auction as open until it is settled.

<Warning>
  The venue must be authorized on the market's liquidation router, otherwise the settlement reverts and the collateral stays in the venue. The API does not check this before building the calldata. Read `routerAuthorized` on [Get Auction Module](/endpoints/lending/get-auction-module), and sign the `authorizeModuleOnRouter` leg from [Wire Auction Module](/endpoints/lending/wire-auction-module) if it is not `true`. The collateral token must also admit the router, as it must for every liquidation.
</Warning>

<Warning>
  Any wallet may settle an expired auction while the market is unpaused. Under a pause, the venue accepts the call only from a wallet holding `LIQUIDATOR_ROLE` on the market. The optional `signerAddress` check is stricter than the contract: it demands `LIQUIDATOR_ROLE` whether or not the market is paused.
</Warning>

## Path Parameters

<ParamField path="marketId" type="string" required>Market ID.</ParamField>

## Body Parameters

<ParamField body="auctionId" type="integer" required>
  Auction ID on the market's venue. Must be a positive integer sent as a JSON number. Required on the confirm call too.
</ParamField>

<ParamField body="signerAddress" type="string">
  Wallet you intend to settle with. Supplying it turns on a `LIQUIDATOR_ROLE` check against that address, so the call is refused with `LIQUIDATOR_ROLE_MISSING` rather than handing back calldata that a paused market would revert. Omit it and no role check runs, which is the right choice when an unpaused market is settled from a wallet without the role.
</ParamField>

<ParamField body="txHash" type="string">
  Hash of the `settleExpiredAuction` transaction you broadcast. Send it with the same `auctionId` to confirm the settlement and record the result. Omit it to receive the calldata.
</ParamField>

## What Happens Next

After settlement the unsold collateral sits at the liquidation router as a `PENDING` liquidation, visible through [Get Pending Liquidations](/endpoints/lending/get-pending-liquidations). From there the standard manual workflow applies: withdraw for sale, report proceeds, settle. The 7 day write-off clock does not restart at this point. It runs from the original liquidation, when the market opened its record and the auction began, so the router-side sale has whatever remains of those 7 days.

Use the returned `liquidationId` on those router-side endpoints. Until this call confirms, they refuse the record with `LIQUIDATION_ON_VENUE`, because the router holds none of its collateral yet. Cash that earlier bids paid stays on the market's record, and it settles together with whatever the router later forwards.

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `MISSING_MARKET_ID` | `400` | The market ID is longer than 100 characters |
| `NO_MARKET_ADDRESS` | `400` | The market has no on-chain address recorded |
| `VALIDATION_ERROR` | `400` | `auctionId` is not a positive integer, `signerAddress` is not a valid address, or `txHash` is malformed |
| `AUCTION_NOT_ACTIVE` | `400` | The auction was already fully bought or settled, so settling it again reverts |
| `AUCTION_NOT_EXPIRED` | `400` | The auction is still running. The error carries `eligibleAt` |
| `LIQUIDATOR_ROLE_MISSING` | `400` | `signerAddress` was supplied and lacks `LIQUIDATOR_ROLE` on the market. The error carries grant `calldata` |
| `ROLE_UNVERIFIABLE` | `400` | `signerAddress` was supplied and its role could not be read on-chain. Retry shortly |
| `TX_NOT_VERIFIED` | `400` | The confirmed transaction settles a different auction |
| `SETTLE_FAILED` | `400` | The settlement could not be prepared or confirmed and no more specific code applied |
| `AUCTION_NOT_FOUND` | `404` | The venue has not created an auction with this ID |
| `MARKET_NOT_FOUND` | `404` | No market with this ID on your instance |
| `AUCTION_MODULE_NOT_SET` | `409` | The market has no auction venue wired, so there is no auction to settle |
| `AUCTION_STATE_UNAVAILABLE` | `503` | The auction could not be read on-chain, so whether it has expired is unknown. Retry shortly |

Refusals from the auction and role checks carry `eligibleAt`, which is `null` except on `AUCTION_NOT_EXPIRED`. Confirming with `txHash` can also return any [transaction verification error](/endpoints/introduction#confirm-a-transaction).
