title: 'Upgrade Market'

description: 'Calldata that moves a market to delivery against payment, for the market admin to sign'
---

<Note>
  Seller Financing is in beta and runs on Ethereum Sepolia instances only for now (`DEVELOPMENT` instances on Ethereum). A `PRODUCTION` instance, or one on another network, answers `503 SELLER_FINANCING_UNAVAILABLE`. See [Seller Financing](/endpoints/seller-financing/introduction).
</Note>

Builds the move of a market to the implementation the factory binds today, as unsigned calldata for the market's own admin. The market is a UUPS proxy: only a wallet that holds `DEFAULT_ADMIN_ROLE` on it can upgrade it. Trusset holds no role on a market and never signs this transaction. See [Market generations](/endpoints/seller-financing/introduction#market-generations).

The answer depends on where the market stands, as [Get Market](/endpoints/seller-financing/get-market) reports it in `implementation`:

- **First implementation, the factory binds a delivery-against-payment one** (`implementation.action: "UPGRADE"`). The build is `upgradeToAndCall(newImplementation, migrateEncumbrance())` on the market: the upgrade and the recount of the live sales in one transaction. `upgradeAction` reads `UPGRADE`. Simulated from `from`, a wallet without `DEFAULT_ADMIN_ROLE` answers `409 TX_WOULD_REVERT` with `AccessControlUnauthorizedAccount`, naming the role and its holders.
- **Delivery against payment without the recount** (`implementation.action: "MIGRATE"`), for example a market whose admin upgraded without the call. The build is `migrateEncumbrance()` alone. Any wallet can sign it; it only recounts and runs once. `upgradeAction` reads `MIGRATE`. Until it runs, deliveries, unwinds, claims, liquidations and custody cancellations answer `409 MIGRATION_PENDING`, because the market's pooled numbers do not know the sales locked before the upgrade.
- **The factory still binds the first implementation**: `409 UPGRADE_NOT_AVAILABLE`.
- **The market already runs what the factory binds**: `409 MARKET_UP_TO_DATE`.
- **The market runs a delivery-against-payment implementation other than the one the factory binds**: `409 UPGRADE_NOT_SUPPORTED`. This build only moves first-generation markets.

The implementation the market runs is read from its ERC-1967 slot and the recount from its OpenZeppelin `Initializable` version, both fresh on every build. Which implementation the factory binds is read from `marketImplementation()` on the factory.

What changes with the upgrade, as the response lists in `changes`:

- A payoff no longer credits the seller. The downpayment and the principal stay in the market until the asset is delivered, by the buyer with [Claim Asset](/endpoints/seller-financing/claim-asset) or by the seller or an operator with [Deliver Asset](/endpoints/seller-financing/deliver-asset).
- 30 days after a payoff without delivery, the buyer can unwind a sale whose asset cannot be delivered, and an operator can unwind any, with [Unwind Sale](/endpoints/seller-financing/unwind-sale). The interest stays with the seller.
- The market counts the asset sold on live sales per seller (freeze) or for the adapter (custody), and a return to the seller unfreezes only what the seller's other sales do not need.
- A listing whose interest periods are shorter than its runtime needs a grace period of at least one day on chain.

Sales paid off before the upgrade keep the first implementation's terms: the seller was credited at the payoff, the buyer still claims the asset, and the sale cannot be unwound. There is no rollback once a payoff is held, because the first implementation does not know the held payment.

The same build is offered in the Issuer Portal, on the Seller Financing page, as Upgrade or Recount next to the market, signed by the connected wallet.

## Path Parameters

<ParamField path="marketId" type="string" required>The market's record ID, as `id` on [List Markets](/endpoints/seller-financing/list-markets).</ParamField>

## Body Parameters

<ParamField body="from" type="string" required>The wallet that signs: a wallet that holds `DEFAULT_ADMIN_ROLE` on the market for the upgrade, any wallet for the recount alone. Without it the answer is `400 FROM_REQUIRED`.</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="action" type="string">`SIGN_TRANSACTIONS`.</ResponseField>
    <ResponseField name="chainId" type="integer">The chain the step is built for.</ResponseField>
    <ResponseField name="steps" type="array">One step on the market: `upgradeToAndCall` or `migrateEncumbrance`, with `gasLimit`.</ResponseField>
    <ResponseField name="confirmStepIndex" type="integer">`0`.</ResponseField>
    <ResponseField name="preflight" type="object">`{ simulated: true, gasEstimate }`.</ResponseField>
    <ResponseField name="upgradeAction" type="string">`UPGRADE` or `MIGRATE`.</ResponseField>
    <ResponseField name="upgrade" type="object">`{ market, currentImplementation, currentGeneration, initializedVersion, factory, factoryImplementation, factoryGeneration, listings }`, plus `migrationCall` (`0xc1fa8cec`) on an upgrade. The recount reads every listing twice, so `listings` sizes the gas.</ResponseField>
    <ResponseField name="signer" type="object">On an upgrade `{ role: "DEFAULT_ADMIN_ROLE", holders, holdersComplete }`. On a recount `{ role: "ANY", note }`.</ResponseField>
    <ResponseField name="changes" type="array">On an upgrade, what changes for the market's sales.</ResponseField>
    <ResponseField name="note" type="string">Who signs, the terms of sales paid off before the upgrade, and that there is no rollback.</ResponseField>
  </Expandable>
</ResponseField>

  -H "Content-Type: application/json" \

```typescript TypeScript
const res = await fetch(
  `https://api.trusset.org/seller-financing/api/markets/${marketId}/upgrade`,
  {
    method: 'POST',
    headers: { 'X-API-Key': 'trusset_your_key_here', 'Content-Type': 'application/json' },
    body: JSON.stringify({ from: await admin.getAddress() })
  }
);
const { data } = await res.json();
const step = data.steps[0];
await (await admin.sendTransaction({ to: step.to, data: step.data, value: 0, gasLimit: step.gasLimit })).wait();
```

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `VALIDATION_ERROR` | `400` | `from` is malformed, or the body carries another field. `error.details` names it |
| `FROM_REQUIRED` | `400` | `from` is missing. The message names who signs |
| `MARKET_NOT_FOUND` | `404` | No market with this ID that your instance reaches on its network |
| `UPGRADE_NOT_AVAILABLE` | `409` | The factory still binds the first implementation. `details.upgrade` carries the plan |
| `MARKET_UP_TO_DATE` | `409` | The market already runs the implementation the factory binds |
| `UPGRADE_NOT_SUPPORTED` | `409` | The market runs another delivery-against-payment implementation than the one the factory binds |
| `TX_WOULD_REVERT` | `409` | The upgrade would revert: `AccessControlUnauthorizedAccount` with `details.requiredRole: "DEFAULT_ADMIN_ROLE"` and `details.roleHolders`, or a refusal of the new implementation such as `UUPSUnsupportedProxiableUUID` |
| `CHAIN_UNAVAILABLE` | `503` | The market implementation, the recount state or the factory could not be read. Nothing was built. Retry shortly |
| `SELLER_FINANCING_UNAVAILABLE` | `503` | The instance is a `PRODUCTION` instance or not on Ethereum |
| `UPGRADE_BUILD_FAILED` | `500` | Unexpected failure. Nothing was built. Retry, or contact support with the request ID |
