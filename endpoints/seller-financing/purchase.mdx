---
title: 'Purchase'
api: 'POST /seller-financing/api/markets/{marketId}/listings/{listingId}/purchase'
description: 'Approve-and-purchase calldata that pays the downpayment and starts the loan'
---

<Note>
  Seller Financing is in beta and runs on testnet instances only (Sepolia, `DEVELOPMENT`). A `PRODUCTION` instance answers `503 SELLER_FINANCING_UNAVAILABLE`. See [Seller Financing](/endpoints/seller-financing/introduction).
</Note>

Builds the purchase of an `OPEN` listing for the buyer to sign: an exact approval of the downpayment on the payment token, then `purchase`. The market pulls exactly the downpayment and holds it in escrow. The loan starts at the block time of the purchase, and its interest periods count from there.

In freeze mode, the purchase freezes the listed amount in the seller's wallet. In custody mode the asset is already in the adapter, and nothing moves. Either way, the asset reaches the buyer only after full payment, through [Claim Asset](/endpoints/seller-financing/claim-asset).

The market admits a buyer that:

- is not the seller, the market or its adapter,
- is the designated buyer, when the listing names one,
- is verified on the market identity register, when the market names one,
- is not refused by the asset token's own identity register, because the token would otherwise refuse the delivery.

The listing must not have expired, the market must not be paused, and the seller must not hold the agent role on the asset token.

In freeze mode the API also checks, before building, that the freeze adapter still holds its agent role and that the seller still holds the listed amount unfrozen. Either failure answers `409 TX_WOULD_REVERT`, with `AgentRoleMissing` or `InsufficientFreeBalance`.

## Path Parameters

<ParamField path="marketId" type="string" required>The market's record ID, as `id` on [List Markets](/endpoints/seller-financing/list-markets).</ParamField>

<ParamField path="listingId" type="string" required>The listing's ID on the market.</ParamField>

## Body Parameters

<ParamField body="from" type="string" required>The buyer's wallet, which signs both steps. It must hold the downpayment in the payment token.</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="action" type="string">`SIGN_TRANSACTIONS`.</ResponseField>
    <ResponseField name="chainId" type="integer">The chain the steps are built for.</ResponseField>
    <ResponseField name="steps" type="array">Any reset of an existing allowance to zero, the approval of exactly the downpayment, then `purchase`. With an allowance that already covers the downpayment, `purchase` alone, with `gasLimit`.</ResponseField>
    <ResponseField name="confirmStepIndex" type="integer">Index of the `purchase` step.</ResponseField>
    <ResponseField name="preflight" type="object">`{ simulated: true, gasEstimate }`, or `{ simulated: false, note }` when the purchase can be simulated only after the approval is mined. The market's own checks of the buyer and the listing passed either way.</ResponseField>
    <ResponseField name="downpayment" type="string">The downpayment, in the payment token's smallest unit.</ResponseField>
    <ResponseField name="downpaymentFormatted" type="string">The same in whole units.</ResponseField>
    <ResponseField name="principal" type="string">What the buyer owes after the purchase, before interest, in smallest units.</ResponseField>
    <ResponseField name="principalFormatted" type="string">The same in whole units.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  The approval is exact, never unlimited. A wallet already holding a smaller non-zero allowance gets a step that resets it to zero first, because some tokens refuse to change a non-zero allowance.
</Note>

<RequestExample>
```bash cURL
curl -X POST "https://api.trusset.org/seller-financing/api/markets/cmsg4x7k20003sf9q1d8v6b2e/listings/4/purchase" \
  -H "X-API-Key: trusset_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"from": "0x09BD3f5c18488e492a7bC3C7CCfc6cc837f511e8"}'
```
```typescript TypeScript
const res = await fetch(
  `https://api.trusset.org/seller-financing/api/markets/${marketId}/listings/${listingId}/purchase`,
  {
    method: 'POST',
    headers: { 'X-API-Key': 'trusset_your_key_here', 'Content-Type': 'application/json' },
    body: JSON.stringify({ from: await buyer.getAddress() })
  }
);
const { data } = await res.json();
for (const step of data.steps) {
  const tx = await buyer.sendTransaction({ to: step.to, data: step.data, value: 0, gasLimit: step.gasLimit });
  await tx.wait();
}
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_LISTING_ID` | `400` | `listingId` is not a positive integer of up to 19 digits |
| `VALIDATION_ERROR` | `400` | `from` is missing or malformed, or the body carries another field |
| `MARKET_NOT_FOUND` | `404` | No market with this ID on your instance and network |
| `LISTING_NOT_FOUND` | `404` | No listing with this ID on the market |
| `INVALID_STATUS` | `409` | The listing is not `OPEN`. `details.status` names its status |
| `INSUFFICIENT_BALANCE` | `409` | `from` holds less of the payment token than the downpayment. `details` carries `token`, `owner`, `balance` and `needed` |
| `TX_WOULD_REVERT` | `409` | The purchase would revert. `details.error` names the reason, for example `ListingExpired`, `NotDesignatedBuyer`, `InvalidBuyer`, `IdentityNotVerified`, `BuyerNotVerified`, `SellerIsTokenAgent`, `EnforcedPause`, or in freeze mode `AgentRoleMissing` and `InsufficientFreeBalance` |
| `CHAIN_UNAVAILABLE` | `503` | The chain could not be read. Nothing was built. Retry shortly |
| `SELLER_FINANCING_UNAVAILABLE` | `503` | The instance is a `PRODUCTION` instance or not on Ethereum |
| `PURCHASE_BUILD_FAILED` | `500` | Unexpected failure. Nothing was built. Retry, or contact support with the request ID |
