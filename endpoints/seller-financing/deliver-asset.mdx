---
title: 'Deliver Asset'
api: 'POST /seller-financing/api/markets/{marketId}/listings/{listingId}/deliver'
description: 'Calldata with which the seller or an operator delivers the asset of a paid sale to the buyer'
---

<Note>
  Seller Financing is in beta and runs on Ethereum Sepolia instances only for now (`DEVELOPMENT` instances on Ethereum). A `PRODUCTION` instance, or one on another network, answers `503 SELLER_FINANCING_UNAVAILABLE`. See [Seller Financing](/endpoints/seller-financing/introduction).
</Note>

Builds the delivery of the asset on a `REPAID` listing, signed by the seller or by a wallet that holds `OPERATOR_ROLE` on the market. The asset goes to the buyer's own wallet, the wallet that bought the listing, and the listing reads `COMPLETED`. In the same transaction the market credits the held payment, the downpayment plus the principal, to the seller, who withdraws it with [Withdraw](/endpoints/seller-financing/withdraw).

The delivery exists on markets that run delivery against payment, the second market implementation. See [Market generations](/endpoints/seller-financing/introduction#market-generations). On a first-generation market the answer is `409 MARKET_UPGRADE_REQUIRED`, and the buyer takes the asset with [Claim Asset](/endpoints/seller-financing/claim-asset). The buyer can always claim the asset itself, also to another wallet the token admits; the delivery lets the seller complete a sale without waiting for the buyer.

Before building, the API checks, in order:

1. The market runs delivery against payment and has recounted its live sales. Otherwise the answer is `409 MARKET_UPGRADE_REQUIRED` or `409 MIGRATION_PENDING`.
2. The listing is `REPAID`.
3. The asset can be delivered, read from the market's own `isDeliverable(id)` and `encumbrance(seller)`. While it cannot, the answer is `409 ASSET_NOT_DELIVERABLE` with `details.assetLeg` and `details.heldPayment`. See [Asset leg](/endpoints/seller-financing/introduction#asset-leg).
4. The buyer is verified on the asset token's own identity register, when the token names one. A buyer the register answers as not verified is refused with `409 RECIPIENT_NOT_VERIFIED`. The buyer can then claim to a verified wallet of its own with [Claim Asset](/endpoints/seller-financing/claim-asset).
5. In custody mode, the token admits the transfer from the custody adapter to the buyer. A refusal answers `409 RECIPIENT_REFUSED` with the token's `reason`.

The delivery is then simulated from `from`. A wallet that is neither the seller nor an operator answers `409 TX_WOULD_REVERT` with `NotSeller`, naming the seller and the wallets that hold `OPERATOR_ROLE`. A delivery stays open while the market is paused.

## Path Parameters

<ParamField path="marketId" type="string" required>The market's record ID, as `id` on [List Markets](/endpoints/seller-financing/list-markets).</ParamField>

<ParamField path="listingId" type="string" required>The listing's ID on the market.</ParamField>

## Body Parameters

<ParamField body="from" type="string" required>The wallet that signs: the seller of the listing or a wallet that holds `OPERATOR_ROLE` on the market. Without it the answer is `400 FROM_REQUIRED`.</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="action" type="string">`SIGN_TRANSACTIONS`.</ResponseField>
    <ResponseField name="chainId" type="integer">The chain the step is built for.</ResponseField>
    <ResponseField name="steps" type="array">One step, `deliverAsset` on the market, with `gasLimit`.</ResponseField>
    <ResponseField name="confirmStepIndex" type="integer">`0`.</ResponseField>
    <ResponseField name="preflight" type="object">`{ simulated: true, gasEstimate }`.</ResponseField>
    <ResponseField name="recipient" type="string">The buyer's wallet, which receives the asset.</ResponseField>
    <ResponseField name="heldPayment" type="object">The payment the market holds for this sale, as on [Get Listing](/endpoints/seller-financing/get-listing#response-fields).</ResponseField>
    <ResponseField name="release" type="object">`{ to, amount, amountFormatted, note }`: the seller and what the delivery credits it. `amount` is `"0"` for a sale paid off before the market moved to delivery against payment, because the seller was credited at that payoff. `null` when the held payment could not be read.</ResponseField>
    <ResponseField name="signer" type="object">`{ role: "SELLER_OR_OPERATOR_ROLE", seller }`.</ResponseField>
    <ResponseField name="assetLeg" type="object">Present only when the asset leg carries a warning while the asset can still be delivered, for example a seller whose backing covers fewer than all of its sold amounts.</ResponseField>
    <ResponseField name="warning" type="string">`assetLeg.warning`, present with it.</ResponseField>
  </Expandable>
</ResponseField>

```bash cURL
  -H "X-API-Key: trusset_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"from": "0x8cC237798b4E5eE7A07F20e8ad2db554404abF88"}'
```
```typescript TypeScript
const res = await fetch(
  `https://api.trusset.org/seller-financing/api/markets/${marketId}/listings/${listingId}/deliver`,
  {
    method: 'POST',
    headers: { 'X-API-Key': 'trusset_your_key_here', 'Content-Type': 'application/json' },
    body: JSON.stringify({ from: await seller.getAddress() })
  }
);
const { data } = await res.json();
const step = data.steps[0];
await (await seller.sendTransaction({ to: step.to, data: step.data, value: 0, gasLimit: step.gasLimit })).wait();
```

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_LISTING_ID` | `400` | `listingId` is not a positive integer of up to 19 digits |
| `VALIDATION_ERROR` | `400` | `from` is malformed, or the body carries another field. `error.details` names it |
| `FROM_REQUIRED` | `400` | `from` is missing. The message names who signs: the seller or a wallet that holds `OPERATOR_ROLE` |
| `MARKET_NOT_FOUND` | `404` | No market with this ID that your instance reaches on its network |
| `LISTING_NOT_FOUND` | `404` | No listing with this ID on the market |
| `MARKET_UPGRADE_REQUIRED` | `409` | The market runs the first implementation. `details` carries `implementation` and `generation` |
| `MIGRATION_PENDING` | `409` | The market runs delivery against payment but has not recounted its live sales. [Upgrade Market](/endpoints/seller-financing/upgrade-market) builds the recount, which any wallet can sign |
| `INVALID_STATUS` | `409` | The listing is not `REPAID`. `details.status` names its status |
| `ASSET_NOT_DELIVERABLE` | `409` | The market reports that the asset cannot be delivered. `details` carries `assetLeg` and `heldPayment` |
| `RECIPIENT_NOT_VERIFIED` | `409` | The buyer is not verified on the asset token's identity register. `details` carries `recipient` and `registry` |
| `RECIPIENT_REFUSED` | `409` | Custody mode: the asset token refuses the transfer from the adapter to the buyer. `details` carries `recipient` and `reason` |
| `TX_WOULD_REVERT` | `409` | The delivery would revert: `NotSeller` with `details.requiredRole`, `details.seller` and `details.roleHolders`, or an adapter or token refusal |
| `CHAIN_UNAVAILABLE` | `503` | The chain could not be read, including the market implementation or the buyer. Nothing was built. Retry shortly |
| `SELLER_FINANCING_UNAVAILABLE` | `503` | The instance is a `PRODUCTION` instance or not on Ethereum |
| `DELIVER_BUILD_FAILED` | `500` | Unexpected failure. Nothing was built. Retry, or contact support with the request ID |
