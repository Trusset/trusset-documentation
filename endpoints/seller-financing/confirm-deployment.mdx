---
title: 'Record Deployment'
api: 'POST /seller-financing/api/markets/confirm'
description: 'Verify a broadcast market deployment and record the market on your instance'
---

<Note>
  Financing is in beta and runs on Ethereum Sepolia instances only for now (`DEVELOPMENT` instances on Ethereum). A `PRODUCTION` instance, or one on another network, answers `503 SELLER_FINANCING_UNAVAILABLE`. See [Financing](/endpoints/seller-financing/introduction).
</Note>

Records a market your instance deployed. Send the hash of the mined `deployMarket` transaction built by [Build Deployment](/endpoints/seller-financing/deploy-market). This is the only Financing write with a confirm call. Everything after it is read from the chain.

The API reads the receipt and checks, in order:

1. The transaction is mined and succeeded.
2. It calls `deployMarket` on your network's Financing factory, directly or wrapped in a smart-account call.
3. The factory emitted `MarketDeployed` with the signing wallet as deployer.
4. No other instance has recorded the market. A market recorded elsewhere answers `409 MARKET_RECORDED_ELSEWHERE`, whatever wallet signed it. `details.marketId` names its record ID only when a verified wallet of your instance holds `OPERATOR_ROLE` or `DEFAULT_ADMIN_ROLE` on it, read on chain.
5. The wallet that signed it is a verified wallet of your instance.
6. The factory recognises the market as its own.

A deployment sent through a Safe, an EIP-7702 account or an ERC-4337 smart account is accepted. The API reads the wrapped call, and the signer is the smart account that called the factory, so that account must be the verified wallet of your instance. The wallet that broadcast the outer transaction is kept as `outerSender` on the role assignment record.

The answer carries the market record, the role assignment record built from the same receipt, and the token-side setup the adapter still needs.

A market is recorded once, on the instance whose wallet signed its deployment. An instance one of whose verified wallets holds `OPERATOR_ROLE` or `DEFAULT_ADMIN_ROLE` on a market another instance recorded does not record it again: every market route answers for it by its ID, and [List Markets](/endpoints/seller-financing/list-markets) lists it when that wallet is the admin or operator named at deployment. See [Which markets your instance reaches](/endpoints/seller-financing/introduction#which-markets-your-instance-reaches).

## Body Parameters

<ParamField body="txHash" type="string" required>
  Hash of the mined deployment transaction: `0x` followed by 64 hex characters. A malformed hash answers the standard `400 VALIDATION_ERROR` with the message "txHash must be a 32-byte hex hash" and `details: [{ field: "txHash", message }]`, before anything is read.
</ParamField>

## Response Fields

The status is `201` when the market is recorded now and `200` when it was already recorded on your instance. Sending the same hash again is safe.

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="market" type="object">The market record, as on [List Markets](/endpoints/seller-financing/list-markets) without the live blocks: `id`, `chainId`, `address`, `adapter`, `assetToken`, `paymentToken`, `mode`, `admin`, `operator`, `collateralAgent`, `deployTxHash`, `deployBlock`, `signer`, `factory` and `createdAt`. Use `id` as `marketId` from now on.</ResponseField>
    <ResponseField name="created" type="boolean">`true` when this call recorded the market, `false` when it was already recorded.</ResponseField>
    <ResponseField name="signer" type="string">The wallet that signed the deployment, lowercased.</ResponseField>
    <ResponseField name="auditDocument" type="object">The role assignment record of the deployment. See [Get Role Audit](/endpoints/seller-financing/get-role-audit) for its fields.</ResponseField>
    <ResponseField name="tokenSetup" type="object">The token-side setup, as [Build Token Setup](/endpoints/seller-financing/token-setup) answers without `from`: `done: true` when the token already accepts the adapter, otherwise the step and who must sign it, or why no step can be prepared. `null` when it could not be read. Call [Build Token Setup](/endpoints/seller-financing/token-setup) then.</ResponseField>
  </Expandable>
</ResponseField>

<Tip>
  `TX_NOT_FOUND` is the expected answer when you confirm before the transaction is mined. Wait for one confirmation and send the hash again.
</Tip>

<Note>
  If the answer is an error after the market was already recorded, for example because the chain could not be read while the role record was built, send the same hash again. A recorded market answers `200` with `created: false`.
</Note>

<RequestExample>
```bash cURL
curl -X POST "https://api.trusset.org/seller-financing/api/markets/confirm" \
  -H "X-API-Key: trusset_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"txHash": "0xab2709878f3c6a93fef46c073043a8a7206fa5a164e04bf1f2cd5055da619fde"}'
```
```typescript TypeScript
const res = await fetch('https://api.trusset.org/seller-financing/api/markets/confirm', {
  method: 'POST',
  headers: { 'X-API-Key': 'trusset_your_key_here', 'Content-Type': 'application/json' },
  body: JSON.stringify({ txHash })
});
const { data } = await res.json();
const marketId = data.market.id;
if (data.tokenSetup && !data.tokenSetup.done) {
  console.log('Token-side setup, signed by', data.tokenSetup.requiredSigner);
}
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `VALIDATION_ERROR` | `400` | `txHash` is missing or not `0x` followed by 64 hex characters ("txHash must be a 32-byte hex hash"), or the body carries another field. `error.details` names the field |
| `TX_REVERTED` | `400` | The transaction was mined but reverted. Nothing was deployed |
| `TX_WRONG_TARGET` | `400` | The transaction is not sent to the Financing factory of your network, and no recognised smart-account call inside it calls `deployMarket` on that factory |
| `TX_WRONG_FUNCTION` | `400` | The transaction calls the factory directly, but not `deployMarket` |
| `TX_NOT_VERIFIED` | `400` | The receipt carries no `MarketDeployed` from the factory for the signing wallet, or the factory does not recognise the market |
| `DEPLOYMENT_NOT_INSTANCE_BOUND` | `403` | The signer is not a verified wallet of your instance. The message names the signer. Register the wallet, then send the hash again. Checked after `MARKET_RECORDED_ELSEWHERE` |
| `TX_NOT_FOUND` | `404` | No receipt yet: the transaction is unmined, dropped or on another network |
| `MARKET_RECORDED_ELSEWHERE` | `409` | The market is recorded on the instance that deployed it. When a verified wallet of yours holds the operator or admin role on it, `details.marketId` is its record ID: use it on the market routes instead of recording the market. Otherwise there are no `details` |
| `CHAIN_UNAVAILABLE` | `503` | The chain could not be read. Retry shortly |
| `SERVICE_UNAVAILABLE` | `503` | Your instance's verified wallets could not be read. Retry shortly |
| `SELLER_FINANCING_UNAVAILABLE` | `503` | The instance is a `PRODUCTION` instance or not on Ethereum |
| `DEPLOY_CONFIRM_FAILED` | `500` | Unexpected failure. Send the hash again, or contact support with the request ID |
