---
title: 'List Claims'
api: 'GET /customers/api/identity/claims/{walletAddress}'
description: 'Every claim on an identity, read from the registry'
---

Returns the active claims the registry holds for a wallet. This is the raw chain read. For the same claims joined with the proof that filed each one, use [List Proofs](/endpoints/customers/list-proofs).

<Warning>
  A failed chain read returns an empty `claims` array with a `200`, not an error. An empty list does not prove the wallet holds no claims. Retry before acting on one.
</Warning>

## Path Parameters

<ParamField path="walletAddress" type="string" required>The subject's wallet address.</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="walletAddress" type="string">The subject, checksummed.</ResponseField>
    <ResponseField name="claims" type="array">One entry per active claim, each with its `claimType` index, `claimTypeLabel`, `dataHash`, `issuer`, `issuedAt`, `expiry` and `active`, which is always `true`. Revoked claims are not returned. On an ERC-3643 register, `issuer` is the trusted issuer contract, `issuedAt` and `expiry` are `0`, and each entry adds `topic`, `claimId` and `onchainId`.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  A claim's `dataHash` is the leaf hash from the bundle that filed it when it came from a proof, or the root itself for the `KYC` claim. That is what ties an on-chain claim back to a specific leaf in a specific bundle, and it is why the hash is worth recording alongside the bundle.
</Note>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/identity/claims/0xabCDeF0123456789AbcdEf0123456789aBCDEF01" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const wallet = '0xabCDeF0123456789AbcdEf0123456789aBCDEF01';
const res = await fetch(`https://api.trusset.org/customers/api/identity/claims/${wallet}`, {
  headers: { 'X-API-Key': 'trusset_your_key_here' }
});
const { data } = await res.json();

const residency = data.claims.find((c: any) => c.claimTypeLabel === 'RESIDENCY');
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_ADDRESS` | `400` | `walletAddress` is not a valid address |
| `CLAIMS_FAILED` | `500` | The register could not be resolved for this instance, for example an own-register binding without a valid address |
