---
title: 'Link Wallet'
api: 'POST /customers/api/manage/link-wallet'
description: 'Link a wallet address to a customer created with a reference key'
---

Links an Ethereum wallet address to an existing customer that was created without a wallet. This is the second step of the deferred wallet flow. First [create a customer](/endpoints/customers/create) without a `walletAddress` to receive a `referenceKey`. Then call this endpoint when the end-customer connects their wallet in your application.

The reference key must belong to a customer on your instance that is not archived and has no wallet yet. The wallet must be neither another active customer's primary nor any other customer's linked wallet.

## Body Parameters

<ParamField body="referenceKey" type="string" required>
  The reference key returned when the customer was created without a wallet address. Format: `ref_` followed by 32 hex characters.
</ParamField>

<ParamField body="walletAddress" type="string" required>
  Ethereum wallet address to link, as the customer's primary. Must be a valid checksummed or lowercased address. Stored checksummed.
</ParamField>

## Response Fields

<ResponseField name="success" type="boolean">Request status</ResponseField>
<ResponseField name="data" type="object">The updated customer record with the linked wallet address, with the fields listed on [Get Customer](/endpoints/customers/get) other than its linked wallets, company links, Sumsub applicant record and audit entries. `referenceKey` stays set.</ResponseField>

<Note>
  `status` becomes `verified` when the registry already holds a verified identity for the wallet, registered by the Trusset platform verifier or by one of your instance's verified wallets. On an instance bound to its own register, any verifier counts. Otherwise `status` is unchanged, and a registry read that fails does not fail the call.
</Note>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `MISSING_REFERENCE_KEY` | `400` | `referenceKey` is missing or not a string |
| `INVALID_ADDRESS` | `400` | `walletAddress` is missing or not a valid address |
| `INVALID_REFERENCE` | `400` | `referenceKey` does not start with `ref_` |
| `CUSTOMER_NOT_FOUND` | `404` | No customer on your instance that is not archived has this reference key |
| `WALLET_ALREADY_LINKED` | `409` | The customer already has a primary wallet |
| `WALLET_IN_USE` | `409` | The wallet is another active customer's primary or any other customer's linked wallet |
| `LINK_FAILED` | `500` | The link could not be written |
