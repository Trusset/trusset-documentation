---
title: 'Onboarding Options'
api: 'GET /customers/api/onboarding/options'
description: 'The profiles your instance onboards under and the provider each one uses'
---

Lists the enabled [verification profiles](/endpoints/customers/list-verification-profiles) of your instance with what an onboarding under each one involves: the provider it defaults to, the KYC sources that verify for it, and the rules a review is held to. Use it to decide in your app which flow to show a customer.

`defaultProvider` is the provider [Start Onboarding](/endpoints/customers/start-onboarding) uses when you name none. It is `KYC_SOURCE` for a profile with an active KYC source and `TRUSSET` for every other profile.

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="profiles" type="array">
      <Expandable>
        <ResponseField name="key" type="string">The value to send as `profile`.</ResponseField>
        <ResponseField name="name" type="string">The display name.</ResponseField>
        <ResponseField name="description" type="string">Or `null`.</ResponseField>
        <ResponseField name="entityType" type="string">`INDIVIDUAL` for natural persons, `COMPANY` for legal entities.</ResponseField>
        <ResponseField name="professionalOnly" type="boolean">Whether the profile is limited to professional clients.</ResponseField>
        <ResponseField name="onChainInvestorType" type="integer">`1` retail, `2` professional, `3` eligible counterparty.</ResponseField>
        <ResponseField name="blockedCountries" type="string[]">ISO 3166-1 alpha-3 codes a customer cannot be onboarded from.</ResponseField>
        <ResponseField name="reverifyDays" type="integer">Days until a verification under the profile lapses, or `null`.</ResponseField>
        <ResponseField name="requiredFields" type="array">The documents the identity check asks for.</ResponseField>
        <ResponseField name="defaultProvider" type="string">`TRUSSET` or `KYC_SOURCE`.</ResponseField>
        <ResponseField name="providers" type="object">
          `TRUSSET` with `available` and `levelName`, the Sumsub level of the profile. `KYC_SOURCE` with `available` and `sources`, each `id`, `name` and `status` (`ACTIVE` or `PAUSED`). A KYC source is available when one is active, your instance has a record key, and sealed KYC records are enabled for it.
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="sealedKyc" type="object">`enabled` and `recordKeySet` for your instance. See [Availability](/endpoints/customers/introduction#availability).</ResponseField>
  </Expandable>
</ResponseField>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/onboarding/options" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const response = await fetch('https://api.trusset.org/customers/api/onboarding/options', {
  headers: { 'X-API-Key': 'trusset_your_key_here' }
});
const { data } = await response.json();
const professional = data.profiles.find((profile) => profile.key === 'PROFESSIONAL');
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `RATE_LIMIT_EXCEEDED` | `429` | More than 240 onboarding reads in the minute |
| `ONBOARDING_OPTIONS_FAILED` | `500` | The read failed on the server |
