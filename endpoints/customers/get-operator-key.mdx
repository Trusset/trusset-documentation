---
title: 'Get Operator Key'
api: 'GET /customers/api/identity/operator-key'
description: 'Read the fallback proof signing key and the proof settings of this instance'
---

Returns the fallback ed25519 public key registered on this instance, and whether `stub` bundles are refused. A 3.1 bundle header is checked against the key the identity hub publishes for its attester; the key here is used only when the attester has published none. See [Set Operator Key](/endpoints/customers/set-operator-key).

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="operatorKey" type="string">The registered fallback key, lowercased and unprefixed. `null` when none is set.</ResponseField>
    <ResponseField name="operatorKeySetAt" type="string">When it was last set, ISO 8601, or `null`.</ResponseField>
    <ResponseField name="proofVerificationEnabled" type="boolean">Whether this instance asked to refuse `stub` bundles.</ResponseField>
    <ResponseField name="proofVerificationEnforced" type="boolean">Whether it actually does. This is `true` when the instance asked for it, and always on a production instance, whose trust anchors refuse stub bundles whatever the instance set. It does not mean Trusset checks proofs: Trusset never receives them, so verify them on your side before you send a bundle.</ResponseField>
    <ResponseField name="maxStalenessDays" type="integer">The staleness bound for a bundle's batch date, in days. `null` when unset, in which case the default of 400 days applies.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  `proofVerificationEnabled` and `proofVerificationEnforced` differ on a production instance that did not ask to refuse stub bundles. The setting is what you chose; the enforced flag is what a submission will be judged against.
</Note>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/identity/operator-key" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const res = await fetch('https://api.trusset.org/customers/api/identity/operator-key', {
  headers: { 'X-API-Key': 'trusset_your_key_here' }
});
const { data } = await res.json();

const stubAccepted = !data.proofVerificationEnforced;
const stalenessDays = data.maxStalenessDays ?? 400;
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key no longer exists |
| `OPERATOR_KEY_FAILED` | `500` | The settings could not be read |
