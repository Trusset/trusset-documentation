---
title: 'Get Operator Key'
api: 'GET /customers/api/identity/operator-key'
description: 'Read the registered proof signing key and enforcement settings'
---

Returns the ed25519 public key this instance verifies proof manifests against, and whether proof verification is actually being enforced.

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="operatorKey" type="string">The registered key, lowercased and unprefixed. `null` when none is set. Without a key, an instance that does not enforce proofs skips the signature check.</ResponseField>
    <ResponseField name="operatorKeySetAt" type="string">When it was last set, ISO 8601, or `null`.</ResponseField>
    <ResponseField name="proofVerificationEnabled" type="boolean">Whether this instance asked for proofs to be required.</ResponseField>
    <ResponseField name="proofVerificationEnforced" type="boolean">Whether they actually are. This is `true` when the instance asked for it, and always on a production instance, whose trust anchors require proofs whatever the instance set. Gate your flow on this field.</ResponseField>
    <ResponseField name="maxStalenessDays" type="integer">The staleness bound for a bundle's batch date, in days. `null` when unset, in which case the default of 400 days applies.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  `proofVerificationEnabled` and `proofVerificationEnforced` differ on a production instance that did not ask for proofs. The setting is what you chose; the enforced flag is what a submission will be judged against.
</Note>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/identity/operator-key" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const res = await fetch('https://api.trusset.org/customers/api/identity/operator-key', {
  headers: { 'X-API-Key': 'trusset_your_key_here' }
});
const { data } = await res.json();

const sendProofs = data.proofVerificationEnforced;
const stalenessDays = data.maxStalenessDays ?? 400;
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key no longer exists |
| `OPERATOR_KEY_FAILED` | `500` | The settings could not be read |
