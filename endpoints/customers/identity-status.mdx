---
title: 'Identity Status'
api: 'GET /customers/api/identity/status/{walletAddress}'
description: 'Query both on-chain and off-chain identity status for a wallet'
---

Returns the current identity state from two sources: the identity register your instance writes to, and your customer record. On the instance ID register the on-chain side is what the register resolves from the attestations of its trusted attesters on the identity hub. Comparing them shows where chain state and your records disagree.

<Warning>
  A register that cannot be read does not fail this call. It answers `200` with `onChain.unavailable: true` and a zeroed record whose `isVerified` is `false`. Check `unavailable` before you read `isVerified`, or an outage reads as a customer who is not verified.
</Warning>

## Path Parameters

<ParamField path="walletAddress" type="string" required>
  The wallet to query. Checksummed or lowercase.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="walletAddress" type="string">The wallet, checksummed.</ResponseField>
    <ResponseField name="onChain" type="object">
      The identity as the register reports it. Always an object, never `null`: a wallet the register does not know reads as a zeroed record.
      <Expandable>
        <ResponseField name="kycHash" type="string">The registered KYC hash. On the instance ID register, the root of the attestation the register resolves for the wallet. On an ERC-3643 register, the data of the wallet's KYC claim. All zeros when there is none.</ResponseField>
        <ResponseField name="investorType" type="integer">`1` retail, `2` professional, `3` eligible counterparty, `0` none. On the instance ID register, the investor class of the attestation, read as `1` when the register does not accept classes from that attester. Always `0` on an ERC-3643 register.</ResponseField>
        <ResponseField name="kycProvider" type="string">The wallet that wrote the identity. On the instance ID register, the attester of the attestation. On an ERC-3643 register, the trusted issuer of the KYC claim. The zero address when there is none.</ResponseField>
        <ResponseField name="timestamp" type="integer">Unix seconds of the last write. On the instance ID register, the issue time of the attestation. Always `0` on an ERC-3643 register, except on T-REX 5, where it is the issue time of the KYC claim.</ResponseField>
        <ResponseField name="softExpiry" type="integer">Unix seconds, or `0`. Always `0` on an ERC-3643 register.</ResponseField>
        <ResponseField name="hardExpiry" type="integer">Unix seconds, or `0`. Always `0` on an ERC-3643 register.</ResponseField>
        <ResponseField name="status" type="string">`none` for a wallet the register holds nothing for, with an all-zero `kycHash`. Otherwise, on the instance ID register and a Trusset-compatible register, `active`, `soft_expired`, `hard_expired` or `revoked`. On the instance ID register a suspended attestation also reads `revoked`. On an ERC-3643 register, `active` when verified, `revoked` when on the register but not verified, `none` when not on it. On T-REX 5 a wallet that carries a KYC claim which no longer counts, for example a revoked one, also reads `revoked`.</ResponseField>
        <ResponseField name="statusCode" type="integer">`0` active, `1` soft expired, `2` hard expired, `3` revoked or none.</ResponseField>
        <ResponseField name="frozen" type="boolean">Whether the register freezes the wallet. On the instance ID register the freeze applies to your instance only. Always `false` on an ERC-3643 register, where freezing lives on each token.</ResponseField>
        <ResponseField name="isVerified" type="boolean">Whether the register counts the wallet as verified. On the instance ID register that holds when a trusted attester's active, unexpired attestation carries `KYC_DONE` and the wallet is not frozen. On T-REX 5 it holds once the ONCHAINID the identity factory links to the wallet carries valid claims for the required topics, whether or not the wallet is registered on the register.</ResponseField>
        <ResponseField name="registerKind" type="string">`INSTANCE` on the instance ID register, `TREX` on an ERC-3643 register. Absent on a Trusset-compatible register of your own.</ResponseField>
        <ResponseField name="attester" type="string">Instance ID register only. The trusted attester whose attestation makes the wallet verified, or `null` when none does. The fields above then describe the first record a trusted attester holds about the wallet, so `status` shows why it does not count.</ResponseField>
        <ResponseField name="predicates" type="string">Instance ID register only. The predicate bits of that attestation the register accepts from its attester, as a decimal string of the 128-bit mask. `"0"` when no attester verifies the wallet. See [Predicates](/endpoints/customers/introduction#predicates).</ResponseField>
        <ResponseField name="predicateNames" type="string[]">Instance ID register only. The names of the standard predicate bits set in `predicates`, such as `KYC_DONE` or `EEA_RESIDENT`. Bits outside the standard table are not named.</ResponseField>
        <ResponseField name="trexVersion" type="integer">T-REX 5 only. `5`.</ResponseField>
        <ResponseField name="identityType" type="integer">T-REX 5 only. The identity type the factory records for the ONCHAINID, `2` individual or `3` corporate, or `null`.</ResponseField>
        <ResponseField name="onchainId" type="string">ERC-3643 only. The wallet's ONCHAINID, or `null`.</ResponseField>
        <ResponseField name="country" type="string">ERC-3643 only. The wallet's country on the register, in alpha-3, or `null`. Always `null` on T-REX 5, which records no country. The instance ID register holds no country.</ResponseField>
        <ResponseField name="unavailable" type="boolean">Present, and `true`, only when the register could not be read. Every other field is then zeroed and `status` is `none`.</ResponseField>
        <ResponseField name="unavailableReason" type="string">Present with `unavailable`. The code of the failed read, or `READ_FAILED`.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="offChain" type="object">
      Your customer record for the wallet, or `null` when there is none or it is archived.
      <Expandable>
        <ResponseField name="status" type="string">Customer status, such as `pending`, `verified` or `revoked`.</ResponseField>
        <ResponseField name="country" type="string">ISO 3166-1 alpha-3, or `null` when the record has none.</ResponseField>
        <ResponseField name="investorType" type="string">The investor type or verification profile key on the record, such as `PROFESSIONAL`.</ResponseField>
        <ResponseField name="verifiedAt" type="string">When the record was last verified, ISO 8601, or `null`.</ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/identity/status/0xaBc123DEf456789012345678901234567890aBCD" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const address = '0xaBc123DEf456789012345678901234567890aBCD';
const response = await fetch(
  `https://api.trusset.org/customers/api/identity/status/${address}`,
  { headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { data } = await response.json();

if (data.onChain.unavailable) {
  throw new Error(`Register unreadable: ${data.onChain.unavailableReason}`);
}
if (data.onChain.isVerified && data.offChain?.status !== 'verified') {
  console.warn('Verified on the register but not in your records');
}
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_ADDRESS` | `400` | `walletAddress` is not a valid address |
| `INSTANCE_REGISTER_REQUIRED` | `409` | Your instance is in Trusset mode and has not created its instance ID register yet |
| `STATUS_FAILED` | `500` | The customer record could not be read, or the request failed unexpectedly |
