---
title: 'Identity Status'
api: 'GET /customers/api/identity/status/{walletAddress}'
description: 'Query both on-chain and off-chain identity status for a wallet'
---

Returns the current identity state from two sources: the identity register your instance writes to, and your customer record. Comparing them shows where chain state and your records disagree.

<Warning>
  A register that cannot be read does not fail this call. It answers `200` with `onChain.unavailable: true` and a zeroed record whose `isVerified` is `false`. Check `unavailable` before you read `isVerified`, or an outage reads as a customer who is not verified.
</Warning>

## Path Parameters

<ParamField path="walletAddress" type="string" required>
  The wallet to query. Checksummed or lowercase.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="walletAddress" type="string">The wallet, checksummed.</ResponseField>
    <ResponseField name="onChain" type="object">
      The identity as the register reports it. Always an object, never `null`: a wallet the register does not know reads as a zeroed record.
      <Expandable>
        <ResponseField name="kycHash" type="string">The registered KYC hash. On an ERC-3643 register, the data of the wallet's KYC claim. All zeros when there is none.</ResponseField>
        <ResponseField name="investorType" type="integer">`1` retail, `2` professional, `3` eligible counterparty, `0` none. Always `0` on an ERC-3643 register.</ResponseField>
        <ResponseField name="kycProvider" type="string">The wallet that last wrote the identity. On an ERC-3643 register, the trusted issuer of the KYC claim. The zero address when there is none.</ResponseField>
        <ResponseField name="timestamp" type="integer">Unix seconds of the last write. Always `0` on an ERC-3643 register.</ResponseField>
        <ResponseField name="softExpiry" type="integer">Unix seconds, or `0`. Always `0` on an ERC-3643 register.</ResponseField>
        <ResponseField name="hardExpiry" type="integer">Unix seconds, or `0`. Always `0` on an ERC-3643 register.</ResponseField>
        <ResponseField name="status" type="string">On a Trusset register, `active`, `soft_expired`, `hard_expired` or `revoked`. A wallet that was never verified also reads `revoked`, with an all-zero `kycHash`. On an ERC-3643 register, `active` when verified, `revoked` when on the register but not verified, `none` when not on it.</ResponseField>
        <ResponseField name="statusCode" type="integer">`0` active, `1` soft expired, `2` hard expired, `3` revoked or none.</ResponseField>
        <ResponseField name="frozen" type="boolean">Whether the register freezes the wallet. Always `false` on an ERC-3643 register, where freezing lives on each token.</ResponseField>
        <ResponseField name="isVerified" type="boolean">Whether the register counts the wallet as verified.</ResponseField>
        <ResponseField name="registerKind" type="string">ERC-3643 only. Always `TREX`.</ResponseField>
        <ResponseField name="onchainId" type="string">ERC-3643 only. The wallet's ONCHAINID, or `null`.</ResponseField>
        <ResponseField name="country" type="string">ERC-3643 only. The wallet's country on the register, in alpha-3, or `null`.</ResponseField>
        <ResponseField name="unavailable" type="boolean">Present, and `true`, only when the register could not be read. Every other field is then zeroed and `status` is `none`.</ResponseField>
        <ResponseField name="unavailableReason" type="string">Present with `unavailable`. The code of the failed read, or `READ_FAILED`.</ResponseField>
        <ResponseField name="migration" type="object">
          Present only on the Trusset ID Register, for an identity the register move of 10 October 2026 copied and nobody has rewritten since. See [The Trusset ID Register](/endpoints/customers/introduction#the-trusset-id-register).
          <Expandable>
            <ResponseField name="previousRegistry" type="string">The register the identity was copied from, lowercased.</ResponseField>
            <ResponseField name="originalKycProvider" type="string">The wallet that verified the identity on the previous register, lowercased.</ResponseField>
            <ResponseField name="originalKycProviderName" type="string">That wallet's name as the previous register records it, such as `Trusset Test KYC`, or `null`.</ResponseField>
            <ResponseField name="originalTimestamp" type="integer">Unix seconds of the original verification.</ResponseField>
            <ResponseField name="originalSoftExpiry" type="integer">The soft expiry on the previous register, Unix seconds, or `null` when it had none.</ResponseField>
            <ResponseField name="softExpiryRefreshed" type="boolean">`true` when that soft expiry had passed and the copy moved it to one hour after the copy. `softExpiry` above holds the moved value.</ResponseField>
            <ResponseField name="migratedAt" type="integer">Unix seconds of the copy. The same value as `timestamp`.</ResponseField>
            <ResponseField name="migrator" type="string">The migration key that wrote the copy, lowercased. The same wallet as `kycProvider`.</ResponseField>
            <ResponseField name="migratorName" type="string">`Trusset register migration`.</ResponseField>
            <ResponseField name="migrationTxHash" type="string">The transaction that wrote the copy, or `null`.</ResponseField>
          </Expandable>
        </ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="offChain" type="object">
      Your customer record for the wallet, or `null` when there is none or it is archived.
      <Expandable>
        <ResponseField name="status" type="string">Customer status, such as `pending`, `verified` or `revoked`.</ResponseField>
        <ResponseField name="country" type="string">ISO 3166-1 alpha-3, or `null` when the record has none.</ResponseField>
        <ResponseField name="investorType" type="string">The investor type or verification profile key on the record, such as `PROFESSIONAL`.</ResponseField>
        <ResponseField name="verifiedAt" type="string">When the record was last verified, ISO 8601, or `null`.</ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
  On an identity copied in the register move, `kycProvider` and `timestamp` show the copy: the migration key and 10 October 2026. The original verifier and the date of the original verification are in `migration`. Read them from there when you report who verified the customer and when.
</Note>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/identity/status/0xaBc123DEf456789012345678901234567890aBCD" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const address = '0xaBc123DEf456789012345678901234567890aBCD';
const response = await fetch(
  `https://api.trusset.org/customers/api/identity/status/${address}`,
  { headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { data } = await response.json();

if (data.onChain.unavailable) {
  throw new Error(`Register unreadable: ${data.onChain.unavailableReason}`);
}
if (data.onChain.isVerified && data.offChain?.status !== 'verified') {
  console.warn('Verified on the register but not in your records');
}
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_ADDRESS` | `400` | `walletAddress` is not a valid address |
| `STATUS_FAILED` | `500` | The customer record could not be read, or no register is configured for the instance's network |
