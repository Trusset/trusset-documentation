---
title: 'List Verification Profiles'
api: 'GET /customers/api/verification-profiles'
description: 'The verification levels configured for your instance'
---

Returns the verification profiles your instance runs. A profile ties a verification level to the investor type it results in, the documents it requires, and the countries it refuses.

That lets a hosted [ID Link](/endpoints/customers/create-id-link) be issued against a named level rather than an ad-hoc set of requirements.

## Response Fields

<ResponseField name="data" type="array">
  <Expandable>
    <ResponseField name="id" type="string">Profile ID.</ResponseField>
    <ResponseField name="key" type="string">Stable key for the profile. The presets use `RETAIL`, `PROFESSIONAL` and `ELIGIBLE_COUNTERPARTY`. A custom profile uses a lowercase slug. An ID link names its profile by this key, in `investorType`.</ResponseField>
    <ResponseField name="name" type="string">Display name.</ResponseField>
    <ResponseField name="description" type="string">What the level covers, or `null`.</ResponseField>
    <ResponseField name="onChainInvestorType" type="integer">The investor type a customer receives on passing: `1` retail, `2` professional, `3` eligible counterparty.</ResponseField>
    <ResponseField name="sumsubLevelName" type="string">The provider-side level this maps to.</ResponseField>
    <ResponseField name="requiredFields" type="array">
      The document sets the level collects.
      <Expandable>
        <ResponseField name="id" type="string">Field ID.</ResponseField>
        <ResponseField name="idDocSetType" type="string">`IDENTITY`, `SELFIE`, `PROOF_OF_RESIDENCE`, `APPLICANT_DATA`, `QUESTIONNAIRE` or `COMPANY`.</ResponseField>
        <ResponseField name="types" type="string[]">The accepted document types, such as `PASSPORT`. Absent when any type is accepted.</ResponseField>
        <ResponseField name="required" type="boolean">Whether the set is mandatory.</ResponseField>
        <ResponseField name="label" type="string">Display label.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="blockedCountries" type="string[]">Countries the profile refuses, as ISO 3166-1 alpha-3 codes, sorted. Empty when none are blocked.</ResponseField>
    <ResponseField name="isPreset" type="boolean">Whether this is a Trusset preset rather than one your instance defined.</ResponseField>
    <ResponseField name="enabled" type="boolean">Whether it can currently be used.</ResponseField>
    <ResponseField name="createdAt" type="string">ISO 8601.</ResponseField>
    <ResponseField name="updatedAt" type="string">ISO 8601.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  `data` is the array itself, not an object wrapping one. Profiles are created and edited in the Issuer Portal; this surface reads them. The first call creates the three presets when the instance has none. Presets come first, then custom profiles, oldest first.
</Note>

## Blocked countries

A customer from a country on `blockedCountries` is refused with `403 COUNTRY_BLOCKED` wherever the profile applies. That covers ID links and customer records that name it, and the pending verification queue.

[Verify Identity](/endpoints/customers/verify-identity) and [Batch Verify](/endpoints/customers/batch-verify) check the preset whose key matches the request's `investorType`. A custom profile's list does not apply to them.

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/verification-profiles" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const response = await fetch('https://api.trusset.org/customers/api/verification-profiles', {
  headers: { 'X-API-Key': 'trusset_your_key_here' }
});
const { data: profiles } = await response.json();

const professional = profiles.find((profile: { key: string }) => profile.key === 'PROFESSIONAL');
```
</RequestExample>
