---
title: 'Get Disclosure Request'
api: 'GET /customers/api/disclosure-requests/{id}'
description: 'Read a disclosure request, with the signed consent and the envelope summary once approved'
---

Returns one disclosure request made by your instance. Once the holder approves it, the response also carries the consent the wallet signed and a summary of the encrypted envelope. It never carries the disclosure itself. Trusset holds only ciphertext, and your [local tool](/tools/kyc-courier/overview) downloads it with [Download Disclosure Envelope](/endpoints/customers/get-disclosure-envelope) and opens it on your machine.

## What an approval tells you

`proofLevel` is `ENCRYPTED_DISCLOSURE` once the holder answered with an envelope. The approval shows that the request wallet signed a consent naming one envelope, and that Trusset found the envelope well formed, within size and addressed to this request and your record key. Trusset verifies no proof and cannot read the envelope.

<Warning>
  An approval is consent, not a verified fact. Whether the envelope holds valid proofs that answer the scope is what your tool finds out when it opens it. Act on the disclosure only after your tool opened and verified it.
</Warning>

The consent recovers to the wallet with any EIP-712 library. The record Trusset keeps names `envelopeDigest` in `consent.typedData.message`, and it must equal `envelope.envelopeDigest`. That checks Trusset's record only. Your tool also recomputes the digest from the envelope bytes it downloads and rebuilds the typed data from the request, so it never relies on the copy served here.

A request approved before disclosures were encrypted shows `proofLevel: null` and `envelope: null`. Its consent is the version 1 typed data, without `envelopeDigest`, and the proofs it carried are no longer served.

## The envelope

`envelope.status` follows the ciphertext:

| `envelope.status` | Trusset holds the ciphertext | Next |
|---|---|---|
| `HELD` | Yes | `OPENED` through [Open Disclosure](/endpoints/customers/open-disclosure), `REJECTED` through [Reject Disclosure](/endpoints/customers/reject-disclosure), or `UNCLAIMED` at `collectBy`, 30 days after the holder answered |
| `OPENED` | No | `REJECTED` |
| `REJECTED` | No | Final |
| `UNCLAIMED` | No | Final |

After the ciphertext is deleted, Trusset keeps the header, the digests, the size, the consent and the dates. The consent names `envelopeDigest`, which commits to the header, which commits to `payloadDigest`, the SHA-256 of the plaintext your tool decrypted. So you can show later which plaintext the holder consented to.

<ParamField path="id" type="string" required>

</ParamField>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/disclosure-requests/cmi6q2x8v0004l50c7k3d9m1r" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
import { verifyTypedData } from 'ethers';

const response = await fetch(
  'https://api.trusset.org/customers/api/disclosure-requests/cmi6q2x8v0004l50c7k3d9m1r',
  { headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { data } = await response.json();

if (data.status === 'APPROVED' && data.envelope) {
  const { domain, types, message } = data.consent.typedData;
  if (message.envelopeDigest !== data.envelope.envelopeDigest) {
    throw new Error('The consent names another envelope');
  }
  const signer = verifyTypedData(domain, types, message, data.consent.signature);
  if (signer.toLowerCase() !== data.walletAddress.toLowerCase()) {
    throw new Error('The consent was not signed by the requested wallet');
  }
}
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `VALIDATION_ERROR` | `400` | `id` contains characters other than letters and digits, or is longer than 100 characters |
| `NOT_FOUND` | `404` | No request with this ID was made by your instance |
| `RATE_LIMIT_EXCEEDED` | `429` | Your instance went over its budget of 240 disclosure request reads per minute |
| `GET_DISCLOSURE_REQUEST_FAILED` | `500` | The request could not be read |
