---
title: 'Revoke Identity'
api: 'POST /customers/api/identity/revoke'
description: 'Revoke a wallet on the identity register and mark the customer revoked'
---

Revokes a wallet's identity on the register your instance writes to, and marks the customer record `revoked`. Use it when a customer fails ongoing compliance checks or their verification must be invalidated.

<Warning>
  On an ERC-3643 register, revoking deletes the wallet's entry from the register and nothing else. The ONCHAINID and its KYC claim stay as they are. To invalidate the claim as well, call [Revoke Claim](/endpoints/customers/revoke-claim) first. Once the entry is deleted, the claim can no longer be found through the wallet.
</Warning>

Both registers answer with one transaction. What it does depends on `registerKind`:

| `registerKind` | Transaction | Effect | Who sends it |
|---|---|---|---|
| `TRUSSET` | `revokeIdentity` on the register | The identity stays on the register and reads as `revoked` | A wallet with `REGISTER_OPERATOR_ROLE` |
| `TREX` | `deleteIdentity` on the register | The wallet's entry is removed from the register | An agent of the register |

Call it once without `txHash` to get the calldata, and again with `txHash` once the transaction is mined. The record is updated on the second call.

## Body Parameters

<ParamField body="walletAddress" type="string" required>
  The wallet to revoke. Checksummed or lowercase.
</ParamField>

<ParamField body="signerAddress" type="string">
  ERC-3643 only. Returned as `signerAddress`, in place of your primary wallet. The API does not check it.
</ParamField>

<ParamField body="txHash" type="string">
  The hash of the mined transaction. Send it to confirm the revocation and update the record. Omit it to receive the calldata.
</ParamField>

## Before the calldata

On a Trusset register, the API refuses with `REGISTER_OPERATOR_ROLE_MISSING` when it can read that none of your instance's wallets holds the role. It does not check that the wallet holds an unrevoked identity, and revoking one that does not reverts on chain.

On an ERC-3643 register, it refuses with `REGISTRY_AGENT_MISSING` when none of your instance's wallets is an agent. It refuses with `NOT_REGISTERED` when the wallet is not on the register.

## Confirm

The confirm leg checks that the transaction is mined, succeeded, and calls `revokeIdentity` or `deleteIdentity` on the register for the wallet you named. A receipt for a different wallet is refused with `TX_TARGET_MISMATCH`, and nothing changes. It does not check who signed.

It then sets the customer record for that wallet to `revoked` with `revokedAt`, archived or not. When no record exists, nothing is written and the call still succeeds.

<RequestExample>
```bash cURL
curl -X POST "https://api.trusset.org/customers/api/identity/revoke" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: trusset_your_key_here" \
  -d '{ "walletAddress": "0xaBc123DEf456789012345678901234567890aBCD" }'
```
```typescript TypeScript
const url = 'https://api.trusset.org/customers/api/identity/revoke';
const headers = {
  'Content-Type': 'application/json',
  'X-API-Key': 'trusset_your_key_here'
};
const walletAddress = '0xaBc123DEf456789012345678901234567890aBCD';

const res = await fetch(url, { method: 'POST', headers, body: JSON.stringify({ walletAddress }) });
const { data } = await res.json();

const tx = await wallet.sendTransaction(data.transaction);
await tx.wait();

await fetch(url, {
  method: 'POST',
  headers,
  body: JSON.stringify({ walletAddress, txHash: tx.hash })
});
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_ADDRESS` | `400` | `walletAddress` is missing or not a valid address |
| `REGISTER_OPERATOR_ROLE_MISSING` | `403` | Trusset register: none of your instance's wallets holds `REGISTER_OPERATOR_ROLE` |
| `REGISTRY_AGENT_MISSING` | `403` | ERC-3643: none of your instance's wallets is an agent of the register |
| `NOT_REGISTERED` | `409` | ERC-3643: the wallet is not on the register |
| `OWN_REGISTRY_NOT_CONFIGURED` | `409` | The instance is bound to its own register but no valid register address is set |
| `REGISTRY_PROBE_FAILED` | `503` | Your own register could not be read to tell its kind |
| `INVALID_TX` | `400` | `txHash` is not 32-byte hex |
| `TX_NOT_FOUND` | `404` | The transaction is not mined yet |
| `TX_REVERTED` | `400` | The transaction reverted |
| `TX_WRONG_TARGET` | `400` | The transaction does not write to the register |
| `TX_WRONG_FUNCTION` | `400` | The transaction does not call `revokeIdentity` or `deleteIdentity` |
| `TX_TARGET_MISMATCH` | `400` | The transaction revokes a different wallet |
| `CHAIN_UNAVAILABLE` | `503` | ERC-3643: the transaction could not be read |
| `REVOKE_FAILED` | `400`, `500` | Any other failure. `400` when a chain call failed |
