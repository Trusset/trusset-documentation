---
title: 'Download Disclosure Envelope'
api: 'GET /customers/api/disclosure-requests/{id}/envelope'
description: 'The encrypted disclosure of an approved request, while Trusset still holds it'
---

Returns the encrypted disclosure of one approved request: the header, the encapsulated key and the ciphertext exactly as the holder's browser sealed them, with the consent the wallet signed. Your [local tool](/tools/kyc-courier/overview) calls this, checks the envelope and decrypts it on your machine. You call it yourself only when you open disclosures with your own implementation.

The envelope is available only while `envelope.status` is `HELD`. Once it is opened, rejected or unclaimed, Trusset has deleted the ciphertext and this call answers `409 ENVELOPE_GONE`. Downloading changes nothing. The status changes only through [Open Disclosure](/endpoints/customers/open-disclosure) or [Reject Disclosure](/endpoints/customers/reject-disclosure). The response is sent with `Cache-Control: no-store`.

This route takes an API key only. The Issuer Portal never downloads or opens an envelope.

<Warning>
  `consent.typedData` and the digests are what Trusset stored. Do not rely on them as served. Recompute `envelopeDigest` from `header`, `enc` and `ciphertext`, rebuild the typed data from the request with that digest, and check that the signature recovers to the request wallet, as the tool does. Otherwise you trust Trusset for what the holder consented to.
</Warning>

## The envelope

`header` is the base64url encoding, without padding, of compact UTF-8 JSON with exactly these keys in this order. Those bytes are the HPKE associated data, so a changed header does not decrypt.

| Key | Value |
|---|---|
| `v` | `1` |
| `type` | `DISCLOSURE` |
| `suite` | `HPKE-X25519-SHA256-AES256GCM` |
| `requestId` | The request ID |
| `walletAddress` | The request wallet, lowercase |
| `recipientKeyId` | The `recipientKeyId` of the request |
| `scope` | The request scope |
| `predicates` | The fixed predicate list of the scope |
| `payloadDigest` | SHA-256 of the plaintext, 64 lowercase hex characters |
| `openCommitment` | SHA-256 of the 32 raw bytes of `openProof`, 64 lowercase hex characters |
| `createdAt` | When the holder's browser sealed it, ISO 8601 with milliseconds |

The header carries no personal data beyond the wallet address, and never names the leaves the holder disclosed.

The ciphertext is sealed with HPKE (RFC 9180) in base mode: DHKEM(X25519, HKDF-SHA256), HKDF-SHA256 and AES-256-GCM, to the public half of your record key. `info` is the UTF-8 string `trusset-disclosure-v1`. A [sealed KYC record](/endpoints/kyc-inbox/introduction#envelope-format) uses the same suite with `trusset-kyc-envelope-v1`, so a record never opens as a disclosure, or the other way round.

The plaintext is UTF-8 JSON with exactly these keys:

```json
{
  "version": "trusset-disclosure-payload-v1",
  "requestId": "cmi6q2x8v0004l50c7k3d9m1r",
  "wallet": "0x4b7250ae316d20ea2c1d74ece6414f4f192cf002",
  "openProof": "<64 lowercase hex characters>",
  "disclosures": [
    { "disclosure": { "...": "disclosures/<leaf>.json of the holder's bundle" }, "proof": "<proofs/<leaf>.bin in standard base64>" }
  ]
}
```

Each of the 1 to 32 items holds one [disclosed leaf](/tools/kyc-starks/bundle-format#disclosures) of a KYC-STARKs 3.1 bundle exactly as the tool wrote it, with its proof file in standard base64 with padding. The proof is an empty string for a commitment-only leaf. `openProof` is the value [Open Disclosure](/endpoints/customers/open-disclosure) takes.

### Envelope digest

```
envelopeDigest = keccak256(
    UTF8("trusset-disclosure-envelope-v1\n")
 || sha256(header bytes)
 || sha256(enc || ciphertext)
)
```

The header bytes are the decoded `header`. Both inner digests are the raw 32 bytes, not hex. `sha256(enc || ciphertext)` is `sealedDigest`. The holder's consent names this digest, so it binds the signature to the header, the ciphertext and, through `payloadDigest`, the plaintext.

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/disclosure-requests/cmi6q2x8v0004l50c7k3d9m1r/envelope" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
import { createHash } from 'node:crypto';
import { keccak256 } from 'ethers';

const res = await fetch(
  `https://api.trusset.org/customers/api/disclosure-requests/${requestId}/envelope`,
  { headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { success, data, error } = await res.json();

if (success) {
  const sha256 = (...parts: Buffer[]) => {
    const hash = createHash('sha256');
    for (const part of parts) hash.update(part);
    return hash.digest();
  };
  const headerBytes = Buffer.from(data.envelope.header, 'base64url');
  const enc = Buffer.from(data.envelope.enc, 'base64');
  const ciphertext = Buffer.from(data.envelope.ciphertext, 'base64');
  const envelopeDigest = keccak256(Buffer.concat([
    Buffer.from('trusset-disclosure-envelope-v1\n', 'utf8'),
    sha256(headerBytes),
    sha256(enc, ciphertext)
  ]));
}
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `VALIDATION_ERROR` | `400` | `id` contains characters other than letters and digits, or is longer than 100 characters |
| `NOT_FOUND` | `404` | No request with this ID was made by your instance |
| `ENVELOPE_NOT_FOUND` | `404` | The request carries no envelope: it is not approved, or it was approved before disclosures were encrypted |
| `ENVELOPE_GONE` | `409` | The envelope was opened, rejected or left uncollected, so the ciphertext was deleted. `details.envelopeStatus` is its status |
| `RATE_LIMIT_EXCEEDED` | `429` | Your instance went over its budget of 240 disclosure request reads per minute |
| `GET_DISCLOSURE_ENVELOPE_FAILED` | `500` | The envelope could not be read |
