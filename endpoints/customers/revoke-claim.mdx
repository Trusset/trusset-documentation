---
title: 'Revoke Claim'
api: 'POST /customers/api/identity/revoke-claim'
description: 'Revoke a claim on the registry'
---

Revokes one claim slot on the registry. It works on any slot, including the four filled from proofs.

<Warning>
  The confirm leg does not check which slot was revoked, and `claimType` in the answer echoes your request. On the Trusset register it checks that a `revokeClaim` for this wallet was mined on this instance's register. On an ERC-3643 register any mined `revokeClaimBySignature`, or a `removeClaim` on this wallet's ONCHAINID, is accepted.
</Warning>

For a proof-backed claim, prefer [Revoke Proof](/endpoints/customers/revoke-proof). It does the same revocation and three things more. It checks the slot on the Trusset register, deletes the ledger row that recorded which proof backed the slot, and writes a `REVOKE_CLAIM` audit entry.

## Body Parameters

<ParamField body="walletAddress" type="string" required>The subject.</ParamField>

<ParamField body="claimType" type="string | integer" required>The slot to revoke, as a name or an integer index from 0 to 7.</ParamField>

<ParamField body="txHash" type="string">Send it to confirm. Omit it to receive the calldata.</ParamField>

<ParamField body="signerAddress" type="string">ERC-3643 register only. The instance wallet you will send the revocation from, echoed back as `signerAddress`.</ParamField>

## Sign and confirm

On the Trusset register the calldata calls `revokeClaim` on the register, which needs a wallet holding `KYC_PROVIDER_ROLE`. Any holder of that role can revoke any slot, whoever filed it. The API checks that one of your instance's wallets holds the role, and refuses with `KYC_PROVIDER_ROLE_MISSING` otherwise. The register reverts the call when the slot holds no active claim.

On an ERC-3643 register the calldata calls `revokeClaimBySignature` on the trusted issuer that signed the claim. The claim stays on the ONCHAINID, and [List Claims](/endpoints/customers/list-claims) stops returning it once the issuer reports it invalid. A slot with no claim is refused up front with `CLAIM_NOT_FOUND`, and the role check becomes an agent check on the register.

The confirm leg does not check who signed.

<RequestExample>
```bash cURL
curl -X POST "https://api.trusset.org/customers/api/identity/revoke-claim" \
  -H "X-API-Key: trusset_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"walletAddress": "0xabCDeF0123456789AbcdEf0123456789aBCDEF01", "claimType": "AML"}'
```
```typescript TypeScript
const url = 'https://api.trusset.org/customers/api/identity/revoke-claim';
const headers = { 'X-API-Key': 'trusset_your_key_here', 'Content-Type': 'application/json' };
const body = { walletAddress: '0xabCDeF0123456789AbcdEf0123456789aBCDEF01', claimType: 'AML' };

const { data } = await fetch(url, { method: 'POST', headers, body: JSON.stringify(body) }).then(r => r.json());

const tx = await signer.sendTransaction(data.transaction);
await tx.wait();

await fetch(url, { method: 'POST', headers, body: JSON.stringify({ ...body, txHash: tx.hash }) });
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_ADDRESS` | `400` | `walletAddress` is missing or malformed |
| `INVALID_CLAIM_TYPE` | `400` | `claimType` is not a slot name or an index from 0 to 7 |
| `INVALID_TX` | `400` | `txHash` is not a 32-byte hex hash |
| `TX_REVERTED` | `400` | The transaction reverted |
| `TX_WRONG_TARGET` | `400` | The transaction was not sent to this instance's register |
| `TX_WRONG_FUNCTION` | `400` | The transaction does not call a revocation function |
| `TX_TARGET_MISMATCH` | `400` | The confirmed transaction targets a different wallet |
| `KYC_PROVIDER_ROLE_MISSING` | `403` | None of your instance's wallets holds `KYC_PROVIDER_ROLE` on the register. Calldata leg only |
| `REGISTRY_AGENT_MISSING` | `403` | ERC-3643 register: none of your instance's wallets is an agent of the register. Calldata leg only |
| `TX_NOT_FOUND` | `404` | The transaction is not mined yet |
| `CLAIM_NOT_FOUND` | `404` | ERC-3643 register: the wallet's ONCHAINID carries no claim in that slot |
| `OWN_REGISTRY_NOT_CONFIGURED` | `409` | The instance is bound to its own register but has no valid register address |
| `CHAIN_UNAVAILABLE` | `503` | ERC-3643 register: the transaction could not be read |
| `REGISTRY_PROBE_FAILED` | `503` | The interface of the instance's own register could not be read |
| `REVOKE_CLAIM_FAILED` | `400` or `500` | A chain call failed (`400`), or the request failed unexpectedly (`500`) |
