---
title: 'Inspect Manifest'
api: 'POST /customers/api/identity/manifest/inspect'
description: 'Check a 3.1 proof bundle against its signed header and see which leaves can be attested'
---

Checks a [KYC-STARKs](/tools/kyc-starks/overview) 3.1 manifest against its signed header, then reports every leaf and whether it can be filed. Nothing is written. Trusset reads the attester's operator key from the identity hub and checks that your instance trusts the attester, but does not compare the root with the one the register holds for the wallet.

Call it before [Add Claims from Proof](/endpoints/customers/add-claims-from-proof) or [Attest Proofs](/endpoints/customers/attest-proofs) to build a selection screen. A leaf that comes back with `attestable: false` cannot be filed there either, and `blockedReason` says why in words you can show.

<Warning>
  Trusset never receives proof bytes. A 3.1 proof reveals the value it is about: an age proof the date of birth, a set-membership proof the country, a tier proof the investor class. Verify the proofs on your side with the tool or the SDK, and send the manifest and its signed header only. A body that carries `proofs`, `proof`, `proofBytes` or `zk` is refused with `400 PROOFS_NOT_ACCEPTED`, and a 2.x or 3.0 manifest, which carries the country and the investor type in clear text, with `400 PERSONAL_DATA_IN_MANIFEST`.
</Warning>

The header signature is checked against the operator key the identity hub publishes for the header's attester and key id. When the attester has published no key on the hub, the key registered with [Set Operator Key](/endpoints/customers/set-operator-key) is used, and `operatorKey.source` reads `instance`. [What Trusset checks](/endpoints/customers/add-claims-from-proof#what-trusset-checks) lists every check.

<Note>
  Inspect Manifest, Add Claims from Proof and Attest Proofs share one rate limit per instance: 30 requests in a 60-second window. Past it, they answer `429 RATE_LIMITED` with a `Retry-After` header in seconds.
</Note>

## Body Parameters

<ParamField body="manifest" type="object" required>
  The `manifest.json` from the bundle directory the tool wrote, parsed as JSON, version `3.1.0`. At most 64 KiB serialized and 32 leaves.
</ParamField>

<ParamField body="header" type="object" required>
  The bundle's `header.json`, parsed.
</ParamField>

<ParamField body="headerSignature" type="string" required>
  The bundle's `header.sig`, the 64-byte ed25519 signature, as `0x` followed by 128 lowercase hex characters.
</ParamField>

<ParamField body="walletAddress" type="string">
  The customer you expect. When sent, the header must name this wallet, or the call answers `WALLET_MISMATCH`.
</ParamField>

<ParamField body="signerAddress" type="string">
  The wallet you will sign with. When sent, it must be the attester the header names, or the call answers `ATTESTER_MISMATCH`.
</ParamField>

## Leaves

<ResponseField name="leaves" type="array">
  <Expandable>
    <ResponseField name="fieldName" type="string">The leaf name, for example `country` or `country@country_allowlist`.</ResponseField>
    <ResponseField name="circuit" type="string">`age_threshold`, `set_membership`, `tier_threshold` or `preimage_knowledge`. A commitment-only leaf carries `preimage_knowledge`.</ResponseField>
    <ResponseField name="circuitId" type="integer">Its numeric id, 1 to 4, which is bound into the leaf hash.</ResponseField>
    <ResponseField name="predicate" type="string">The hub predicate the leaf proves, from its `binding.predicate`, or `null`.</ResponseField>
    <ResponseField name="predicateBit" type="integer">That predicate's bit on the identity hub, or `null`. `INVESTOR_CLASS` has none.</ResponseField>
    <ResponseField name="listId" type="string">For a `set_membership` leaf, the list it was proved against, or `null`.</ResponseField>
    <ResponseField name="listVersion" type="integer">The version of that list, or `null`.</ResponseField>
    <ResponseField name="validity" type="object">`from`, `until` (or `null`) and `basisAsOf`, in days, as the leaf records them.</ResponseField>
    <ResponseField name="leafHash" type="string">The leaf hash. On a register of your own it is written on chain as the claim's `dataHash`. On the instance ID register it stays in Trusset's proof ledger, and the chain holds the root and the predicate bit.</ResponseField>
    <ResponseField name="commitment" type="string">The commitment over the value.</ResponseField>
    <ResponseField name="proofDigest" type="string">The digest of the proof bytes the attester hashed. Trusset never sees the bytes.</ResponseField>
    <ResponseField name="publicDigest" type="string">Digest of the public inputs.</ResponseField>
    <ResponseField name="proofPath" type="string">Where the proof file sits in the bundle.</ResponseField>
    <ResponseField name="canonicalClaimType" type="string">The claim this leaf files as. On the instance ID register the claim of its predicate, such as `RESIDENCY` or `ADULT`. On a register of your own its reserved slot, or `null` when it has none and you choose one with Attest Proofs.</ResponseField>
    <ResponseField name="commitmentOnly" type="boolean">`true` for a `commitment_only` leaf, which carries no proof.</ResponseField>
    <ResponseField name="classOnly" type="boolean">`true` for the `INVESTOR_CLASS` leaf on the instance ID register. It sets the investor class of the attestation and is not a predicate of its own.</ResponseField>
    <ResponseField name="attestable" type="boolean">Whether this leaf can be filed as a claim right now.</ResponseField>
    <ResponseField name="blockedReason" type="string">Why not, in one sentence. `null` when attestable.</ResponseField>
  </Expandable>
</ResponseField>

## Why a leaf is blocked

Four things block a leaf, and each blocks only that leaf. The rest of the bundle stays usable.

**It carries no predicate.** A `commitment_only` leaf, or a proving leaf without a `binding.predicate` such as `documentIssuingCountry`, proves nothing the hub can record.

**Its parameters or list are outside policy.** The trust anchors decide which thresholds, which lists and which list contents this network accepts. A leaf proving an age floor nobody approved is reported here rather than failing the whole bundle.

**It is outside its validity window.** The leaf's `until` has passed, or its `from` is still ahead.

**It sets the investor class.** On the instance ID register the `INVESTOR_CLASS` leaf comes back `classOnly`. Its class goes into every attestation from this bundle.

The `INVESTOR_CLASS` leaf itself must not be blocked by policy or by its window: the whole call then fails with that leaf's code.

<RequestExample>
```bash cURL
BUNDLE=output/0xabCDeF0123456789AbcdEf0123456789aBCDEF01

curl -X POST "https://api.trusset.org/customers/api/identity/manifest/inspect" \
  -H "X-API-Key: trusset_your_key_here" \
  -H "Content-Type: application/json" \
  -d "{
    \"manifest\": $(cat "$BUNDLE/manifest.json"),
    \"header\": $(cat "$BUNDLE/header.json"),
    \"headerSignature\": \"0x$(xxd -p -c 64 "$BUNDLE/header.sig")\"
  }"
```
```typescript TypeScript
import { readFile } from 'node:fs/promises';

const bundle = 'output/0xabCDeF0123456789AbcdEf0123456789aBCDEF01';
const manifest = JSON.parse(await readFile(`${bundle}/manifest.json`, 'utf8'));
const header = JSON.parse(await readFile(`${bundle}/header.json`, 'utf8'));
const headerSignature = '0x' + (await readFile(`${bundle}/header.sig`)).toString('hex');

const res = await fetch(
  'https://api.trusset.org/customers/api/identity/manifest/inspect',
  {
    method: 'POST',
    headers: { 'X-API-Key': 'trusset_your_key_here', 'Content-Type': 'application/json' },
    body: JSON.stringify({ manifest, header, headerSignature })
  }
);
const { data } = await res.json();

for (const leaf of data.leaves.filter((l: any) => !l.attestable)) {
  console.warn(`${leaf.fieldName}: ${leaf.blockedReason}`);
}
```
</RequestExample>

## Error Codes

Every failure below except the last seven means the bundle did not hold together or does not bind to your instance. Each code means what it means on [Add Claims from Proof](/endpoints/customers/add-claims-from-proof#verification-failures).

| Code | HTTP | Cause |
|---|---|---|
| `PROOFS_NOT_ACCEPTED` | `400` | The body carries `proofs`, `proof`, `proofBytes` or `zk` |
| `PERSONAL_DATA_IN_MANIFEST` | `400` | The manifest carries clear-text personal values. Re-issue it with tool 3.1 |
| `INVALID_MANIFEST` | `400` | The manifest is missing, malformed or outside the 3.1.0 format, or its `epochDays` is missing or in the future |
| `PROOF_TOO_LARGE` | `413` | The manifest is over 64 KiB |
| `TOO_MANY_LEAVES` | `413` | The manifest carries more than 32 leaves |
| `UNSUPPORTED_VERSION` | `400` | The manifest version, STARK library or security level is not one this verifier accepts |
| `UNSUPPORTED_CIRCUIT` | `400` | A leaf names a circuit this verifier does not know |
| `STUB_NOT_ALLOWED` | `400` | A `stub` bundle was sent to a production instance, or to a development instance on which proof verification is enforced |
| `HEADER_REQUIRED` | `400` | `header` or `headerSignature` is missing |
| `INVALID_HEADER` | `400` | The header is malformed or not version `3.1.0` |
| `HEADER_MISMATCH` | `400` | The header and the manifest disagree |
| `WALLET_MISMATCH` | `400` | The header names a different wallet than `walletAddress` |
| `CHAIN_MISMATCH` | `400` | The header names a chain your instance does not write to |
| `HUB_MISMATCH` | `400` | The header names an identity hub your instance does not use |
| `ATTESTER_NOT_TRUSTED` | `403` | The header's attester is not trusted by your register |
| `ATTESTER_MISMATCH` | `400` | `signerAddress` is not the attester the header names |
| `OPERATOR_KEY_UNKNOWN` | `400` | The hub holds no operator key under the header's key id for this attester |
| `UNREGISTERED_OPERATOR_KEY` | `400` | No operator key on the hub and none registered on this instance |
| `INVALID_HEADER_SIGNATURE` | `400` | The header signature is malformed or does not verify |
| `PROOF_STALE` | `400` | The batch date is older than the staleness bound |
| `LEAF_INVALID` | `400` | A leaf's digests, parameters, list version or predicate do not hold |
| `LEAF_HASH_MISMATCH` | `400` | A leaf hash or binding digest does not recompute |
| `ROOT_MISMATCH` | `400` | The leaves do not recompute to the root the header signs |
| `UNAPPROVED_PARAMS`, `UNAPPROVED_LIST`, `LEAF_LAPSED` | `400` | The `INVESTOR_CLASS` leaf is outside policy or its window |
| `INVALID_ADDRESS` | `400` | `walletAddress` is malformed |
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key no longer exists |
| `INSTANCE_REGISTER_REQUIRED` | `409` | Your instance has no instance ID register yet |
| `RATE_LIMITED` | `429` | More than 30 proof requests from this instance in the current 60-second window |
| `IDENTITY_HUB_NOT_CONFIGURED` | `501` | The identity hub is not deployed on your instance's network |
| `CHAIN_UNAVAILABLE` | `503` | The identity hub or your register could not be read |
| `INSPECT_FAILED` | `500` | The bundle could not be read |
