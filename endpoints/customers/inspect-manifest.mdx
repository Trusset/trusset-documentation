---
title: 'Inspect Manifest'
api: 'POST /customers/api/identity/manifest/inspect'
description: 'Read a proof bundle and see which leaves can be attested'
---

Reads a manifest, checks its signature and recomputes its Merkle root, then reports every leaf and whether it can be filed as a claim. Nothing is written and no chain read happens.

Call it before [Add Claims from Proof](/endpoints/customers/add-claims-from-proof) to build a selection screen. A leaf that comes back with `attestable: false` cannot be filed there either, and `blockedReason` says why in words you can show.

<Note>
  Inspect Manifest, Add Claims from Proof and [Attest Proofs](/endpoints/customers/attest-proofs) share one rate limit per instance: 30 requests in a 60-second window. Past it, they answer `429 RATE_LIMITED` with a `Retry-After` header in seconds.
</Note>

## Body Parameters

<ParamField body="manifest" type="object" required>
  The `manifest.json` from the bundle directory the proof tool wrote, parsed as JSON. At most 64 KiB serialized and 32 leaves.
</ParamField>

<ParamField body="manifestSig" type="string">
  The 64 raw bytes of `manifest.sig`, base64-encoded. It is the ed25519 signature over a canonical view of the manifest, verified against the key from [Set Operator Key](/endpoints/customers/set-operator-key). Required whenever a key is registered. Without one, an instance that enforces proofs refuses the bundle and any other instance skips the check.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="ok" type="boolean">Always `true` on a `200`. A bundle that does not hold together is an error response, not `ok: false`.</ResponseField>
    <ResponseField name="kycHash" type="string">The Merkle root recomputed from the leaves, lowercased. It equals the manifest's own `kycHash`, or the call fails with `ROOT_MISMATCH`. It is the value to register on chain as the identity's `kycHash`.</ResponseField>
    <ResponseField name="walletAddress" type="string">The subject the bundle is for, checksummed.</ResponseField>
    <ResponseField name="epochDays" type="integer">The pinned batch date the bundle was proved against, in days. Every per-leaf commitment derives from it.</ResponseField>
    <ResponseField name="mode" type="string">`production` or `stub`. A `stub` bundle carries no real STARKs and is refused outright on a production instance.</ResponseField>
    <ResponseField name="signature" type="string">`verified` when the signature checked out against the registered key. `skipped-dev` when no key is registered and proofs are not enforced.</ResponseField>
    <ResponseField name="verifierVersion" type="string">The verifier that produced this reading, as `trusset-verifier@<tool commit>/<wasm hash prefix>`. It is recorded on every verification report so an old result stays interpretable.</ResponseField>
    <ResponseField name="assignableClaimTypes" type="array">The four slots a non-canonical leaf may be filed under: `AML`, `TAX_RESIDENCY`, `SANCTIONS_CHECK`, `PEP_CHECK`.</ResponseField>
    <ResponseField name="passthrough" type="object">`country`, `investorType`, `softExpiryDays` and `hardExpiryDays` as the tool carried them through. These are plain values, not proved facts, and each is `null` when absent.</ResponseField>
    <ResponseField name="leaves" type="array">One entry per leaf. See below.</ResponseField>
  </Expandable>
</ResponseField>

## Leaves

<ResponseField name="leaves" type="array">
  <Expandable>
    <ResponseField name="fieldName" type="string">The field this leaf commits to, for example `country` or `dateOfBirth@7665d`.</ResponseField>
    <ResponseField name="circuit" type="string">`age_threshold`, `set_membership`, `tier_threshold` or `preimage_knowledge`. A commitment-only leaf carries `preimage_knowledge`.</ResponseField>
    <ResponseField name="circuitId" type="integer">Its numeric id, 1 to 4, which is bound into the leaf hash.</ResponseField>
    <ResponseField name="leafHash" type="string">The leaf hash. This is what is written on chain as the claim's `dataHash`.</ResponseField>
    <ResponseField name="commitment" type="string">The hiding commitment over the value.</ResponseField>
    <ResponseField name="proofDigest" type="string">Digest of the STARK bytes, so the proof file can be tied to this leaf.</ResponseField>
    <ResponseField name="publicDigest" type="string">Digest of the public inputs.</ResponseField>
    <ResponseField name="proofPath" type="string">Where the proof file sits in the bundle, or `null`.</ResponseField>
    <ResponseField name="canonicalClaimType" type="string">The reserved slot this field must occupy, or `null` when the field has no canonical meaning and you choose a slot. A canonical field proved with the wrong circuit is also `null`, and cannot be filed at all.</ResponseField>
    <ResponseField name="commitmentOnly" type="boolean">`true` when the leaf is a commitment with no STARK behind it, which shows as a `proofDigest` equal to the digest of an empty proof.</ResponseField>
    <ResponseField name="attestable" type="boolean">Whether this leaf can be filed as a claim right now.</ResponseField>
    <ResponseField name="blockedReason" type="string">Why not, in one sentence. `null` when attestable.</ResponseField>
  </Expandable>
</ResponseField>

## Why a leaf is blocked

Three things block a leaf, and each blocks only that leaf. The rest of the bundle stays usable.

**The predicate parameters are outside policy.** A trust anchor decides which thresholds and which allowlists this network accepts. A leaf proving an age floor nobody approved is reported rather than failing the whole bundle.

**A canonical field was proved with the wrong circuit.** `country` must be proved with `set_membership`, `nationality` likewise, `investorType` with `tier_threshold`. A `country` leaf proved with `preimage_knowledge` is not filed anywhere, because filing it elsewhere would let it pass as an unrelated attestation.

**It is commitment-only and proofs are enforced.** There is no STARK to check, so under enforcement there is nothing to verify.

<RequestExample>
```bash cURL
BUNDLE=output/0xabCDeF0123456789AbcdEf0123456789aBCDEF01

curl -X POST "https://api.trusset.org/customers/api/identity/manifest/inspect" \
  -H "X-API-Key: trusset_your_key_here" \
  -H "Content-Type: application/json" \
  -d "{\"manifest\": $(cat "$BUNDLE/manifest.json"), \"manifestSig\": \"$(base64 < "$BUNDLE/manifest.sig" | tr -d '\n')\"}"
```
```typescript TypeScript
import { readFile } from 'node:fs/promises';

const bundle = 'output/0xabCDeF0123456789AbcdEf0123456789aBCDEF01';
const manifest = JSON.parse(await readFile(`${bundle}/manifest.json`, 'utf8'));
const manifestSig = (await readFile(`${bundle}/manifest.sig`)).toString('base64');

const res = await fetch(
  'https://api.trusset.org/customers/api/identity/manifest/inspect',
  {
    method: 'POST',
    headers: { 'X-API-Key': 'trusset_your_key_here', 'Content-Type': 'application/json' },
    body: JSON.stringify({ manifest, manifestSig })
  }
);
const { data } = await res.json();

for (const leaf of data.leaves.filter((l: any) => !l.attestable)) {
  console.warn(`${leaf.fieldName}: ${leaf.blockedReason}`);
}
```
</RequestExample>

## Error Codes

Every failure below except the last three means the bundle did not hold together. Each code means what it means on [Add Claims from Proof](/endpoints/customers/add-claims-from-proof#verification-failures), which has further codes of its own.

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_MANIFEST` | `400` | The manifest is missing or malformed, or its `epochDays` is missing or in the future |
| `PROOF_TOO_LARGE` | `413` | The manifest is over 64 KiB |
| `TOO_MANY_LEAVES` | `413` | The manifest carries more than 32 leaves |
| `UNSUPPORTED_VERSION` | `400` | The manifest version, circuits version or STARK library is not one this verifier accepts, or the security level is below 100 bits |
| `UNSUPPORTED_CIRCUIT` | `400` | A leaf names a circuit this verifier does not know |
| `COMMITMENT_MISMATCH` | `400` | A leaf's `publicInputs.commitment` differs from its `commitment` |
| `STUB_NOT_ALLOWED` | `400` | A `stub` bundle was sent to a production instance |
| `INVALID_SIGNATURE` | `400` | The signature is not 64 bytes, or does not verify under the registered key |
| `UNREGISTERED_OPERATOR_KEY` | `400` | No operator key is registered and proofs are enforced. Set one first |
| `PROOF_STALE` | `400` | The batch date is older than the staleness bound |
| `PROOF_INVALID` | `400` | A leaf's `publicDigest` does not recompute from its public inputs |
| `LEAF_HASH_MISMATCH` | `400` | A leaf hash does not recompute from its own components |
| `ROOT_MISMATCH` | `400` | The root recomputed from the leaves does not equal the one the manifest states |
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key no longer exists |
| `RATE_LIMITED` | `429` | More than 30 proof requests from this instance in the current 60-second window |
| `INSPECT_FAILED` | `500` | The bundle could not be read |
