---
title: 'Create Customer'
api: 'POST /customers/api/manage'
description: 'Register a new customer for the authenticated instance'
---

Creates a new customer record tied to the authenticated instance. You can either provide a wallet address directly, or omit it to receive a `referenceKey` that allows linking a wallet later via the [Link Wallet](/endpoints/customers/link-wallet) endpoint.

<Warning>
  If an archived customer on your instance has this `walletAddress` as its primary, the call restores that record rather than creating one. The record keeps its ID, linked wallets and `kycHash`. Its `status` and `verifiedAt` are set as for a new record, and its `referenceKey` is cleared. Every other field this endpoint takes is replaced from the body, and a field you omit is cleared or reset to its default.
</Warning>

## Body Parameters

At least one of `name`, `walletAddress` and `externalId` is required.

<ParamField body="walletAddress" type="string">
  Primary wallet. Letter case does not matter, but a mixed-case address must carry a valid checksum. Stored checksummed. If omitted, a `referenceKey` is generated for deferred wallet linking.
</ParamField>

<ParamField body="name" type="string">
  Customer display name. Required when `customerType` is `COMPANY`.
</ParamField>

<ParamField body="externalId" type="string">
  Your own external reference identifier for this customer. It must be unique among the customers of your instance that are not archived. [Update Customer](/endpoints/customers/update) does not take it.
</ParamField>

<ParamField body="customerType" type="string" default="INDIVIDUAL">
  `INDIVIDUAL` or `COMPANY`, in any letter case. [Update Customer](/endpoints/customers/update) refuses to change it.
</ParamField>

<ParamField body="country" type="string">
  ISO 3166-1 alpha-2, alpha-3 or numeric code, in any letter case (`DE`, `DEU` or `276`). Stored and returned as alpha-3.
</ParamField>

<ParamField body="investorType" type="string" default="RETAIL">
  `RETAIL`, `PROFESSIONAL` or `ELIGIBLE_COUNTERPARTY` in any letter case, or the key of one of your custom [verification profiles](/endpoints/customers/list-verification-profiles), also in any letter case. The record stores the key as the profile spells it, so `professional` is stored as `PROFESSIONAL`. A profile that is disabled takes no new customer, so naming one is refused with `INVALID_INVESTOR_TYPE` and the message says the profile is disabled. Omitted, `null` or an empty string stores `RETAIL`, unless the `RETAIL` preset is disabled. Anything else, a number included, is refused with `INVALID_INVESTOR_TYPE`, and the message lists the values your instance accepts.

  When the profile's blocked-country list holds `country`, the call is refused with `COUNTRY_BLOCKED`.
</ParamField>

<ParamField body="companyUrl" type="string">
  Company records only. Up to 300 characters. `https://` is added when no scheme is given, and the URL must use `http` or `https` with a dotted hostname. Stored in normalised form.
</ParamField>

<ParamField body="companyId" type="string">
  Individual records only. The ID of a company record on your instance that is not archived.
</ParamField>

<ParamField body="contactChannels" type="string[]">
  Up to 20 strings of up to 200 characters each. Entries are trimmed, blank ones are dropped, and duplicates are removed ignoring case.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary key-value metadata to store with the customer record.
</ParamField>

## Response Fields

Returns `201`, including when an archived record was restored.

<ResponseField name="success" type="boolean">Request status</ResponseField>
<ResponseField name="data" type="object">
  The customer record, with the fields listed on [Get Customer](/endpoints/customers/get) other than its linked wallets, company links, Sumsub applicant record and audit entries. `referenceKey` is set when no `walletAddress` was sent.
</ResponseField>

<Note>
  `status` starts as `pending`. It starts as `verified` when the registry already holds a verified identity for `walletAddress`, registered by the Trusset platform verifier or by one of your instance's verified wallets. On an instance bound to its own register, any verifier counts. A registry read that fails leaves the record `pending` and does not fail the call.
</Note>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_COUNTRY` | `400` | `country` is not an ISO 3166-1 code |
| `INVALID_INVESTOR_TYPE` | `400` | `investorType` names neither a preset nor one of your verification profiles, names a disabled profile, or is not a string |
| `MISSING_IDENTIFIER` | `400` | None of `name`, `walletAddress` and `externalId` was sent |
| `INVALID_ADDRESS` | `400` | `walletAddress` is not a valid address |
| `INVALID_CUSTOMER_TYPE` | `400` | `customerType` is not `INDIVIDUAL` or `COMPANY` |
| `MISSING_NAME` | `400` | A company was sent without `name` |
| `COMPANY_CANNOT_LINK` | `400` | A company was sent with `companyId` |
| `INVALID_COMPANY_URL` | `400` | `companyUrl` was sent for an individual, or is not a usable URL |
| `COMPANY_URL_TOO_LONG` | `400` | `companyUrl` is over 300 characters |
| `INVALID_COMPANY` | `400` | `companyId` is not a string of 20 to 40 characters |
| `INVALID_CONTACT_CHANNELS` | `400` | `contactChannels` is not an array |
| `TOO_MANY_CONTACT_CHANNELS` | `400` | More than 20 contact channels |
| `INVALID_CONTACT_CHANNEL` | `400` | A contact channel is not a string |
| `CONTACT_CHANNEL_TOO_LONG` | `400` | A contact channel is over 200 characters |
| `COUNTRY_BLOCKED` | `403` | `country` is on the blocked-country list of the profile `investorType` names |
| `COMPANY_NOT_FOUND` | `404` | `companyId` names no company record on your instance that is not archived |
| `CUSTOMER_EXISTS` | `409` | The wallet is another active customer's primary or any customer's linked wallet, or `externalId` is taken |
| `CREATE_FAILED` | `500` | The record could not be written |
