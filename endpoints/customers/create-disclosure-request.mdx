title: 'Create Disclosure Request'
api: 'POST /customers/api/disclosure-requests'
description: 'Ask a wallet holder to disclose facts from their KYC proof bundle, encrypted to your record key'
---

Asks the holder of a wallet to disclose facts from their KYC proof bundle to your instance. The holder answers on verify.trusset.org. Their browser encrypts the proofs the scope needs to the record key of your instance, and their wallet signs a consent that names that exact envelope. Trusset relays the ciphertext and cannot read it. Your [local tool](/tools/kyc-courier/overview) opens it and verifies the proofs on your machine. [Disclosures from a holder](/protocol/infrastructure/sealed-kyc-records#disclosures-from-a-holder) sets out the whole flow.

<Warning>
  A KYC STARK proof is not zero-knowledge. An age proof shows the date of birth and a country proof shows the country. You receive exactly the values the disclosed proofs show. Ask only for a scope you are entitled to see.
</Warning>

<Note>
  Creating a request sends the holder nothing. Tell them to sign in at verify.trusset.org with the wallet, in the same environment as your instance. No webhook reports the answer either, so read the request with [Get Disclosure Request](/endpoints/customers/get-disclosure-request).
</Note>

## Before you create one

The holder encrypts to the active record key of your instance: the key `trusset-kyc keygen` created and [Set Record Key](/endpoints/customers/set-kyc-record-key) registered. Without one the call answers `409 RECIPIENT_KEY_REQUIRED`. The request stores the key's ID as `recipientKeyId`, and an envelope encrypted to any other key is refused.

Replacing the record key strands every open request made under the old one. The holder can then only decline it, and an approval is refused with `409 RECIPIENT_KEY_RETIRED`. Cancel those requests and create them again. An open request made before disclosures were encrypted has no `recipientKeyId`. Its approval is refused with `409 RECIPIENT_KEY_REQUIRED`, so replace it the same way.

On a production instance, encrypted disclosures stay off until Trusset enables them for your organisation, with the same switch as [sealed KYC records](/protocol/infrastructure/sealed-kyc-records#availability). Until then this call answers `409 ENCRYPTED_DISCLOSURES_NOT_ENABLED`.

## Scopes

| Scope | `predicates` | The disclosure answers it when | What you learn |
|---|---|---|---|
| `AGE` | `["ADULT"]` | A disclosed leaf proves `ADULT` | The date of birth |
| `COUNTRY` | `["EEA_RESIDENT", "RESIDENCY_ON_FILE"]` | A disclosed leaf proves either predicate | The country of residence |
| `FULL_KYC` | `[]` | It covers every leaf of the bundle, under one root | Every value a proof in the bundle shows. Names and document data are commitment-only leaves and stay hidden |

The predicate list is fixed per scope, so it says nothing about the holder. The envelope never names the leaf the holder chose: for `COUNTRY` that would show whether the holder lives in the EEA. Only bundles made with [KYC-STARKs](/tools/kyc-starks/overview) 3.1 can be disclosed.

## What the holder sees and signs

The holder signs in by signing a message with the wallet. Each open request for that wallet shows your issuer name, or your instance name when there is none, with the scope, your `message`, your `referenceUrl` and the expiry.

Approving builds and encrypts the envelope in the browser first. The wallet then signs this EIP-712 consent, version 2. `envelopeDigest` commits to the header and the ciphertext of that envelope, so the signature covers exactly what you receive. Declining needs no signature.

```json
{
  "domain": { "name": "Trusset Verify", "version": "2", "chainId": 11155111 },
  "primaryType": "DisclosureConsent",
  "types": {
    "DisclosureConsent": [
      { "name": "requestId", "type": "string" },
      { "name": "wallet", "type": "address" },
      { "name": "requestor", "type": "string" },
      { "name": "scope", "type": "string" },
      { "name": "reference", "type": "string" },
      { "name": "expiresAt", "type": "uint256" },
      { "name": "envelopeDigest", "type": "bytes32" }
    ]
  },
  "message": {
    "requestId": "cmi6q2x8v0004l50c7k3d9m1r",
    "wallet": "0x4b7250ae316D20Ea2c1d74Ece6414F4f192cF002",
    "requestor": "ACME Capital AG",
    "scope": "COUNTRY",
    "reference": "https://acme-capital.example/onboarding/4711",
    "expiresAt": 1796376600,
    "envelopeDigest": "0xeb6b31ad295cd93c10b4cdc19ba1a136b767e17aa2e04b178c97903007f09548"
  }
}
```

`chainId` is 1 for a production instance and 11155111 (Sepolia) for a development one. `reference` is an empty string when you send no `referenceUrl`, and `expiresAt` is in Unix seconds. [Download Disclosure Envelope](/endpoints/customers/get-disclosure-envelope#envelope-digest) shows how `envelopeDigest` is computed. A version 1 consent had no `envelopeDigest`, and its signature never verifies as version 2.

Trusset recovers the signer from the envelope the holder posts and refuses the approval unless it is the request wallet. Only signatures from an externally owned wallet are accepted.

## How a request resolves

A request starts `OPEN` and ends in one of four states. `APPROVED` and `DECLINED` are the holder's answers. `CANCELLED` is yours, through [Cancel Disclosure Request](/endpoints/customers/cancel-disclosure-request). `EXPIRED` applies once `expiresAt` passes without an answer, and the holder can no longer respond.

Expiry is applied when requests are read, so a list or a fetch never shows an overdue request as `OPEN`.

An approved request carries an `envelope` with its own status. Trusset holds the ciphertext while it is `HELD`, and deletes it when you open or reject it, or 30 days after the holder answered. [Get Disclosure Request](/endpoints/customers/get-disclosure-request#the-envelope) has the states.

## Body Parameters

<ParamField body="walletAddress" type="string" required>
  The wallet whose holder you ask, as `0x` and 40 hex characters. Send it lowercase or correctly checksummed. It is returned checksummed.
</ParamField>

<ParamField body="scope" type="string" required>
  `AGE`, `COUNTRY` or `FULL_KYC`, in any case.
</ParamField>

<ParamField body="referenceUrl" type="string">
  An `https` link the holder can open, such as the case the request belongs to. At most 512 characters, with no user name or password in it. It is normalised, so a bare host gains a trailing slash, and it is part of the signed consent.
</ParamField>

<ParamField body="message" type="string">
  Shown to the holder. At most 280 characters after the ends are trimmed. Control characters other than tabs and line breaks are removed first.
</ParamField>

<ParamField body="expiresInDays" type="integer" default="14">
  Days the holder has to answer, from 1 to 90.
</ParamField>

A wallet can have one open request per scope from your instance, and at most five open requests from it in all. Requests made in the Issuer Portal count toward both.

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_ADDRESS` | `400` | `walletAddress` is missing or is not `0x` and 40 hex characters |
| `INVALID_SCOPE` | `400` | `scope` is not `AGE`, `COUNTRY` or `FULL_KYC` |
| `INVALID_REFERENCE` | `400` | `referenceUrl` is not an `https` URL, is longer than 512 characters, or carries a user name or password |
| `INVALID_MESSAGE` | `400` | `message` is not a string, or is longer than 280 characters |
| `INVALID_EXPIRY` | `400` | `expiresInDays` is not an integer from 1 to 90 |
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key no longer exists or is archived |
| `ENCRYPTED_DISCLOSURES_NOT_ENABLED` | `409` | A production instance whose organisation Trusset has not enabled yet |
| `RECIPIENT_KEY_REQUIRED` | `409` | Your instance has no active record key. Register one with [Set Record Key](/endpoints/customers/set-kyc-record-key) |
| `DUPLICATE_REQUEST` | `409` | The wallet already has an open request for this scope from your instance |
| `TOO_MANY_OPEN_REQUESTS` | `409` | The wallet already has five open requests from your instance |
| `RATE_LIMIT_EXCEEDED` | `429` | Your instance went over its budget of 120 disclosure request changes per minute |
| `CREATE_DISCLOSURE_REQUEST_FAILED` | `500` | The request could not be created. A mixed-case `walletAddress` with a wrong checksum also ends here |

`RECIPIENT_KEY_RETIRED` never comes from this call. The holder meets it when approving a request whose record key you replaced since.
