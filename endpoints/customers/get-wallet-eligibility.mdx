---
title: 'Get Wallet Eligibility'
api: 'GET /customers/api/eligibility/wallet/{walletAddress}'
description: 'Where one wallet stands on every eligibility register of your instance'
---

Reports, for one wallet, every verification profile of your instance that carries an eligibility register: the admission recorded for the wallet, and what the register itself answers right now. Use it before a lending or vault action to tell whether a gate built on a profile will admit the wallet.

The register's live answer is what a market or vault reads. It can differ from the admission: a removal waiting to be signed leaves the wallet on the register, and a register managed outside Trusset can hold wallets no admission was recorded for.

## Path Parameters

<ParamField path="walletAddress" type="string" required>
  The wallet, `0x` followed by 40 hex characters.
</ParamField>

## Query Parameters

<ParamField query="live" type="string" default="true">
  `false` skips the chain reads, so every `onChain` is `null`. Any other value reads the registers.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="walletAddress" type="string">The wallet, checksummed.</ResponseField>
    <ResponseField name="profiles" type="array">
      One entry per profile with a register, oldest profile first. Empty when no profile has one.
      <Expandable>
        <ResponseField name="profile" type="object">`{ key, name, entityType, professionalOnly, requirementsHash }`.</ResponseField>
        <ResponseField name="registryAddress" type="string">The profile's eligibility register.</ResponseField>
        <ResponseField name="admissionMode" type="string">`REGISTER`, `INSTANCE_REGISTER` or `EXTERNAL`, recorded when the register was bound. See [Which registers can be signed here](/endpoints/customers/introduction#which-registers-can-be-signed-here).</ResponseField>
        <ResponseField name="admission" type="object">The wallet's admission to that register, as on [List Admissions](/endpoints/customers/list-admissions), or `null` when none was recorded.</ResponseField>
        <ResponseField name="lastRefusal" type="object">The last automatic admission to this profile that was refused, `{ code, message, source, at }`, when it is newer than the admission row. For example a verification that finished while the customer's country is blocked under the profile. `null` otherwise.</ResponseField>
        <ResponseField name="onChain" type="object">
          The register's live answer. `null` with `live=false`.
          <Expandable>
            <ResponseField name="registered" type="boolean">Whether the wallet holds an identity on the register (`contains`). `null` when the register does not answer `contains`.</ResponseField>
            <ResponseField name="verified" type="boolean">What `isVerified(address)` answers, which is what a market or vault gate reads.</ResponseField>
            <ResponseField name="unavailable" type="boolean">Present and `true`, alone, when the register could not be read. It says nothing about the wallet.</ResponseField>
          </Expandable>
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>

<Warning>
  `onChain.unavailable: true` is a failed read, not a verdict. Do not treat the wallet as refused, and do not queue an admission or removal because of it. Read again shortly.
</Warning>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/eligibility/wallet/0xfF21b8AC28Bb6A20c1c0160AF42303D2946B99EA" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const wallet = '0xfF21b8AC28Bb6A20c1c0160AF42303D2946B99EA';
const response = await fetch(
  `https://api.trusset.org/customers/api/eligibility/wallet/${wallet}`,
  { headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { data } = await response.json();

const professional = data.profiles.find(
  (entry: { profile: { key: string } }) => entry.profile.key === 'PROFESSIONAL'
);
const admittedOnChain = professional?.onChain?.verified === true;
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_ADDRESS` | `400` | `walletAddress` is not a valid address, or is the zero address |
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key no longer exists |
| `ELIGIBILITY_NETWORK_UNSUPPORTED` | `409` | Your instance is not on Ethereum and `live` was not `false` |
| `RATE_LIMIT_EXCEEDED` | `429` | Your instance went over its budget of 120 eligibility requests per minute |
| `WALLET_ELIGIBILITY_FAILED` | `500` | The admissions could not be read |
