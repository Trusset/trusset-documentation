---
title: 'List KYC Sources'
api: 'GET /customers/api/kyc-sources'
description: 'The verifiers your instance accepts sealed KYC records from'
---

Returns the KYC sources of your instance, newest first, with the record key they seal to. A KYC source is a verifier you designate, for example the liability umbrella that verified an investor at the time of investment. It delivers the KYC file of a wallet as a sealed envelope through its [inbox](/endpoints/kyc-inbox/introduction). See [Sealed KYC records](/endpoints/customers/introduction#sealed-kyc-records).

Up to 200 sources are returned, removed ones included.

| `status` | Meaning |
|---|---|
| `ACTIVE` | The source can deliver and revoke records |
| `PAUSED` | Deliveries are refused with `403 SOURCE_PAUSED`. The source can still read its inbox and delivery status, and revoke records |
| `REVOKED` | Removed with [Remove KYC Source](/endpoints/customers/remove-kyc-source). Its token no longer works. Final |

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="sources" type="array">
      <Expandable>
        <ResponseField name="id" type="string">The source ID. It is part of the inbox URL and of every envelope header.</ResponseField>
        <ResponseField name="name" type="string">The name you gave the source.</ResponseField>
        <ResponseField name="signingKey" type="string">The Ed25519 public key the source signs with, 64 lowercase hex characters.</ResponseField>
        <ResponseField name="signingKeyFingerprint" type="string">The first 32 hex characters of the SHA-256 hash of the raw key, in 8 groups of 4.</ResponseField>
        <ResponseField name="profileKey" type="string">The [verification profile](/endpoints/customers/list-verification-profiles) the source verifies for. A delivery under another profile key is refused.</ResponseField>
        <ResponseField name="accessLists" type="array">The whitelists bound to the source, each `{ id, name, address }`. [Approve KYC Record](/endpoints/customers/approve-kyc-record) returns the listing transaction for each of them. Empty when none is bound.</ResponseField>
        <ResponseField name="status" type="string">`ACTIVE`, `PAUSED` or `REVOKED`.</ResponseField>
        <ResponseField name="tokenHint" type="string">The last 4 characters of the source's current token, or `----` for a removed source. The token itself is shown only inside the invite.</ResponseField>
        <ResponseField name="tokenIssuedAt" type="string">When the current token was issued, ISO 8601.</ResponseField>
        <ResponseField name="lastDeliveryAt" type="string">When the source last delivered a record, or `null`.</ResponseField>
        <ResponseField name="createdAt" type="string">ISO 8601.</ResponseField>
        <ResponseField name="counts" type="object">`{ received, opened, approved }`: the source's records in each of those statuses.</ResponseField>
      </Expandable>
    </ResponseField>
    <ResponseField name="recipientKey" type="object">The record key in use: `{ keyId, publicKey, fingerprint }`, or `null` when none is registered.</ResponseField>
  </Expandable>
</ResponseField>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/kyc-sources" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const res = await fetch('https://api.trusset.org/customers/api/kyc-sources', {
  headers: { 'X-API-Key': 'trusset_your_key_here' }
});
const { data } = await res.json();

const active = data.sources.filter((source) => source.status === 'ACTIVE');
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `RATE_LIMIT_EXCEEDED` | `429` | Your instance went over its budget of 120 KYC source reads per minute. See [Rate limits](/endpoints/customers/introduction#rate-limits) |
| `LIST_KYC_SOURCES_FAILED` | `500` | The sources could not be read |
