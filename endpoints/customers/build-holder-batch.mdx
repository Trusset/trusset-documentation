---
title: 'Build Holder Batch'
api: 'POST /customers/api/identity/pending/holder-batch'
description: 'One message your attester signs, so each customer can submit their own attestation'
---

Turns a set of rows from [List Pending Verifications](/endpoints/customers/list-pending-verifications) into one batch of attestations that each customer submits from their own wallet. Your attester signs a single EIP-712 message for the whole batch, and each customer pays the gas for their own claim. See [Holder claims](/endpoints/customers/introduction#holder-claims) for the whole path.

This is the holder path, on the [instance ID register](/endpoints/customers/introduction#the-instance-id-register) only. The issuer path, where your wallet sends one `attestBatch` for the rows and pays its gas, stays the default: [Build Pending Registration](/endpoints/customers/build-pending-registration). Both read the same rows.

Nothing is signed or sent here. The call reads the chain time and each wallet's current nonce on the identity hub, builds the batch, and stores the draft on each row. Sign `typedData` with the wallet you named as `attester`, then send the signature to [Store Holder Signature](/endpoints/customers/store-holder-signature) with the same `ids`.

## What each claim attests

Each row becomes one attestation under your attester's address, with the row's `kycHash` as the root, its investor type as the investor class, its expiries, and these [predicates](/endpoints/customers/introduction#predicates):

| Predicate | Set when |
|---|---|
| `KYC_DONE` | Always |
| `RESIDENCY_ON_FILE` | The row carries a `residencyClaim` |
| `EEA_RESIDENT` | The row's country is in the EEA |

These are the same attestations Build Pending Registration would send for the rows. The country itself never goes on chain.

Each attestation is a leaf of a Merkle tree: `keccak256(keccak256(abi.encode(subject, root, predicates, softExpiry, hardExpiry, investorClass, nonce)))`, with each pair hashed in sorted order. Your attester signs only the tree's root, `batchRoot`.

The batch is dated with `issuedAt`, the earlier of the server time and the chain time when it was built. The hub stores that signed time as the attestation's issue time, so a late claim never looks fresher than the batch. A claim can be sent until `deadline`, 30 days after the build.

<Warning>
  A claim carries the wallet's nonce from the build. Any later write by your attester about the same wallet on the identity hub voids it, including an attestation from the issuer path for that row. Building the batch again replaces the draft on each row, and a signature stored for an earlier batch stays on the row until a new one is stored.
</Warning>

## Body Parameters

<ParamField body="ids" type="array" required>
  1 to 200 row ids. Only rows still `PENDING` on your instance are used, and any other id is dropped without an error. Compare `ids` in the response with what you sent.
</ParamField>

<ParamField body="attester" type="string" required>
  The wallet that signs the batch. Your instance ID register must trust it as an attester. The attestations are written under this address.
</ParamField>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_ADDRESS` | `400` | `attester` is missing or not a wallet address |
| `VALIDATION_ERROR` | `400` | `ids` is not an array of 1 to 200 ids |
| `INVALID_EXPIRY` | `400` | A row's soft or hard expiry has already passed, or the soft expiry is not before the hard expiry. Dismiss that row to build the rest |
| `INVALID_INVESTOR_TYPE` | `400` | A row's investor type is not 1, 2 or 3 |
| `NOT_FOUND` | `404` | None of the ids is a `PENDING` row of your instance, or the instance no longer exists |
| `COUNTRY_BLOCKED` | `403` | A row's country is blocked by its verification profile. The message names the wallet |
| `UNTRUSTED_ATTESTER` | `403` | Your instance ID register does not trust `attester`. A register admin trusts a wallet in the Issuer Portal, on the wallet page |
| `CUSTOMER_ARCHIVED` | `409` | A row's wallet belongs only to an archived customer |
| `HOLDER_PATH_UNAVAILABLE` | `409` | Your instance writes to a register of its own, not to an instance ID register. Use Build Pending Registration |
| `INSTANCE_REGISTER_REQUIRED` | `409` | Your instance has no instance ID register yet. It is created in the Issuer Portal, under Settings |
| `KYC_HASH_MISSING` | `409` | A row has no `kycHash` to attest. Dismiss it and verify the customer again |
| `IDENTITY_HUB_NOT_CONFIGURED` | `501` | The identity hub is not deployed on your instance's network |
| `CHAIN_UNAVAILABLE` | `503` | The chain time could not be read. Retry shortly |
| `HOLDER_BATCH_FAILED` | `400`, `500` | The batch could not be built, for example because a chain read failed |
