---
title: 'Reissue Source Invite'
api: 'POST /customers/api/kyc-sources/{sourceId}/invite'
description: 'Issue a new invite for a source and end the old one'
---

Issues a new invite for a KYC source. The new invite carries a new token, your current record key and the source's current profile key. The request has no body.

<Warning>
  The old token stops working at once. Until the verifier stores the new invite, its calls to the inbox answer `401 UNAUTHORIZED`. Hand the new invite over through a confidential channel, as with the first one.
</Warning>

Issue a new invite when:

- you replaced the record key with [Set Record Key](/endpoints/customers/set-kyc-record-key). The verifier's tool pins the key from its invite and refuses to send while the inbox reports another one.
- you changed the source's `profileKey` with [Update KYC Source](/endpoints/customers/update-kyc-source).
- the invite may have reached someone other than the verifier.

Records already delivered are not affected. On the verifier's side a new invite for a source that already has one is stored with `trusset-kyc invite add --replace --fingerprint "<fingerprint>"`, with the fingerprint you read out from `trusset-kyc key show` over a separate channel.

## Path Parameters

<ParamField path="sourceId" type="string" required>
  The source `id` from [List KYC Sources](/endpoints/customers/list-kyc-sources).
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="source" type="object">The source, as on [List KYC Sources](/endpoints/customers/list-kyc-sources), with the new `tokenHint` and `tokenIssuedAt`.</ResponseField>
    <ResponseField name="invite" type="string">The new invite. See [The invite](/endpoints/kyc-inbox/introduction#the-invite) for its fields.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  The response is sent with `Cache-Control: no-store`. The call is written to the customer audit log as `KYC_SOURCE_INVITE_ISSUED`.
</Note>

<RequestExample>
```bash cURL
curl -X POST "https://api.trusset.org/customers/api/kyc-sources/cmhw2a6r10003l80c9d4h1n8v/invite" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const res = await fetch(
  `https://api.trusset.org/customers/api/kyc-sources/${sourceId}/invite`,
  { method: 'POST', headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { data } = await res.json();
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `SOURCE_NOT_FOUND` | `404` | No KYC source with this ID belongs to your instance |
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key is archived or no longer exists |
| `SOURCE_REVOKED` | `409` | The source was removed. Add a new source instead |
| `SEALED_KYC_NOT_ENABLED` | `409` | Your instance is a production instance and sealed KYC records are not enabled for your organisation. See [Availability](/endpoints/customers/introduction#availability) |
| `RECIPIENT_KEY_NOT_SET` | `409` | Your instance has no record key |
| `RATE_LIMIT_EXCEEDED` | `429` | Your instance went over its budget of 20 KYC source writes per minute |
| `ISSUE_KYC_INVITE_FAILED` | `500` | The invite could not be issued |
