---
title: 'List Eligibility Profiles'
api: 'GET /customers/api/eligibility/profiles'
description: 'The verification profiles that carry an eligibility register or a profile gate'
---

Returns the verification profiles of your instance that a lending market or a vault can gate on, by key, with the address each one stands for. That is a profile with an eligibility register, or, on an instance that keeps its customers on its [instance ID register](/endpoints/customers/introduction#the-instance-id-register), a profile put on chain with its [profile gate](/endpoints/customers/introduction#profile-gates).

A profile with an eligibility register is one [Request Admission](/endpoints/customers/request-admission) can queue wallets for. A profile gate takes no admissions: it computes eligibility from each wallet's attestation, so it is listed with `admissionMode: GATE`.

A profile with neither is left out. Eligibility registers are deployed or bound in the Issuer Portal, and a profile is put on chain there under Customers, Investor Profiles. [List Verification Profiles](/endpoints/customers/list-verification-profiles) returns every profile with its full requirements. See [Eligibility registers](/endpoints/customers/introduction#eligibility-registers).

## Response Fields

<ResponseField name="data" type="array">
  Profiles with an eligibility register first, then profiles with a gate. Within each, presets first, then custom profiles, oldest first. Empty when no profile has either.
  <Expandable>
    <ResponseField name="key" type="string">The profile key, as the lending endpoints take it in `identityRegistryProfile`, `providerRegistryProfile`, `borrowerProfile` and `providerProfile`.</ResponseField>
    <ResponseField name="name" type="string">Display name.</ResponseField>
    <ResponseField name="entityType" type="string">`INDIVIDUAL` or `COMPANY`.</ResponseField>
    <ResponseField name="professionalOnly" type="boolean">Whether the profile is limited to professional clients. Only the register of such a profile, in the `REGISTER` or `CLAIM` mode, or its profile gate can be the borrower gate of a `MARKET`-priced lending market. See [Professional borrowers](/endpoints/lending/set-identity-gates#professional-borrowers).</ResponseField>
    <ResponseField name="requirementsHash" type="string">The hash of the profile's current requirements. See [Requirements hash](/endpoints/customers/list-verification-profiles#requirements-hash).</ResponseField>
    <ResponseField name="registryAddress" type="string">The eligibility register, or the profile gate for `admissionMode: GATE`, checksummed.</ResponseField>
    <ResponseField name="admissionMode" type="string">`REGISTER`, `CLAIM`, `INSTANCE_REGISTER` or `EXTERNAL`, recorded when the register was bound, or `GATE` for a profile gate on your instance ID register. Only `REGISTER` and `CLAIM` take admissions through this API, `CLAIM` as profile claims on a T-REX 5 register. A `GATE` profile admits every wallet whose attestation meets its rules, with nothing to sign per wallet. See [Which registers can be signed here](/endpoints/customers/introduction#which-registers-can-be-signed-here).</ResponseField>
  </Expandable>
</ResponseField>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/customers/api/eligibility/profiles" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const response = await fetch('https://api.trusset.org/customers/api/eligibility/profiles', {
  headers: { 'X-API-Key': 'trusset_your_key_here' }
});
const { data: profiles } = await response.json();

const professionalGates = profiles.filter(
  (profile: { professionalOnly: boolean }) => profile.professionalOnly
);
```
</RequestExample>
