---
title: 'Reject Disclosure'
api: 'POST /customers/api/disclosure-requests/{id}/reject'
description: 'Refuse the encrypted disclosure of an approved request'
---

Rejects the encrypted disclosure of an approved request while `envelope.status` is `HELD` or `OPENED`. It becomes `REJECTED`, and Trusset deletes the ciphertext if it still holds it. The request itself stays `APPROVED`: the holder answered, and you refused the answer.

Your [local tool](/tools/kyc-courier/overview) calls this when a disclosure fails one of its [checks](/endpoints/customers/open-disclosure#what-your-tool-checks-first). You call it for a disclosure you do not accept. A held disclosure can be rejected without being downloaded or opened.

A rejection is final for the envelope. To ask the holder again, create a new request. Rejecting an envelope that is already `REJECTED` changes nothing and answers with the request.

## Reasons

| `reason` | Sent when |
|---|---|
| `UNDECRYPTABLE` | The envelope does not decrypt with the record key the header names |
| `DIGEST_MISMATCH` | The plaintext does not match `payloadDigest`, or `openProof` does not match `openCommitment` |
| `PROOF_INVALID` | A disclosed proof fails `verify_disclosure`, or its root is not the wallet's attestation on the identity hub |
| `INCOMPLETE` | The disclosures do not answer the scope |
| `NOT_ACCEPTED` | You decline the content after your own review |

The reason is a code only: this endpoint takes no free text. The holder's view of the request carries the envelope status, not the reason.

## Path Parameters

<ParamField path="id" type="string" required>
  The request `id`. Letters and digits only, at most 100 characters.
</ParamField>

## Body Parameters

<ParamField body="reason" type="string" required>
  One of the five codes above, in any letter case.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="request" type="object">The request after the call, as on [Get Disclosure Request](/endpoints/customers/get-disclosure-request#response-fields), with `envelope.status: REJECTED`, `rejectedAt`, `rejectReason` and `consent`.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  The rejection is written to the customer audit log as `DISCLOSURE_REJECTED`, with the reason and the envelope status before it.
</Note>

<RequestExample>
```bash cURL
curl -X POST "https://api.trusset.org/customers/api/disclosure-requests/cmi6q2x8v0004l50c7k3d9m1r/reject" \
  -H "X-API-Key: trusset_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{ "reason": "INCOMPLETE" }'
```
```typescript TypeScript
const res = await fetch(
  `https://api.trusset.org/customers/api/disclosure-requests/${requestId}/reject`,
  {
    method: 'POST',
    headers: { 'X-API-Key': 'trusset_your_key_here', 'Content-Type': 'application/json' },
    body: JSON.stringify({ reason: 'INCOMPLETE' })
  }
);
const { data } = await res.json();
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `VALIDATION_ERROR` | `400` | `reason` is missing or is not one of the five codes, with `details.field` set to `reason`. Checked first. Also an `id` with characters other than letters and digits, or longer than 100 characters |
| `NOT_FOUND` | `404` | No request with this ID was made by your instance |
| `ENVELOPE_NOT_FOUND` | `404` | The request carries no envelope |
| `ENVELOPE_NOT_REJECTABLE` | `409` | The envelope is `UNCLAIMED`. `details.envelopeStatus` is its status |
| `RATE_LIMIT_EXCEEDED` | `429` | Your instance went over its budget of 120 disclosure request changes per minute |
| `REJECT_DISCLOSURE_FAILED` | `500` | The rejection could not be recorded |
