---
title: 'Open KYC Record'
api: 'POST /customers/api/kyc-records/{recordId}/open'
description: 'Prove that a record was decrypted, so Trusset deletes its ciphertext'
---

Acknowledges that you hold the decrypted record. The proof is `openProof`, a random value the source placed inside the sealed record. Trusset holds only its SHA-256 hash, in the header's `openCommitment`, so only someone who decrypted the envelope can send the matching value.

Your [local tool](/tools/kyc-courier/overview) calls this from `trusset-kyc open`, after it has verified the record and written the files to disk. You call it yourself only when you open envelopes with your own implementation.

<Warning>
  When the proof matches, Trusset deletes the ciphertext and the record becomes `OPENED`. The envelope cannot be downloaded again. Store the decrypted record first and acknowledge second, as the tool does. The only way to get the file again is a new delivery from the source.
</Warning>

## What opening does

- The record becomes `OPENED` and `held` becomes `false`.
- The record is linked to the customer record of your instance that holds the wallet. When no customer holds it, a customer record is created for the wallet with the record's `profileKey` as its `investorType`. It holds the wallet and the profile only. Nothing from the KYC file is added, because Trusset cannot read it.
- A `customer.kyc_record_opened` event goes to your customer webhooks.

Sending the proof again for a record that is already `OPENED` or `APPROVED` changes nothing and answers with the record, so a retry after a lost response is safe. Nothing is written on chain and no whitelist changes here. The next step is [Approve KYC Record](/endpoints/customers/approve-kyc-record) or [Reject KYC Record](/endpoints/customers/reject-kyc-record).

## Path Parameters

<ParamField path="recordId" type="string" required>
  The record `id` from [List KYC Records](/endpoints/customers/list-kyc-records).
</ParamField>

## Body Parameters

<ParamField body="openProof" type="string" required>
  The `openProof` field of the decrypted record document: 32 bytes as 64 lowercase hex characters.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="record" type="object">The record after the call, as on [List KYC Records](/endpoints/customers/list-kyc-records#response-fields).</ResponseField>
  </Expandable>
</ResponseField>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `OPEN_PROOF_MISMATCH` | `400` | `openProof` is missing, is not 64 lowercase hex characters, or does not hash to the record's `openCommitment`. Checked before the record's status |
| `RECORD_NOT_FOUND` | `404` | No KYC record with this ID belongs to your instance |
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key is archived or no longer exists |
| `RECORD_NOT_OPENABLE` | `409` | The record is rejected, revoked, expired, unclaimed or superseded. `details.status` is its status |
| `RECORD_EXPIRED` | `409` | The record's `validUntil` passed before it was opened. Ask the source for a current record |
| `RATE_LIMIT_EXCEEDED` | `429` | Your instance went over its budget of 120 KYC record writes per minute |
| `OPEN_KYC_RECORD_FAILED` | `500` | The opening could not be recorded |
