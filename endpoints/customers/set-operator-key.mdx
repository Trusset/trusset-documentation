---
title: 'Set Operator Key'
api: 'PUT /customers/api/identity/operator-key'
description: 'Register a fallback ed25519 key for proof bundle headers, and the proof settings of this instance'
---

Records the public half of the operator key the [KYC-STARKs](/tools/kyc-starks/overview) tool signs bundle headers with, and sets how strictly bundles are judged on this instance.

The key is public by nature. No secret reaches this API, and the private half never leaves the machine that runs the tool. `npm run key -- show` prints the value.

Publish the key on the identity hub instead, with `setAttesterProfile` from your attester wallet; `npm run key -- show` prints that calldata too. Trusset checks a 3.1 header against the key the hub publishes for the header's attester and key id. It falls back to the key set here only when the attester has published no key on the hub, and then says so with `operatorKey.source: instance` on every proof response. Once the attester publishes a key on the hub, the key set here is no longer read for that attester's bundles.

## Body Parameters

Send any combination. Sending none is refused with `NOTHING_TO_UPDATE`.

<ParamField body="publicKey" type="string">
  32-byte ed25519 public key as 64 hex characters, with or without a `0x` prefix. It is stored lowercased and unprefixed. Send `null` to clear the key. With no key here and none on the hub, a 3.1 bundle is refused with `UNREGISTERED_OPERATOR_KEY`.
</ParamField>

<ParamField body="proofVerificationEnabled" type="boolean">
  Whether this instance refuses `stub` bundles, which carry no real proofs. A production instance refuses them whatever the setting says. Trusset never receives or runs the proofs themselves, so this setting does not make the server verify a STARK: verifying the proofs before you send a bundle is your step. A value that is not a boolean is ignored.
</ParamField>

<ParamField body="maxStalenessDays" type="integer">
  The staleness bound for a bundle's batch date, in days. `PROOF_STALE` is the failure for a batch date older than this. Integer between 1 and 36500. Send `null` to fall back to the default of 400 days.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="operatorKey" type="string">The stored key, lowercased and unprefixed, or `null`.</ResponseField>
    <ResponseField name="operatorKeySetAt" type="string">When it was last set, ISO 8601, or `null`.</ResponseField>
    <ResponseField name="proofVerificationEnabled" type="boolean">What this instance asked for.</ResponseField>
    <ResponseField name="proofVerificationEnforced" type="boolean">What actually applies. It is `true` when the instance asked for it, and always on a production instance, whose trust anchors refuse stub bundles. Read this one, not the setting.</ResponseField>
    <ResponseField name="maxStalenessDays" type="integer">The stored bound, or `null` when unset, in which case the default of 400 days applies.</ResponseField>
  </Expandable>
</ResponseField>

<Warning>
  Rotating the key does not re-verify anything already attested. Claims filed under the old key stay on chain. Rotate deliberately, and keep the old key with the bundles it signed. On the hub, publishing a new key gives it the next key id and keeps the old one readable, so headers signed under an older key id keep verifying.
</Warning>

<Note>
  [Disclosure requests](/endpoints/customers/create-disclosure-request) do not use the key set here. Trusset verifies no disclosed proof. Your local tool verifies each one against the operator key the identity hub publishes for its attester.
</Note>

<Note>
  Every change is written to the customer audit log as `PROOF_OPERATOR_KEY_UPDATED`, recording whether a key was sent, whether it was cleared, and the new value of each setting sent.
</Note>

<RequestExample>
```bash cURL
curl -X PUT "https://api.trusset.org/customers/api/identity/operator-key" \
  -H "X-API-Key: trusset_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "publicKey": "d75a980182b10ab7d54bfed3c964073a0ee172f3daa62325af021a68f707511a",
    "proofVerificationEnabled": true,
    "maxStalenessDays": 365
  }'
```
```typescript TypeScript
const res = await fetch('https://api.trusset.org/customers/api/identity/operator-key', {
  method: 'PUT',
  headers: { 'X-API-Key': 'trusset_your_key_here', 'Content-Type': 'application/json' },

}
```

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_KEY` | `400` | `publicKey` is not 64 hex characters |
| `INVALID_STALENESS` | `400` | `maxStalenessDays` is not an integer between 1 and 36500 |
| `NOTHING_TO_UPDATE` | `400` | None of the three fields was supplied |
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key no longer exists |
| `OPERATOR_KEY_FAILED` | `500` | The update could not be written |
