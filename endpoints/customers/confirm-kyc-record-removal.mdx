---
title: 'Confirm Record Removal'
api: 'POST /customers/api/kyc-records/{recordId}/removal/confirm'
description: 'Record the mined transaction that took a record wallet off a whitelist'
---

Verifies the mined `setListed` transaction that [Build Record Removal](/endpoints/customers/build-kyc-record-removal) returned for one whitelist, and records that the record's wallet is no longer listed. Confirm once per whitelist, each with its own transaction hash.

`listId` must be a whitelist bound to the record's source. The transaction is verified the same way [Confirm Whitelist Members](/endpoints/lending/confirm-access-list-members) verifies it, and every wallet it listed or removed is written to the whitelist's record from the list's `AccountListed` events. After that the whitelist's record must no longer hold this record's wallet as listed. When it still does, the call is refused with `TX_DID_NOT_REMOVE_WALLET`.

The removal takes effect on chain when the transaction mines, whether or not it is confirmed here. The confirm keeps the record's `lists[].listed` and `action` in step with the chain.

## Path Parameters

<ParamField path="recordId" type="string" required>
  The record `id` from [List KYC Records](/endpoints/customers/list-kyc-records).
</ParamField>

## Body Parameters

<ParamField body="listId" type="string" required>
  The whitelist the transaction was sent to: `removals[].listId` from [Build Record Removal](/endpoints/customers/build-kyc-record-removal).
</ParamField>

<ParamField body="txHash" type="string" required>
  Hash of the mined `setListed` transaction, `0x` followed by 64 hex characters.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="record" type="object">The record after the call, as on [List KYC Records](/endpoints/customers/list-kyc-records#response-fields). `lists[].listed` is `false` for the confirmed list.</ResponseField>
    <ResponseField name="confirmation" type="object">What the transaction changed on the list, with the fields of [Confirm Whitelist Members](/endpoints/lending/confirm-access-list-members#response-fields): `list`, `applied`, `skipped`, `events`, `listedCount`, `removedCount`, `txHash` and `signedBy`.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  The removal is written to the customer audit log as `KYC_RECORD_REMOVED`, with the whitelist, the transaction and the wallet that signed it.
</Note>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `ACCESS_LIST_NOT_BOUND` | `400` | `listId` is missing or is not a whitelist bound to the record's source. `details.field` is `listId` |
| `INVALID_TX` | `400` | `txHash` is missing or is not `0x` followed by 64 hex characters |
| `TX_NOT_VERIFIED` | `400` | The transaction listed or removed no wallet on this whitelist |
| `TX_DID_NOT_REMOVE_WALLET` | `400` | The whitelist's record still holds this record's wallet as listed after the transaction. `details.txHash` is the transaction |
| `RECORD_NOT_FOUND` | `404` | No KYC record with this ID belongs to your instance |
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key is archived or no longer exists |
| `ACCESS_LIST_NOT_FOUND` | `404` | The whitelist is no longer kept or managed by your instance on this network |
| `RATE_LIMIT_EXCEEDED` | `429` | Your instance went over its budget of 120 KYC record writes per minute |
| `CONFIRM_KYC_REMOVAL_FAILED` | `500` | The removal could not be recorded |
| `ACCESS_LISTS_NOT_CONFIGURED` | `501` | The whitelist factory is not deployed on your instance's network |
| `ACCESS_LIST_UNREADABLE` | `503` | The list belongs to another instance and whether your wallets still manage it could not be read. Retry shortly |

The confirm call can also return any [transaction verification error](/endpoints/introduction#confirm-a-transaction).
