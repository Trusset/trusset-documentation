---
title: 'Erase Identity'
api: 'POST /customers/api/identity/erase'
description: 'Build the transaction that erases an attester its own entry about a wallet on the identity hub'
---

Builds `erase(subject)` on the identity hub for one attester's entry about one wallet. Sent by that attester, it deletes the entry from the hub's storage. Use it when a customer asks for their data to be erased, after the attester has met its own retention duties off chain. See [Erasure](/protocol/infrastructure/data-storage#erasure).

The hub lets a wallet erase only its own entries, so name the attester whose entry should go as `signerAddress` and send the transaction from that wallet. Entries other attesters wrote about the same wallet stay as they are. Then record it with [Confirm Erase Identity](/endpoints/customers/confirm-erase-identity).

Erasing is for the [instance ID register](/endpoints/customers/introduction#the-instance-id-register) only. On a register of your own, use [Revoke Identity](/endpoints/customers/revoke-identity).

<Note>
  A revoked entry can be erased too. Revoke first when the wallet must stop counting before the erasure is signed: an erasure withdraws the statement just as a revoke does, but it also removes the record.
</Note>

## Body Parameters

<ParamField body="walletAddress" type="string" required>
  The wallet whose entry is erased, the subject. Checksummed or lowercase.
</ParamField>

<ParamField body="signerAddress" type="string" required>
  The attester whose entry is erased, and the wallet that sends the transaction. When it holds no entry about the wallet on the hub, active, suspended or revoked, the call answers `409 NOTHING_TO_ERASE`.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="action" type="string">`SIGN_TRANSACTION`.</ResponseField>
    <ResponseField name="chainId" type="integer">The chain the identity hub runs on.</ResponseField>
    <ResponseField name="transaction" type="object">`{ to, data }`, where `to` is the identity hub.</ResponseField>
    <ResponseField name="functionName" type="string">`eraseIdentity`.</ResponseField>
    <ResponseField name="contractFunction" type="string">`erase`, the hub function the transaction calls.</ResponseField>
    <ResponseField name="registerKind" type="string">`INSTANCE`.</ResponseField>
    <ResponseField name="description" type="string">What the transaction does.</ResponseField>
    <ResponseField name="walletAddress" type="string">The wallet, checksummed.</ResponseField>
    <ResponseField name="attester" type="string">The attester whose entry is erased, checksummed. It must send the transaction.</ResponseField>
    <ResponseField name="entryStatus" type="string">The entry's status before the erasure: `active`, `suspended` or `revoked`.</ResponseField>
    <ResponseField name="confirmWith" type="object">`{ endpoint: "POST /customers/api/identity/erase/confirm", fields: ["walletAddress", "signerAddress", "txHash"] }`.</ResponseField>
  </Expandable>
</ResponseField>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_ADDRESS` | `400` | `walletAddress` is missing or not a valid address |
| `INVALID_SIGNER` | `400` | `signerAddress` is missing, not a valid address or the zero address |
| `REGISTER_OPERATION_UNSUPPORTED` | `409` | Your instance writes to a register of its own. Revoke the wallet there instead |
| `INSTANCE_REGISTER_REQUIRED` | `409` | Your instance is in Trusset mode and has not created its instance ID register yet |
| `NOTHING_TO_ERASE` | `409` | `signerAddress` holds no entry about the wallet on the hub |
| `IDENTITY_HUB_NOT_CONFIGURED` | `501` | The identity hub is not deployed on your instance's network |
| `CHAIN_UNAVAILABLE` | `503` | The hub could not be read. Retry |
| `ERASE_FAILED` | `400`, `500` | Any other failure. `400` when a chain call failed |
