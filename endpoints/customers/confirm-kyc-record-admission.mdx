---
title: 'Confirm Record Admission'
api: 'POST /customers/api/kyc-records/{recordId}/admission/confirm'
description: 'Record the mined transaction that listed a record wallet on a whitelist'
---

Verifies the mined `setListed` transaction that [Approve KYC Record](/endpoints/customers/approve-kyc-record) returned for one whitelist, and records that the record's wallet is listed. Confirm once per whitelist, each with its own transaction hash.

## What the confirm reads

The record must be `APPROVED`, and `listId` must be a whitelist bound to the record's source. The transaction is then verified the same way [Confirm Whitelist Members](/endpoints/lending/confirm-access-list-members) verifies it: it must be mined and successful, and every wallet it listed or removed is read from the list's `AccountListed` events and written to the whitelist's record.

After that the whitelist's record must hold this record's wallet as listed. When it does not, because the transaction listed other wallets only, the call is refused with `TX_DID_NOT_LIST_WALLET`. What the transaction did change on the list stays recorded.

The wallet passes every gate the list serves from the moment the transaction mines, whether or not it is confirmed here. The confirm keeps the record's `lists[].listed` and `action` in step with the chain.

## Path Parameters

<ParamField path="recordId" type="string" required>
  The record `id` from [List KYC Records](/endpoints/customers/list-kyc-records).
</ParamField>

## Body Parameters

<ParamField body="listId" type="string" required>
  The whitelist the transaction was sent to: `admissions[].listId` from [Approve KYC Record](/endpoints/customers/approve-kyc-record).
</ParamField>

<ParamField body="txHash" type="string" required>
  Hash of the mined `setListed` transaction, `0x` followed by 64 hex characters.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="record" type="object">The record after the call, as on [List KYC Records](/endpoints/customers/list-kyc-records#response-fields). `lists[].listed` is `true` for the confirmed list.</ResponseField>
    <ResponseField name="confirmation" type="object">What the transaction changed on the list, with the fields of [Confirm Whitelist Members](/endpoints/lending/confirm-access-list-members#response-fields): `list`, `applied`, `skipped`, `events`, `listedCount`, `removedCount`, `txHash` and `signedBy`.</ResponseField>
  </Expandable>
</ResponseField>

<Note>
  The admission is written to the customer audit log as `KYC_RECORD_ADMITTED`, with the whitelist, the transaction and the wallet that signed it.
</Note>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `ACCESS_LIST_NOT_BOUND` | `400` | `listId` is missing or is not a whitelist bound to the record's source. `details.field` is `listId` |
| `INVALID_TX` | `400` | `txHash` is missing or is not `0x` followed by 64 hex characters |
| `TX_NOT_VERIFIED` | `400` | The transaction listed or removed no wallet on this whitelist |
| `TX_DID_NOT_LIST_WALLET` | `400` | The transaction did not list this record's wallet on the whitelist. `details.txHash` is the transaction |
| `RECORD_NOT_FOUND` | `404` | No KYC record with this ID belongs to your instance |
| `INSTANCE_NOT_FOUND` | `404` | The instance behind your key is archived or no longer exists |
| `ACCESS_LIST_NOT_FOUND` | `404` | The whitelist is no longer kept or managed by your instance on this network |
| `RECORD_NOT_APPROVED` | `409` | The record is not `APPROVED`. `details.status` is its status |
| `RATE_LIMIT_EXCEEDED` | `429` | Your instance went over its budget of 120 KYC record writes per minute |
| `CONFIRM_KYC_ADMISSION_FAILED` | `500` | The admission could not be recorded |
| `ACCESS_LISTS_NOT_CONFIGURED` | `501` | The whitelist factory is not deployed on your instance's network |
| `ACCESS_LIST_UNREADABLE` | `503` | The list belongs to another instance and whether your wallets still manage it could not be read. Retry shortly |

The confirm call can also return any [transaction verification error](/endpoints/introduction#confirm-a-transaction).
