---
title: 'Promote Wallet'
api: 'POST /customers/api/manage/{customerId}/wallets/{address}/promote'
description: 'Make a linked wallet the customer primary'
---

Makes a linked wallet the customer's primary. The wallet that was primary becomes a linked wallet labelled `Previously primary`, so no wallet is lost in the swap. The promoted wallet's link row is removed, and its label with it.

## Path Parameters

<ParamField path="customerId" type="string" required>Customer record ID.</ParamField>
<ParamField path="address" type="string" required>The linked wallet to promote, in any letter case. It must already be linked to this customer.</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  The customer record after the swap, with the promoted wallet as `walletAddress`. It carries the fields listed on [Get Customer](/endpoints/customers/get) other than its linked wallets, company links, Sumsub applicant record and audit entries.
</ResponseField>

<Warning>
  The primary wallet is what other parts of the platform read as the customer's address. Promoting changes which wallet that is, and it does not move anything on chain. Identity verification and claims stay attached to the wallet that holds them. The new primary carries only the identity the registry already holds for it.

  Promoting does not read the registry. The record's `status`, `verifiedAt` and `kycHash` are left as they were, so they can still describe the old primary. When the instance switches identity registers, each record whose `status` is `verified` and that holds a `kycHash` is queued for registration with that `kycHash` under its current primary. Check the new primary with [Identity Status](/endpoints/customers/identity-status) and verify it if it has no identity.
</Warning>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `INVALID_ADDRESS` | `400` | `address` is not a valid address |
| `NOT_FOUND` | `404` | No such customer, the record is archived, or that wallet is not linked to them. The current primary is not a link, so it answers here too |
| `ALREADY_PRIMARY` | `409` | The wallet is linked to this customer and is also its primary |
| `WALLET_IN_USE` | `409` | The wallet, or the outgoing primary, conflicts with another customer record |
| `PROMOTE_FAILED` | `500` | The promotion could not be written |
