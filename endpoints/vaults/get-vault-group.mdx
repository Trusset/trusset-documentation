---
title: 'Get Vault Group'
api: 'GET /lending-external-securities-v2/api/vaults/groups/{groupId}'
description: 'One multi-currency vault group with every pocket, live totals per currency and an optional holder position'
---

Returns one vault group with its pockets read from the chain. A vault group is one vault product with two to four currency pockets. Each pocket is a vault of its own that holds one settlement token (stablecoin), for example one in USDC and one in EURC. All pockets examine their depositors against the same register for the life of the group, are run by one operator, and are published together under the group's risk disclosure.

A deposit goes into one pocket and stays in its currency. Nothing converts between pockets, so the group's value is reported per currency in `tvlByCurrency`. Only on a group that mixes exactly EUR and USD is `approximateTotal` filled in, at the ECB euro reference rate of its date, labelled as an approximation.

You see your own groups, and the groups other operators published on the same network and in the same environment. On another operator's group only its published pockets with a deployed address are listed. Creating a group, adding a currency, publishing and the operator's batched pocket actions are done in the Issuer Portal.

## Path Parameters

<ParamField path="groupId" type="string" required>
  Vault group ID, as `groups[].id` on [List Vaults](/endpoints/vaults/list-vaults) or `groupId` on a pocket's vault row.
</ParamField>

## Query Parameters

<ParamField query="holderAddress" type="string">
  Wallet to read a position for in every pocket. `address` is accepted too. Any value that is not a `0x` address is ignored, and each pocket's `holder` is then `null`.
</ParamField>

## Response Fields

<ResponseField name="data" type="object">
  <Expandable>
    <ResponseField name="id" type="string">Vault group ID.</ResponseField>
    <ResponseField name="instanceId" type="string">The operating instance.</ResponseField>
    <ResponseField name="own" type="boolean">`true` when your instance operates the group.</ResponseField>
    <ResponseField name="onChainGroupId" type="integer">The group's ID on the vault factory.</ResponseField>
    <ResponseField name="factoryAddress" type="string">The vault factory that holds the group.</ResponseField>
    <ResponseField name="name" type="string">Group name.</ResponseField>
    <ResponseField name="symbolStem" type="string">The share symbol stem the pockets' symbols derive from, or `null`.</ResponseField>
    <ResponseField name="operatorWallet" type="string">The wallet that created the group.</ResponseField>
    <ResponseField name="identityRegistryAddress" type="string">The depositor register every pocket examines its depositors against.</ResponseField>
    <ResponseField name="depositorGate" type="object">`kind`, `register` and a display `statement`, as on a vault row of [List Vaults](/endpoints/vaults/list-vaults).</ResponseField>
    <ResponseField name="depositorProfile" type="object">Your group only. The verification profile whose eligibility register the depositor register is, or `null`.</ResponseField>
    <ResponseField name="depositorAccessList" type="object">Your group only. The whitelist the depositor register is, as `{ id, name, purpose, address, own }`, or `null`.</ResponseField>
    <ResponseField name="depositorRegisterRetired" type="boolean">Present, and `true`, only when the group's depositor register is the previous Trusset ID Register, `0xE9114c40934f6fB6BB317935156b731f7A86D006`. That register takes no new identities, so every pocket refuses a depositor verified since 10 October 2026. See [The Previous Trusset ID Register](/endpoints/lending/set-identity-gates#the-previous-trusset-id-register).</ResponseField>
    <ResponseField name="currentRegistry" type="string">Present with `depositorRegisterRetired`. The current Trusset ID Register, lowercased.</ResponseField>
    <ResponseField name="depositorRegisterNote" type="string">Present with `depositorRegisterRetired`. The same note as on [List Vaults](/endpoints/vaults/list-vaults).</ResponseField>
    <ResponseField name="performanceFeeBps" type="integer">The group's performance fee in basis points as recorded. Each pocket carries its own, reconciled with the chain.</ResponseField>
    <ResponseField name="active" type="boolean">Whether the group is published.</ResponseField>
    <ResponseField name="archived" type="boolean">Always `false` here.</ResponseField>
    <ResponseField name="riskDisclosure" type="string">The operator's risk statement, shown on every pocket. Show it before any deposit control.</ResponseField>
    <ResponseField name="riskDisclosureUrl" type="string">Link to the full risk disclosure, `https`, or `null`.</ResponseField>
    <ResponseField name="network" type="string">The chain the group lives on.</ResponseField>
    <ResponseField name="operatedBy" type="object">`instanceName`, `issuerName`, `isBank`, `image` and `profileImage`. Display the operator next to the group name.</ResponseField>
    <ResponseField name="pockets" type="array">Each pocket as a vault row of [List Vaults](/endpoints/vaults/list-vaults), with `onChain` as on [Get Vault](/endpoints/vaults/get-vault) and `holder` for `holderAddress`. A pocket row leaves out `depositorProfile`, `depositorAccessList` and the retired-register fields, which the group carries once. `onChain` and `holder` are `null` on a pocket with no deployed address. Deposit into a pocket with [Deposit to Vault Group](/endpoints/vaults/deposit-to-vault-group) or with [Deposit](/endpoints/vaults/deposit) on its vault ID.</ResponseField>
    <ResponseField name="operatorDiverged" type="boolean">`true` when the pockets are owned by different wallets on chain, `false` when one wallet owns them all, `null` when an owner could not be read.</ResponseField>
    <ResponseField name="currentOperator" type="string">The one wallet that owns every pocket, or `null`.</ResponseField>
    <ResponseField name="tvl" type="object">Total assets per currency, keyed by currency code, for example `{ "USD": "1250000.0", "EUR": "480000.0" }`. A pocket whose asset has no known currency is keyed by its symbol.</ResponseField>
    <ResponseField name="tvlByCurrency" type="array">The same per currency: `currency`, `amount` (`null` when a pocket could not be read), `pockets`, `symbols` and `readFailed`.</ResponseField>
    <ResponseField name="approximateTotal" type="object">Only when the pockets hold exactly EUR and USD and every figure was read: `currency` (`USD`), `amount`, `eurAmount`, `eurUsd`, `referenceDate`, `source` (`ECB`), `approximate: true` and a `label`. `null` otherwise.</ResponseField>
    <ResponseField name="chain" type="object">The group as the vault factory holds it: `operator`, `identityRegistry`, `performanceFeeBps` and `vaults`, or `{ readFailed: true }`.</ResponseField>
    <ResponseField name="unregisteredPockets" type="string[]">Your group only. Pockets the factory holds that your instance has not registered yet. Empty otherwise.</ResponseField>
    <ResponseField name="createdAt" type="string">ISO 8601.</ResponseField>
    <ResponseField name="updatedAt" type="string">ISO 8601.</ResponseField>
  </Expandable>
</ResponseField>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/lending-external-securities-v2/api/vaults/groups/cmv3a1b2c0007l80d4e5f6g7h?holderAddress=0x6a6cba16dad34f7ea7ecbcdbf050f8146b942d6b" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const res = await fetch(
  `https://api.trusset.org/lending-external-securities-v2/api/vaults/groups/${groupId}?holderAddress=${wallet}`,
  { headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { data: group } = await res.json();
for (const pocket of group.pockets) {
  console.log(pocket.assetSymbol, pocket.onChain?.totalAssets, pocket.holder?.shares);
}
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `VAULT_GROUP_NOT_FOUND` | `404` | No such group, it is archived, or it belongs to another operator and is unpublished or on another network or environment |
| `VAULT_GROUP_READ_FAILED` | `500` | Unexpected failure. Retry, or contact support with the request ID |
| `CHAIN_UNAVAILABLE` | `503` | The chain could not be read. Retry shortly |
| `SERVICE_UNAVAILABLE` | `503` | The vault records could not be reached. Retry shortly |
