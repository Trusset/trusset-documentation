---
title: 'List Vaults'
api: 'GET /lending-external-securities-v2/api/vaults'
description: 'Your instance''s vaults first, then every vault published on your network'
---

Returns every vault visible to the instance behind the API key, in three groups:

1. Vaults this instance operates, marked `own: true`, newest first. An instance runs at most three live vaults.
2. Vaults other operators published, on the same network and in the same environment (production or not), newest first.
3. Unpublished vaults of other operators in which this instance is a distributor of record. One of its verified wallets still has attributed shares or unpaid distributor fees there. These rows carry `distributorView: true`, no risk disclosure, and take no deposit from this instance.

Any other unpublished vault is visible only to its operator. Archived vaults are left out.

Every row carries an `onChain` block read from the vault contract, so a directory can show share price and size without a call per vault. It carries no per-holder position and none of the operator-only blocks. Those are on [Get Vault](/endpoints/vaults/get-vault).

## Response Fields

<ResponseField name="data.vaults" type="array">
  <Expandable>
    <ResponseField name="id" type="string">Vault ID. Every other vault endpoint takes this.</ResponseField>
    <ResponseField name="instanceId" type="string">The operating instance.</ResponseField>
    <ResponseField name="own" type="boolean">True when your instance operates this vault.</ResponseField>
    <ResponseField name="distributorView" type="boolean">Present and `true` only on an unpublished vault you see as a distributor of record. You can read it, redeem from it and collect your earnings in it. [Deposit](/endpoints/vaults/deposit) refuses it with `VAULT_NOT_PUBLISHED`.</ResponseField>
    <ResponseField name="vaultAddress" type="string">The vault contract.</ResponseField>
    <ResponseField name="operatorWallet" type="string">The wallet that created the vault and was recorded as its operator. The live on-chain owner is `onChain.owner` on [Get Vault](/endpoints/vaults/get-vault).</ResponseField>
    <ResponseField name="assetAddress" type="string">The vault's asset, a settlement token (stablecoin). Deposits, redemptions and the share price are denominated in it.</ResponseField>
    <ResponseField name="assetSymbol" type="string">Asset symbol, for example `USDC`.</ResponseField>
    <ResponseField name="assetDecimals" type="integer">Asset decimals. Every amount you send is parsed at this precision, shares included, and every amount returned is formatted with it.</ResponseField>
    <ResponseField name="identityRegistryAddress" type="string">The vault's own identity register, or `null` when the vault names none. Fixed for the life of the vault.</ResponseField>
    <ResponseField name="depositorGate" type="object">`kind` is `REGISTER` when the vault names an identity register and `NONE` when it names none. Carries `register` and a display `statement`. A `NONE` vault still examines each depositor against the provider register of every market it funds, so it is not open to every wallet.</ResponseField>
    <ResponseField name="name" type="string">Vault name.</ResponseField>
    <ResponseField name="symbol" type="string">Share token symbol.</ResponseField>
    <ResponseField name="performanceFeeBps" type="integer">The vault operator's cut of share-price growth above the high-water mark, in basis points. The contract only accepts decreases.</ResponseField>
    <ResponseField name="active" type="boolean">True once the operator published the vault.</ResponseField>
    <ResponseField name="archived" type="boolean">Always `false` here, because archived vaults are excluded.</ResponseField>
    <ResponseField name="network" type="string">The chain the vault lives on, taken from the operating instance.</ResponseField>
    <ResponseField name="settlementCurrency" type="string">The fiat currency the vault's asset settles in, resolved from the asset address rather than guessed from its symbol. `null` when the address is not a known settlement asset.</ResponseField>
    <ResponseField name="riskDisclosure" type="string">The operator's risk statement. Show it before any deposit control. `null` on a `distributorView` row.</ResponseField>
    <ResponseField name="riskDisclosureUrl" type="string">Link to the operator's full risk disclosure. Always `https`. `null` on a `distributorView` row.</ResponseField>
    <ResponseField name="operatedBy" type="object">`instanceName`, `issuerName`, `isBank`, plus `image` and `profileImage`. Display the operator next to the vault name.</ResponseField>
    <ResponseField name="onChain" type="object">Live vault state, identical in shape to the block on [Get Vault](/endpoints/vaults/get-vault#response-fields), where every field is described. It is `null` for a vault with no recorded address. It carries `readFailed: true` when the chain could not be read for that vault alone, and one vault failing does not empty the others.</ResponseField>
    <ResponseField name="createdAt" type="string">When the vault was registered, ISO 8601.</ResponseField>
    <ResponseField name="updatedAt" type="string">Last change to the record, ISO 8601.</ResponseField>
  </Expandable>
</ResponseField>

<Warning>
  `performanceFeeBps` on the row is reconciled against the fee the contract reports, and the lower of the two is served. A vault whose `onChain` read failed keeps the recorded value, which can be the higher one. Read the fee from `onChain.performanceFeeBps` when it is present.
</Warning>

<Note>
  The groups come in the order above. Pin on `own` and `distributorView` if you re-sort client-side.
</Note>

<RequestExample>
```bash cURL
curl "https://api.trusset.org/lending-external-securities-v2/api/vaults" \
  -H "X-API-Key: trusset_your_key_here"
```
```typescript TypeScript
const res = await fetch(
  'https://api.trusset.org/lending-external-securities-v2/api/vaults',
  { headers: { 'X-API-Key': 'trusset_your_key_here' } }
);
const { data } = await res.json();
for (const vault of data.vaults) {
  console.log(`${vault.name} (${vault.symbol}), operated by ${vault.operatedBy?.issuerName}`);
}
```
</RequestExample>

## Error Codes

| Code | HTTP | Cause |
|---|---|---|
| `SERVICE_UNAVAILABLE` | `503` | The vault records could not be reached. Retry shortly |
| `VAULT_READ_FAILED` | `500` | Unexpected failure. Retry, or contact support with the request ID |
